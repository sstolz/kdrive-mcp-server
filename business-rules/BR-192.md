## Rule

A JSON route response with any 3xx status is refused. A download request accepts either a direct 206 from the API origin or exactly one 302 whose `Location` is an absolute `https:` URL on default port 443, without userinfo or fragment, whose host is one label matching `^[a-z0-9-]{1,63}$` followed by `.download.kdrive.infomaniakusercontent.com`; the second request carries no `Authorization` or `Cookie` header, and any 3xx on it is refused. Verified by: AC-03.

## Rationale

The download redirect is the only cross-host hop; bounding it to one allowlisted storage host without credentials prevents token forwarding and open redirects. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** a download answers 302 to `https://s1.download.kdrive.infomaniakusercontent.com/r`
  **When** `describe` runs
  **Then** one storage request without `Authorization` or `Cookie` follows.
- **Given** a download answers 302 to `https://s1.download.kdrive.infomaniakusercontent.com:8443/r`
  **When** `describe` runs
  **Then** it rejects `READ_UNAVAILABLE` and no storage request is made.
