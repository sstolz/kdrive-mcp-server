# BR-408 — Language switcher

## Rule

The consent page, and no error page, carries a language switcher as the last child of `<header>`, exactly: `<nav class="languages" aria-label="{languageNav}">` + the English item + one space + the French item + `</nav>`, English first. The item of the page language is `<span lang="xx" aria-current="true">Name</span>`; the other is `<a href="?{query}" lang="xx" hreflang="xx">Name</a>`, where Name is `English` or `Français` and `{query}` is the HTML-escaped serialization (`URLSearchParams.toString()`) of the authorize request's own query with `lang` set to the other language (`URLSearchParams.set`: every original parameter kept, in order, a previous `lang` replaced in place, otherwise `lang` appended). The link is a relative reference, so it resolves to the same authorize path. When the byte length of the issuer URL's path + `/oauth/authorize?` + the serialization exceeds 8,192 (BR-169), the `<nav>` is omitted. Following the link is an ordinary authorize GET: every BR-128 check runs again.

## Rationale

The owner asked for a switcher showing each language's full name in its own language, without flags; error pages hold no request value and cannot rebuild the request (F-031 D-2). Source: [F-031 v1](../features/F-031-oauth-proxy-page-languages.md).

## Examples

- **Given** an English consent page for a query with `state` `"<x>'&` and `extra=1`
  **When** the page is rendered
  **Then** the `<nav>` links to the same query with `lang=fr` appended, HTML-escaped, and the English item is the `aria-current` span
- **Given** a query whose link would be 8,193 bytes
  **When** the consent page is rendered
  **Then** it has no `<nav>`
- **Given** any error page
  **When** it is rendered
  **Then** it has no `<nav>`, `hreflang` or `?lang=` and its only `<a>` is the GitHub link
