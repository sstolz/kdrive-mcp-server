# BR-433 — Restore the prior stable image before cleanup

## Rule

Cleanup of a candidate GHCR package version with a prior stable default is permitted only after GET confirms latest restored to the recorded prior digest while the prior version still serves that digest.

The exhaustive predicates and diagnostics are in
[F-024 v4](../features/F-024-gated-publication.md), ticket #91.

## Rationale

Digest-keyed deletion removes every attached tag; restore the prior index bytes before deletion can endanger default consumers. npm absence, confirmed identity and explicit owner authority remain prerequisites.

## Examples

- **Given** prior stable 1.0.0 and orphan candidate 1.0.1
  **When** the owner copies and GET-confirms prior raw bytes
  **Then** permits separately authorized candidate deletion.
- **Given** prior stable 1.0.0 and orphan candidate 1.0.1
  **When** the copy returns success but latest raw hash differs
  **Then** refuses deletion.
