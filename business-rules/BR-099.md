## Rule

The validator rejects with status 401 reason `id-token` a token carrying a `nonce` claim or a header `typ` other than absent, `JWT`, `at+jwt`, `application/jwt` or `application/at+jwt` (case-insensitive).

## Rationale

Together with the audience rule, an OIDC ID token is never accepted as an access token. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-10.

## Examples

- **Given** an otherwise valid token with `typ` `id_token`.
  **When** it is validated.
  **Then** it is rejected with 401 `id-token`.
- **Given** an otherwise valid token with `typ` `application/at+jwt`.
  **When** it is validated.
  **Then** it is accepted.
- **Given** an ID-token-shaped JWT without `nonce`, `typ: JWT` and `aud` equal to the client ID.
  **When** it is validated.
  **Then** it is rejected with 401 `audience`.
