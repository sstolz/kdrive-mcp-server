## Rule

**v3 (F-026 v1; superseded by v4)**

Every active tool invocation obeys the stated request/output bounds and stops publishing results or starting dependency calls after cancellation, deadline or session close, except a mutation gate run once its intent append has started: from that point the navigation deadline, cancellation, session close and output checks no longer abort, race or replace the run, which is bounded by F-016 (BR-249, BR-250, BR-254, BR-258), and its gate result is published unless the session is closed. The F-005 1,000 ms exit bound after EOF, SIGINT or SIGTERM holds when no gate run is past its intent append start; otherwise the process exits after the gate close (BR-254), bounded by that run's total deadline plus two bounded appends (BR-259; file sink — with the stderr sink the wait also depends on stderr draining, D-16-7). On stdio, a second outbound frame sent while one is being written waits in the bounded outbound queue (BR-388) instead of closing the session; only a queue overflow, a frame above 1,048,576 bytes or a frame not written within 1,000 ms of its write start closes it, besides a write error or a serialization failure, which still close it as today.

v2 (accepted; superseded by v3): Every active tool invocation obeys the stated request/output bounds and stops publishing results or starting dependency calls after cancellation, deadline or session close, except a mutation gate run once its intent append has started: from that point the navigation deadline, cancellation, session close and output checks no longer abort, race or replace the run, which is bounded by F-016 (BR-249, BR-250, BR-254, BR-258), and its gate result is published unless the session is closed. The F-005 1,000 ms exit bound after EOF, SIGINT or SIGTERM holds when no gate run is past its intent append start; otherwise the process exits after the gate close (BR-254), bounded by that run's total deadline plus two bounded appends (BR-259; file sink — with the stderr sink the wait also depends on stderr draining, D-16-7).

**v4 (F-038 v1, #47; accepted on main `2ae303c`)** — The v3 rule holds, with the 512 invocation budget counting upstream dependency operations and their admitted retries, not reads from an already-open response body (including the EOF probe). The 513th operation is refused before its port starts. Body reads remain guarded by the existing byte bounds, deadline, cancellation and close checks, are never retried, and close the owned body exactly once. No read resets the deadline. The five-list bound, output bounds, final authorization and committed-mutation exception remain unchanged. Any body read that issues or resumes an upstream request is a charged operation. This preserves existing operation charging points; it does not introduce a physical-HTTP-hop counter (F-038 D-1).

**v5 (F-039 v1, #47 lot C, pending acceptance; v4 stays the active rule until then)** — The v4 rule holds with its inherited unlimited stderr shutdown exception replaced by BR-259 v2's 5,000 ms append budget and BR-254 v2's bounded sink/gate close. The dedicated stdio process's 1,000 ms bound on calling the exit primitive when no run is past intent remains, measured from EOF/signal handling: before draining runs, apply its remaining deadline to non-committed in-flight appends (including denied), then to sink closure and owned release. Expiry rejects/latches the append while preserving denied/ACCESS_DENIED with zero attempts; repeated closes never extend the deadline. Dedicated stdio routes termination through the same production exit helper as HTTP and other production exit callers (BR-254 v2): both stdout/stderr flush callbacks race a fixed ref'd 250 ms timer capped by the remaining stdio budget; an exhausted budget calls exit immediately. Owned/library compositions only set the exit code, including transport failure, and settle closure without terminating their host; their closure does not prove dedicated-process exit. Actual OS termination remains outside the bound for synchronous fd 2 blockage or a libuv file operation stuck during teardown. Once intent append starts, navigation cancellation, deadlines and output checks never replace the gate result; stream accounting, invocation queues and all other v4 clauses remain unchanged.

## Rationale

Bounded evidence and stream ownership prevent stalled readers or evidence from retaining a session. Source: [F-005 v1](../features/F-005-stdio-navigation.md), AC-12.

v4 removes fragmentation-dependent refusal without weakening byte evidence or pending-read settlement. Source: [F-038 v1](../features/F-038-stream-budget-and-weak-etags.md), AC-01–AC-06.

Pending v5: A stalled audit collector must release the invocation and shutdown without misreporting a dispatched write. Source: [F-039 v1](../features/F-039-bounded-audit-sink.md).

## Examples

- **Given** a request using exactly512 dependency calls and bounded terminal output.
  **When** it completes before deadline.
  **Then** the result succeeds.
- **Given** a513th call, a seventh waiting outbound frame (v3; v2: a second pending send), or stalled output/evidence.
  **When** the bound is reached.
  **Then** the fixed refusal/close occurs, no new work starts and owned resources settle.
- **Given** one stdio frame being written (v3)
  **When** a second frame is sent
  **Then** it waits, both are written in send order and the session stays open (v2: the session closes with `STDIO_OUTPUT_FAILED`)
- **Given** a gate run past its intent append whose mutator answers 200 after 12,000 ms
  **When** the 10,000 ms navigation deadline passes
  **Then** the caller receives `succeeded`, never `REQUEST_TIMEOUT`, and the slot stays held until then

v4 examples (the preceding examples describe superseded v3):

- **Given** 8,388,608 ASCII bytes, admitted byte caps and valid evidence
  **When** `kdrive_read` consumes 512 chunks of 16,384 bytes and EOF before its deadline
  **Then** the one-character text result succeeds with `total_characters:8388608` and one body close. Maps to `TestBR070_v4_AC01_eight_MiB_in_16_KiB_chunks_succeeds`.
- **Given** the same caps and a descriptor of 8,388,609 bytes
  **When** `kdrive_read` starts
  **Then** it returns `LIMIT_EXCEEDED` before `open`. Maps to `TestBR070_v4_AC03_declared_source_over_byte_cap_refuses_before_open`.
- **Given** a 600-byte source as 600 one-byte chunks or one chunk, followed by EOF
  **When** downloaded
  **Then** the exact same 600 bytes succeed in both cases with one `describe`, one `open` and four authorization `inspect` calls in each case. Maps to `TestBR070_v4_AC02_fragmentation_does_not_consume_operations`.
- **Given** a 600-byte range that yields a 601st byte at the EOF probe
  **When** consumed
  **Then** it returns `CONTENT_UNAVAILABLE` and closes once without publishing data. Maps to `TestBR070_v4_AC03_stream_byte_evidence_remains_bounded`.
- **Given** a data read or EOF probe still pending at 10,000 ms from slot acquisition
  **When** the deadline is reached
  **Then** it returns `REQUEST_TIMEOUT`, aborts and closes once, with no late success. Maps to `TestBR070_v4_AC04_pending_data_and_EOF_obey_deadline`.
- **Given** cancellation or session close during either pending-read case
  **When** the invocation settles
  **Then** its controller result is `ACCESS_DENIED`, the body closes once and no late success is published. Maps to `TestBR070_v4_AC04_pending_data_and_EOF_obey_cancel_and_close`.
- **Given** 512 upstream operations suffice, or a 513th is required
  **When** path resolution runs
  **Then** the first case succeeds and the second returns `LIMIT_EXCEEDED`; each starts exactly 512 operations. Maps to `TestBR070_v4_AC05_operation_512_succeeds_and_513_never_starts`.

Pending v5 examples (the accepted examples above remain historical/current as labelled):

- **Given** a mutation with a blocked intent and a read waiting behind it
  **When** 5,000 ms from intent append elapse
  **Then** the mutation returns failed/AUDIT_UNAVAILABLE with zero attempts, releases its slot and the read runs. Maps to `TestBR070_v5_AC11_audit_timeout_releases_navigation_slot`.
- **Given** a committed mutation whose upstream attempt is pending when shutdown starts
  **When** the attempt and audit bounds elapse
  **Then** its uncertain result retains outcome_unrecorded and shutdown completes within BR-254 v2's ceiling. Maps to `TestBR070_v5_AC08_shutdown_keeps_committed_result_semantics`.
- **Given** stdio with no run past intent
  **When** EOF starts closure
  **Then** closure completes within 1,000 ms, including a stalled owned file release. Maps to `TestBR070_v5_AC09_idle_stdio_exit_bound_is_unchanged`.
- **Given** the dedicated stdio path with an injected exit primitive, a denied append blocked from time 0, no run past intent, shutdown at 100 ms and transport close ending at 300 ms
  **When** time reaches 1,099 then 1,100 ms
  **Then** the append is pending then rejects/latches with the denied result preserved; sink/gate close settle and the shared real exit helper calls the primitive once by 1,100 ms, with zero remaining flush allowance and no extra release wait. An owned/library closure control, including transport failure, only sets the exit code and never calls the process exit primitive. Dedicated STDIO_OUTPUT_FAILED/STDIO_START_FAILED rows exit with 1. Maps to `TestBR070_v5_AC13_denied_append_shares_remaining_stdio_shutdown_budget`.
