# BR-355 — Dispatch-only release workflow

## Rule

`.github/workflows/release.yml` has `name: Release`, `run-name` exactly `Release ${{ inputs.version }} @ ${{ inputs.sha }} dry_run=${{ inputs.dry_run }}`, `on` exactly `workflow_dispatch` with exactly the inputs `version` (string, required), `sha` (string, required) and `dry_run` (boolean, required `false`, default `true`), top-level `permissions: {}`, `concurrency` exactly `{group: release, cancel-in-progress: false}`, top-level `env` exactly `{DEV_UID: "1001", DEV_GID: "1001"}`, and exactly the jobs `verify`, `publish-image`, `publish-npm` and `read-back`.

## Rationale

A release starts only by an explicit dispatch whose approval page shows the version, commit and dry-run flag being approved; no push or PR event can publish. Source: [F-024 v2](../features/F-024-gated-publication.md).
