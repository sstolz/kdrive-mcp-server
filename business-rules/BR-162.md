## Rule

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11): v1 holds, and the process-wide windows also include `health_loopback` and `health_public`, 120 per 60 seconds each (BR-325). A `/healthz` request has no body to read; it is counted only after the shutdown, target-length, `Host`, method and framing checks of BR-322 pass, and a request refused by one of those checks or by 429 is not counted.

Process-wide windows, keyed by route, bound unauthenticated OAuth work: `/oauth/register` 30 per 3,600 seconds; `/oauth/authorize`, `/oauth/consent` and `/oauth/callback` 30 per 60 seconds each; `/oauth/token` 60 per 60 seconds. A request on these routes is counted and checked before its body is read; refusal is HTTP-layer error 429 `rate_limited` with `Retry-After`. MCP requests have no process-wide window: a request whose token verifies is never refused by one (D-7).

## Rationale

Process-wide windows keep the F-010 stores below their capacity while MCP requests carry no shared window. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-11.

## Examples

- **Given** 30 registrations in 3,600 seconds
  **When** a 31st arrives
  **Then** 429 `rate_limited` and no handler call.
- **Given** 1,000 MCP requests with invalid tokens in 60 seconds
  **When** a request with a valid token arrives
  **Then** it reaches the transport.
