# BR-276 — Owner-run write acceptance

## Rule

`make kdrive-write-acceptance` runs only on an actual main checkout (BR-215 v2 definition) inside the dev Compose service, reads the token through BR-212, requires `KDRIVE_WRITE_FOLDER` (a positive decimal folder ID) and refuses before any Docker command without it, configures the server with mode `write` and that folder as the only root, runs the two phases of the F-017 Acceptance sequence (deny list empty, then `**/*-deny*`) with at most 200 upstream requests within 600,000 ms, writes the audit log to a container temporary file, and prints only a sanitized summary (per-step pass/fail, statuses, request counts by method and route template, durations, main SHA) with no ID, name, path, token or `cancel_id`.

## Rationale

Real writes need the owner's token and a disposable folder (D-17-12); the report must leak nothing. Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** `KDRIVE_WRITE_FOLDER` unset
  **When** `make kdrive-write-acceptance` runs
  **Then** it prints `Set KDRIVE_WRITE_FOLDER to a positive decimal folder ID.` and no Docker command runs
- **Given** `KDRIVE_WRITE_FOLDER=42` on actual main with a valid acceptance directory
  **When** the target runs
  **Then** `node scripts/kdrive-write-acceptance.ts` starts in the dev service with the folder and SHA passed
