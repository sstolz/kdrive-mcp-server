## Rule

`ops/runner/Dockerfile` has exactly one `FROM`, `ghcr.io/actions/actions-runner:<version>@sha256:<64 hex>`, adds only the `make` package and the Docker Compose CLI plugin at an exact version whose SHA-256 is checked in the same `RUN`, copies `ops/runner/entrypoint.sh` as the image entrypoint, and ends with `USER runner`. `ops/runner/compose.yaml` defines exactly one service `runner` with image `kdrive-ci-runner:local`, `pull_policy: never`, `restart: "no"`, no `privileged`, `ports`, `network_mode`, `cap_add`, `devices`, `pid`, `environment` or `command`; its volumes are exactly `/var/run/docker.sock` → `/var/run/docker.sock`, `/home/runner/_work` → `/home/runner/_work` (identical paths, so job bind mounts resolve in the VM's Docker) and `/run/kdrive-runner` → `/run/kdrive-runner`; `group_add` is exactly `["${DOCKER_GID:?}"]`. The JIT configuration reaches the container only as the file `/run/kdrive-runner/jitconfig` on the VM's tmpfs `/run`, in a directory the supervisor recreates every cycle owned by uid 1001 with mode `0700`, the file owned by uid 1001 with mode `0400`, written from the stdin of `limactl shell` (BR-223). `entrypoint.sh` reads that file into a non-exported shell variable, deletes the file, exits nonzero with a fixed message when it was missing or empty or when the deletion fails, and then runs `exec ./run.sh --jitconfig "$cfg"`; no environment variable holds the value at any point.

## Rationale

The runner image is the pinned official image plus `make` and Compose, and the one-job JIT configuration never sits in an environment variable (T4, D-05, D-15). Source: [F-015 v1](../features/F-015-self-hosted-runner.md).

## Examples

- **Given** a JIT file holding a synthetic value
  **When** `entrypoint.sh` runs with a stub `run.sh`
  **Then** the stub receives `--jitconfig <value>`, the file is gone and no environment variable holds the value
- **Given** an empty JIT file
  **When** `entrypoint.sh` runs
  **Then** it exits nonzero with its fixed message and the stub never runs
