# BR-030 — Configured-root membership

## Rule

A configured-tree operation is authorized only when every affected existing identity and destination belongs to a configured drive and its own identity or complete ancestor chain includes a resolved root in that same drive, with root ID `1` treated as whole-drive membership.

The normalized evidence, matching, effect and paging details in
[F-003 v1](../features/F-003-tree-access-policy.md) remain normative.

## Rationale

Constrain token visibility to configured drive and folder identities.

## Examples

These are synthetic injected cases, not provider observations.

- **Given** root 7:10 and file 13 with ancestor 10, **When** reading file 13, **Then** the read is authorized.
- **Given** the same root and file 30 at /outside, **When** reading file 30, **Then** ACCESS_DENIED is returned.

Both examples map to the test or parameter rows named below.
