# BR-404 — Page language resolution

## Rule

Every proxy HTML page (consent page and every error page) is rendered in exactly one page language, `en` or `fr`, resolved per request in this order: (1) the request's `lang` query parameter when it is valid under BR-405 (authorize GET, the consent POST target of BR-129 v4, callback GET); (2) otherwise the `Accept-Language` result of BR-406; (3) otherwise `en`. The language is never read from a cookie, a form field, the client's registration or document, or stored state.

## Rationale

The owner chose English and French, with the browser's language as default, English as fallback and the choice carried in the URL, never stored (#31). Source: [F-031 v1](../features/F-031-oauth-proxy-page-languages.md).

## Examples

- **Given** an authorize request with `lang=fr` and `Accept-Language: en`
  **When** the page language is resolved
  **Then** `fr`
- **Given** an authorize request without `lang` and with `Accept-Language: fr`
  **When** the page language is resolved
  **Then** `fr`
- **Given** a request with `lang=de` and no `Accept-Language`
  **When** the page language is resolved
  **Then** `en`
