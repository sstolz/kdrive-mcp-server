## Rule

The stdio runtime writes only MCP protocol messages with sanitized tool/protocol error text to stdout, and emits to stderr only fixed sanitized diagnostics and, when `auditLog` is `stderr`, F-016 audit records (BR-234–BR-236).

v1, the active rule until v2 is accepted: The stdio runtime writes only MCP protocol messages with sanitized tool/protocol error text to stdout and emits only fixed sanitized diagnostics to stderr.

## Rationale

MCP framing and error redaction must survive invalid or hostile client/evidence input. Source: [F-005 v1](../features/F-005-stdio-navigation.md), AC-11.

## Examples

- **Given** a malformed JSON line containing a canary.
  **When** the actual stdio boundary receives it.
  **Then** the fixed -32700/null-ID frame appears without echo.
- **Given** an unknown tool or registered schema-invalid argument.
  **When** the client sends the request.
  **Then** fixed sanitized protocol/tool envelopes disclose no canary or dependency data.
- **Given** mode `write` with `auditLog=stderr` and a synthetic mutator
  **When** a gate run completes over the stdio composition
  **Then** stdout carries only MCP frames and stderr carries the intent and outcome records
