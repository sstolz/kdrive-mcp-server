# BR-413 — PDF object resolution

## Rule

An object is resolved only through the merged cross-reference table. A type 1 object is parsed at its offset as `<number> <generation> obj`, one value, an optional stream framed by its `/Length`, and `endobj`; its number and generation equal the entry's. A type 2 object is read from the object stream named by the entry, which is itself a type 1 object with `/Type /ObjStm`, a direct `/N` and `/First`; its header pair at the entry's index names the same object number, the object is the one value between its offset and the next, has generation 0 and is not a stream; `/Extends` is ignored. An indirect `/Length` resolves to a nonnegative integer object; resolving it never requires framing the stream it measures and opens at most one object stream, whose own `/Length` is direct or a type 1 integer object. A reference to a free, absent or mismatched object in a role the projection needs refuses. At most 4,096 objects are resolved per invocation (the F-009 indirect-object ceiling).

## Rationale

Object streams and indirect lengths are common (F-034 S06, S08). Locating an object stream only through a type 1 entry and limiting length resolution to one object stream stops recursion and length chains. Source: [F-034 v1](../features/F-034-pdf-extraction-profile.md).

## Examples

- **Given** all non-stream objects stored in one object stream
  **When** page 1 is read
  **Then** its text
- **Given** a type 2 entry naming an object stream that is itself a type 2 object
  **When** page 1 is read
  **Then** `CONTENT_UNAVAILABLE` before PDF.js
