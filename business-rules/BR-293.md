# BR-293 — File and directory checks before use

## Rule

Before the file is used: its parent directory must exist, be a directory (by `lstat`, not a symlink) owned by the effective user ID with the owner read, write and search bits (`mode & 0o700 === 0o700`) and no group or other write bit (`mode & 0o022 === 0`); the path, when present, must be by `lstat` a regular file (not a symlink) with one link (`nlink === 1`), owned by the effective user ID, with the owner read and write bits (`mode & 0o600 === 0o600`) and no group or other permission bit (`mode & 0o077 === 0`); when absent it is created with `O_CREAT | O_EXCL | O_NOFOLLOW | O_CLOEXEC` and mode `0600`. The path `<path>-journal`, when present before SQLite opens the file, must pass the same checks as the path. Neither `<path>-wal` nor `<path>-shm` may exist (by `lstat`, whatever its type, a dangling symlink included). After SQLite has opened the path, a second `lstat` must give the same device and inode (BR-295 step (3a)), and SQLite must not have opened the database read-only, which is detected by the failure of the real write that BR-295 step (11) always commits (`BEGIN EXCLUSIVE` succeeds on a read-only database; only the first write fails, D-2). Any failure stops startup with `OAUTH_STATE_UNAVAILABLE` (BR-297), changes no mode, owner or content of the file or the journal and creates no `<path>-wal` or `<path>-shm`, except the `<path>-wal` that SQLite may create in the residual case of BR-295 step (3b) (D-9).

## Rationale

A state file that others can read or write, or that was swapped, is a credential leak; the server refuses it instead of repairing it. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** a missing parent directory
  **When** the store opens
  **Then** `OAUTH_STATE_UNAVAILABLE`
- **Given** a parent directory that is a symlink
  **When** the store opens
  **Then** `OAUTH_STATE_UNAVAILABLE` and nothing is created
- **Given** an absent path in a `0700` directory owned by the effective user
  **When** the store opens
  **Then** the file is created with mode `0600`
- **Given** an existing file with mode `0640`
  **When** the store opens
  **Then** `OAUTH_STATE_UNAVAILABLE` and the mode is unchanged
- **Given** a path replaced between the checks
  **When** the store opens
  **Then** `OAUTH_STATE_UNAVAILABLE`
