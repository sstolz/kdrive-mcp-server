## Rule

A sanitized recording keeps only the JSON members of the Recorded-members list and drops every other member (emails, users, `created_by`, drive names, share links, timestamps included). It replaces every drive/file ID except `1` by a consistent synthetic ID, assigned only after the whole session is recorded, drawn sequentially from 1,000,001 upward and skipping every real ID observed in the session, every name by an alias (`n<k>` for manifest fixtures, `x<k>` for any other entry, so entry counts are preserved), every path by the path rebuilt from aliases with the literal components `Shared` and `Private` kept, every ETag and cursor by a synthetic value preserving equality, and every storage `Location` by `https://s1.download.kdrive.infomaniakusercontent.com/r`; it keeps only the header allowlist (`status`, `content-type`, `content-length`, `content-range`, `accept-ranges`, `etag`, `location`) and body bytes only of the designated synthetic binary. Synthetic cursors are `cursor<k>` and synthetic ETags `"etag<k>"`, each `k` a decimal counter from 1 in first-seen order per kind, so neither contains a whole decimal token and every ETag stays within BR-205's bound. The leak check refuses output containing the token, any real ID other than `1` as a whole decimal token (a digit run with no letter, digit or underscore immediately before or after it) outside the exempt fields, any real name of 4 or more bytes seen in any response, any `@` between word characters, or any `http:`/`https:` URL other than the fixed synthetic `Location`. The exempt fields are an exchange `template` exactly equal to a route-table template, a hop's `status`, the `limit` query value, the request `range`, the `content-length` and `content-range` header values, and the value of every `size` member; only the real-ID search skips them. Each exempt value has its form or the check fails: `status` an integer from 100 to 599, `limit` exactly `50`, `range` `bytes=<a>-<b>`, `content-range` `bytes <a>-<b>/<n>` or `bytes */<n>` with `<a>`, `<b>` and `<n>` decimal digits, `content-length` decimal digits, and `size` a nonnegative integer or `null`; a form violation fails with the category `exempt field form` and its location only. The `content-type` value is searched with its `charset=utf-8` parameter (ASCII case-insensitive) removed. A failure message names only the category and, for real IDs, the digit count and the JSON location of each colliding ID, never a value; a location prints array indices as numbers and a member name only when it is in the Recorded-members list, the header allowlist, the route-table path placeholders, or the recording schema (`exchanges`, `template`, `params`, `query` as `[name, value]` pairs, `range`, `hops`, `status`, `headers`, `json`, `body`), and every other member name as `<member>`. Verified by: AC-21.

## Rationale

Recordings are committed; every real identifier, name, path, link, user or token must be removed before anything is written. Source: [F-014 v5](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** a response holding an email, a share link and a `created_by` object
  **When** the session is sanitized
  **Then** only Recorded members remain and names become `n<k>`/`x<k>`.
- **Given** output still containing the token
  **When** the leak check runs
  **Then** nothing is written.
- **Given** real ID 200 and a hop whose `status` is 200
  **When** the leak check runs
  **Then** it passes.
- **Given** real ID 200 and an unexpected member `depth: 200`
  **When** the leak check runs
  **Then** nothing is written and the message names `real ID of 3 digits at …<member>`.
- **Given** real ID 50 and a query `limit=50`
  **When** the leak check runs
  **Then** it passes.
- **Given** a query `limit=100`
  **When** the leak check runs
  **Then** nothing is written and the message names `exempt field form at exchanges[<i>].query[<j>][1]`.
