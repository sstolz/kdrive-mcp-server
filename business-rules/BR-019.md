# BR-019 — Explicit configured-drive allowlist

Statement preserved from [F-002 v1](../features/history/F-002-v1.md); accepted under [F-002 v2](../features/F-002-configuration.md). The v2 CLI diagnostic phase ordering applies without rewriting this rule.

## Rule

Require at least one explicit drive identifier: `driveId` or
`driveIds`. When only `driveId` is supplied, the allowlist is that singleton;
when only `driveIds` is supplied, the first listed ID is the default. When
both are supplied, the default must belong to the allowlist. Reject invalid,
duplicate or out-of-bound IDs. Never infer configured drives from a token or
from a preflight response; retain the supplied drive order.

The source specification's inventory, bounds, grammars, auth matrix, credential
contract, error mapping and preflight port supply the normative details for
this statement; this record does not redefine those tables.

## Rationale

Token visibility must never decide which drives the server exposes.

## Examples

These examples illustrate the accepted rule; they do not replace the source specification or claim a new test execution. Unless a scenario overrides them, local-loader fixtures use explicit drive `7` and token `SYNTHETIC_TOKEN`, with no deployment state. Each verification reference identifies one existing test case or table row.

- **Given** only `KDRIVE_ID=7` and a valid synthetic token.
  **When** drive selection is normalized.
  **Then** default drive is `7` and the exact allowlist is `[7]`.
  Verified by: [`derives defaults while retaining exact allowlists`](../tests/config.test.ts), singleton assertion.

- **Given** only `KDRIVE_IDS=08,7` and a valid synthetic token.
  **When** drive selection is normalized.
  **Then** default drive is `8`, the ordered allowlist is `[8, 7]`, and the leading zero is normalized.
  Verified by: [`derives defaults while retaining exact allowlists`](../tests/config.test.ts), IDs-only assertion.

- **Given** a synthetic token but neither singular nor plural drive setting.
  **When** drive selection is validated.
  **Then** it rejects with `{code: MISSING_REQUIRED, setting: driveIds}`.
  Verified by: [`derives defaults while retaining exact allowlists`](../tests/config.test.ts), neither-drive assertion.

- **Given** `KDRIVE_ID=7` and `KDRIVE_IDS=8,9`.
  **When** drive selection is validated.
  **Then** it rejects with `{code: CONFLICTING_SETTINGS, setting: driveId}` because the default is outside the allowlist.
  Verified by: [`derives defaults while retaining exact allowlists`](../tests/config.test.ts), default-membership assertion.

- **Given** `KDRIVE_ID=7` and plural IDs `1,2,3,...,64` enumerating every integer from `1` through `64`.
  **When** drive selection is normalized.
  **Then** 64 distinct configured drives are accepted, including minimum ID `1`.
  Verified by: [`accepts exact string/list maxima and rejects adjacent values`](../tests/config.test.ts), 64-drive assertion.

- **Given** `KDRIVE_ID=0`.
  **When** drive selection is validated.
  **Then** it rejects with `{code: INVALID_VALUE, setting: driveId}`.
  Verified by: [`rejects ID %s`](../tests/config.test.ts), row `0`.

- **Given** `KDRIVE_ID=9007199254740991`.
  **When** drive selection is normalized.
  **Then** the default drive is `9007199254740991`, the maximum safe integer.
  Verified by: [`preserves literal YAML paths and allows explicit whole roots`](../tests/config.test.ts), maximum ID assertion.

- **Given** `KDRIVE_ID=9007199254740992`.
  **When** drive selection is validated.
  **Then** it rejects with `{code: INVALID_VALUE, setting: driveId}`.
  Verified by: [`rejects ID %s`](../tests/config.test.ts), row `9007199254740992`.

- **Given** `KDRIVE_ID=7` and plural IDs `1,2,3,...,65` enumerating every integer from `1` through `65`.
  **When** drive-list count is checked.
  **Then** it rejects with `{code: LIMIT_EXCEEDED, setting: driveIds}`.
  Verified by: [`rejects root/drive case %j`](../tests/config.test.ts), 65-drive row.

- **Given** `KDRIVE_IDS=7,07`.
  **When** drive-list duplicates are checked after numeric normalization.
  **Then** it rejects with `{code: INVALID_VALUE, setting: driveIds}`.
  Verified by: [`rejects root/drive case %j`](../tests/config.test.ts), row `KDRIVE_IDS: "7,07"`.
