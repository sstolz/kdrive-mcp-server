# BR-363 — Version unpublished and npm placeholder in place

## Rule

npm: `GET <registry>/@sstolz%2fkdrive-mcp-server` returning 404 passes only when `RELEASE_DRY_RUN` is `true`; 200 passes only if neither `versions` nor `time` has the key `<version>`; any other status fails. When `RELEASE_DRY_RUN` is `false`, the same request must return 200 (else `npm placeholder missing (P-0)`) and `dist-tags.latest` must name another version whose `deprecated` is a non-empty string (else `npm latest is not a deprecated placeholder (P-0)`). GHCR: a pull token obtained with `GITHUB_TOKEN` (non-200 fails with `unexpected GHCR token status <code>; refer to the owner`), then `HEAD /v2/sstolz/kdrive-mcp-server/manifests/<version>`: in phases `verify` and `image` 404 passes and 200 fails; in phase `npm` 200 passes and 404 fails with `image not pushed`; any other status fails with `unexpected GHCR status <code>; refer to the owner`. These checks and BR-378 run in `release-check` before every publish step.

## Rationale

A version is never published twice, npm `latest` stays on the deprecated placeholder, and an unexpected registry answer stops the run for an owner decision. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** npm 200 with only the deprecated `0.0.0-placeholder.0` on `latest` and dry run `false`
  **When** `release-check` runs in phase `verify`
  **Then** the npm checks pass
- **Given** npm 404 and dry run `false`
  **When** `release-check` runs
  **Then** it fails with `npm placeholder missing (P-0)`
- **Given** GHCR manifest 401
  **When** `release-check` runs
  **Then** it fails with `unexpected GHCR status 401; refer to the owner`
