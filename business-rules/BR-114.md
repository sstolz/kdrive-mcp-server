## Rule

PDF extraction accepts only the bounded preflight profile and never starts PDF.js on unsupported, malformed or over-budget containers.

**v2 (F-034 v1, #4, pending acceptance; v1 stays the accepted rule until then)** — v1 holds with the profile of F-034: only input that passes BR-412–BR-418 is accepted, and PDF.js only ever receives the canonical projection of BR-415, never source bytes. The header is `%PDF-1.0` to `%PDF-1.7` or `%PDF-2.0`. A refusal is `LIMIT_EXCEEDED` when a ceiling of F-009 or F-034 is passed, otherwise `UNSUPPORTED_FORMAT` for a well-formed file using a feature outside the profile, otherwise `CONTENT_UNAVAILABLE` for a file that contradicts its own structure.

## Rationale

Compressed source size alone does not bound parser expansion or text production. Source: [F-009 v1](../features/F-009-bounded-content-reading.md). v2: the closed v1 profile refused 18 of 20 synthetic files carrying one common generator feature each; a projection admits them while PDF.js still sees only bounded canonical input ([F-034 v1](../features/F-034-pdf-extraction-profile.md), ADR-012).

## Examples

- **Given** classic xref, one Flate page stream and simple Helvetica WinAnsi.
  **When** admission runs.
  **Then** bounded canonical uncompressed bytes reach PDF.js.
- **Given** a4097-byte Flate expansion with budget4096.
  **When** preflight runs.
  **Then** LIMIT_EXCEEDED occurs before PDF.js.
- **Given** a PDF 1.5 file with a cross-reference stream, an object stream and a Type0 `ToUnicode` font (v2)
  **When** page 1 is read
  **Then** its text is returned and PDF.js receives no `/XRef`, `/ObjStm` or font program
- **Given** a well-formed file with `/Encrypt` (v2)
  **When** page 1 is read
  **Then** `UNSUPPORTED_FORMAT` before PDF.js
