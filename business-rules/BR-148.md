# BR-148 — Same-repository pull-request analysis

## Rule

`make sonar-pr` analyses only a clean checkout whose provenance is a
same-repository pull request into `main`: `GITHUB_ACTIONS=true`,
`GITHUB_EVENT_NAME=pull_request`, `GITHUB_REPOSITORY` and
`SONAR_PR_HEAD_REPOSITORY` both equal `sstolz/kdrive-mcp-server` (an empty or
missing value is foreign), `GITHUB_BASE_REF=main`, `GITHUB_REF` matches
`^refs/pull/[1-9][0-9]*/merge$`, and `GITHUB_SHA` is a 40-hex commit equal to
`HEAD` and to the snapshot commit. It sends project key `kdrive-mcp-server-pr`
as `-Dsonar.projectKey=kdrive-mcp-server-pr` (never `kdrive-mcp-server`),
passes `sonar.scm.revision` = that commit, no `sonar.branch.*` or
`sonar.pullrequest.*` parameter, waits up to 300 seconds for this task's
Quality Gate within the shared 15-minute deadline, verifies the task metadata
`projectKey=kdrive-mcp-server-pr`, and exits nonzero on any failed gate,
scanner, network, processing or timeout outcome. Any other provenance is
rejected before coverage and upload.

## Rationale

Community Edition has no PR analysis; a dedicated project gives each same-repository PR a blocking gate without touching the main project. Source: [F-011 v1](../features/F-011-pre-merge-quality-gates.md).

## Examples

- **E-01 — Given** the trusted same-repository merge-commit environment
  **When** PR provenance is inspected
  **Then** the snapshot carries `event=pull_request` and `ref=refs/pull/7/merge`.
- **E-02 — Given** `SONAR_PR_HEAD_REPOSITORY=fork/kdrive-mcp-server`
  **When** PR provenance is inspected
  **Then** it is rejected before coverage.
- **E-03 — Given** a fake scanner returning exit 3 in PR mode
  **When** the wrapper runs
  **Then** it returns 3.
