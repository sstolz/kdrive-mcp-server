## Rule

`scripts/image-smoke.sh` exits non-zero on the first failed check, writes one line naming that check to stderr, and on every exit path removes (`docker rm -f`) only the containers it started; it removes no image, volume or other container.

## Rationale

Failures are diagnosable and the runner never touches unrelated Docker state. Source: [F-013 v1](../features/F-013-http-image.md).

## Examples

- **Given** a stub docker failing the `metadata` check
  **When** the runner runs
  **Then** it exits non-zero, prints one line naming `metadata`, and removes exactly the containers it started
- **Given** an unsupported platform
  **When** the runner runs
  **Then** it fails before calling docker
