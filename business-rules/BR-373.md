# BR-373 — Image read-back

## Rule

`release-verify` reads the GHCR manifest of tag `<version>` with a pull token: it is an OCI image index or Docker manifest list whose non-attestation entries have exactly the platforms `linux/amd64` and `linux/arm64`, and tag `latest` returns 404 or another digest. It prints `release-verify: image digest sha256:<hex>`. The check `image is public (P-3)` requests an anonymous pull token and then `HEAD` the manifest with it, passing only when both return 200. It prints one line per condition like BR-365 and exits 0 only when all hold.

## Rationale

The pushed image must serve both platforms publicly, must not be `latest`, and its digest must be printed so users can pin it. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** an index with `linux/amd64` and `linux/arm64` and a public package
  **When** `release-verify` runs
  **Then** it passes and prints the index digest
- **Given** an index lacking `linux/arm64`
  **When** `release-verify` runs
  **Then** it fails
