# BR-325 — Health windows

## Rule

Two process-wide windows bound `/healthz`, each 120 requests per 60 seconds: `health_loopback` counts requests whose `Host`, lowercased, is a BR-324 loopback form (even when it is also an accepted public form), and `health_public` counts every other accepted `Host`. A request is counted in its window only after it passes checks (1)–(5) of BR-322; requests refused by those checks or by 429 are not counted. A full window refuses only its own requests, with 429 `rate_limited`, `Retry-After` (the seconds until that window ends) and one `request_refused` event with `route` `health`.

## Rationale

Bounds anonymous handler work while keeping a flood through the public host from failing a loopback probe (D-8). Source: [F-021 v1](../features/F-021-container-health-check.md).

## Examples

- **Given** a fixed clock and 120 public-`Host` GETs on `/healthz` in the window
  **When** the 121st arrives
  **Then** 429 `rate_limited` with `Retry-After: 60` and one `request_refused` event `{route: "health", status: 429, error: "rate_limited"}`
- **Given** the same full `health_public` window
  **When** a GET with `Host: 127.0.0.1:3000` arrives
  **Then** 200
- **Given** the same full window
  **When** 60 s pass and a GET arrives
  **Then** 200
