# BR-361 — Tagged main HEAD is the dispatched commit

## Rule

`refs/tags/v<version>` exists and `v<version>^{commit}` equals `RELEASE_SHA` (lightweight or annotated), `git merge-base --is-ancestor <sha> refs/remotes/origin/main` succeeds, and `GITHUB_SHA` (passed by name) equals `RELEASE_SHA`, else the check fails with `sha is not the dispatched commit`; an unset `GITHUB_SHA` fails the same way. A missing tag, a tag on another commit and a commit not on `main` each fail their check.

## Rationale

Provenance and the npm OIDC claim name `GITHUB_SHA`, and the running workflow comes from it, so the release commit must be the tagged `main` HEAD at dispatch. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** an annotated tag on the release commit and `GITHUB_SHA` equal to it
  **When** `release-check` runs
  **Then** the tag and commit checks pass
- **Given** `GITHUB_SHA` set to the parent commit
  **When** `release-check` runs
  **Then** the check fails with `sha is not the dispatched commit`
