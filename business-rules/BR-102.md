## Rule

The provider verdict is `delegate-capable` when discovery is usable, PKCE S256 and JWKS are `yes`, dynamic registration or CIMD is `yes`, the access token is authenticated and any returned ID token is rejected with 401; `delegate-static-capable` under the same conditions without either registration mechanism; `proxy-only` when delegation fails, discovery is usable, PKCE S256 is `yes` and a usable ID token was returned; `unsupported` otherwise; `incomplete` for a `discover`-only run or a started `token` run without token response. Identity results never change it.

## Rationale

The decision that gates P-12 must follow from evidence and be reproducible from the report. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-14.

## Examples

- **Given** all delegation conditions with dynamic registration `yes`.
  **When** the verdict is computed.
  **Then** it is `delegate-capable`.
- **Given** the same run whose real ID token the validator accepts, with a usable ID token.
  **When** the verdict is computed.
  **Then** it is `proxy-only`.
- **Given** a `discover`-only run.
  **When** the verdict is computed.
  **Then** it is `incomplete`.
