# BR-268 — Raw port result; the mutator alone validates

## Rule

Once the status line and headers are received, the port returns `{status, retryAfter?, body?}`, where `retryAfter` is the raw `Retry-After` text only when it is at most 32 bytes and `body` holds the bytes of a 2xx body only when it is complete within the BR-194 limits; a non-2xx body is discarded after at most 8 KiB. The port never parses or validates a body: the mutator alone does, and returns the gate reply `{outcome:"response", status, retryAfter?, accepted, value?, created?}` with `accepted:true` only when `body` is present, is JSON with `result` equal to `success`, and its `data` passes the kind's check (BR-272, BR-273); any other 2xx gives `accepted:false`.

## Rationale

An unchecked 2xx must never become `succeeded`. Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** a 200 body larger than 4 MiB
  **When** a trash run ends
  **Then** the result is `uncertain`
- **Given** a 429 with a 33-byte `Retry-After`
  **When** a trash run continues
  **Then** the retry waits 1,000 ms (no `retryAfter` passed)
