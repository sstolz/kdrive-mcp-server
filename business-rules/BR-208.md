## Rule

The token is read only through the existing F-002 sources. After `loadConfiguration` the CLI deletes `KDRIVE_TOKEN` from its environment object, passes the token only to the adapter factory, and passes to `preflightConfiguration` and to each runtime only the configuration returned by `withoutCredential(local)` (exported from `src/config.ts`: a frozen copy whose `token` is the empty string and which has no `tokenFile`). No exported value, runtime configuration, error, log line, MCP result, HTTP event, recording or acceptance report contains the token.

## Rationale

The token must stay confined to the adapter closure and the API Authorization header; runtimes and logs never need it. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** an environment object holding `KDRIVE_TOKEN`
  **When** `main` loads the configuration
  **Then** the key is deleted and the runtimes receive a configuration whose `token` is empty.
- **Given** an upstream 401 echoing the token
  **When** the client calls `kdrive_info`
  **Then** the result, stderr and stdout do not contain the token.
