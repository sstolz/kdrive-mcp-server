## Rule

`describe` reads fresh metadata, then issues one download with `Range: bytes=0-0`; it returns `version_bound:true` and `etag` = `"kd1-` + base64url(SHA-256(provider ETag bytes)) + `"` only when the metadata is a live `file` of size ≥ 1, the response is 206 with `Content-Range: bytes 0-0/<size>` equal to the metadata size, and the provider ETag is 1–256 visible ASCII bytes; when the metadata is a valid live item but any of these conditions fails (not a file, size 0, a 2xx download that fails the range or length checks, or an absent or out-of-range ETag) it returns a descriptor whose `etag` is `null`, which the content reader refuses with `VERSION_UNAVAILABLE`.

## Rationale

Version binding needs a strong ETag that changes with the content; deriving it from the opaque provider value hides that value and keeps the scheme versioned. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** a 16-byte file whose `bytes=0-0` download is 206 `bytes 0-0/16` with ETag `"opaque-etag-1"`
  **When** `describe` runs
  **Then** it returns `version_bound:true` and `etag` `"kd1-<base64url sha256>"`.
- **Given** the same file with a 257-byte ETag
  **When** `describe` runs
  **Then** it returns `etag:null` and the reader refuses `VERSION_UNAVAILABLE`.
