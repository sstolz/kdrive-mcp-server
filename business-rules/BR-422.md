# BR-422 — Peer of an OAuth request

## Rule

The peer of a request on an OAuth route is derived from the socket's remote address `S`, as Node reports it, and the BR-421 list `T`:

(1) every address is normalised before it is compared or used: an IPv4-mapped IPv6 address becomes its IPv4 address and an IPv6 zone index (`%…`) is dropped; an IPv4 address never matches an IPv6 entry of `T`, nor the reverse;

(2) when `T` is empty or `S` is not inside an entry of `T`, the peer address is `S`, and no forwarding header is read;

(3) otherwise the `X-Forwarded-For` field lines are joined in order with commas and split on commas, each element is trimmed of spaces and tabs, and the elements are examined from the rightmost, at most 32 of them; the walk ends at the first element that is not an IPv4 address in dotted-decimal form without leading zeros or an IPv6 address without brackets, port or zone (an empty element included), at the leftmost element, or after the 32nd; the peer address is the first examined valid element that is not inside an entry of `T`; when there is none, it is the leftmost valid element examined, or `S` when no examined element was valid (no header, an empty one, or an invalid rightmost element);

(4) the peer is the IPv4 peer address itself, or the first 64 bits of an IPv6 peer address: two IPv6 addresses whose first 64 bits are equal are the same peer; a socket without a remote address is the one peer `unknown`;

(5) the `Forwarded`, `X-Real-IP` and other `X-Forwarded-*` headers are never read, and the peer serves only the BR-162 v3 windows.

## Rationale

The per-peer windows of BR-162 v3 need a client identity that a client cannot choose: the socket address by default, and the address a listed proxy observed itself when the request comes through one. Walking `X-Forwarded-For` from the right stops before any client-supplied element; IPv6 is grouped per `/64` so that one host cannot spread over 2^64 peers (F-035 D-4). Source: [F-035 v1](../features/F-035-oauth-proxy-hardening.md).

## Examples

- **Given** an empty trusted list and socket `127.0.0.1`
  **When** a request carries `X-Forwarded-For: 203.0.113.9`
  **Then** the peer is `127.0.0.1`
- **Given** trusted list `127.0.0.1` and socket `127.0.0.1`
  **When** a request carries `X-Forwarded-For: 198.51.100.1, 203.0.113.9`
  **Then** the peer is `203.0.113.9`
- **Given** trusted list `127.0.0.1` and socket `127.0.0.1`
  **When** a request carries `X-Forwarded-For: junk`
  **Then** the peer is `127.0.0.1`
- **Given** trusted list `127.0.0.0/8` and socket `127.0.0.1`
  **When** `X-Forwarded-For` holds `198.51.100.1` followed by 31 elements `127.0.0.3`, then by 33
  **Then** the peer is `198.51.100.1`, then `127.0.0.3`
- **Given** sockets `2001:db8:1:2::1` and `2001:db8:1:2::5%eth0`
  **When** their peers are derived
  **Then** they are the same peer, and `2001:db8:1:3::1` is another
- **Given** sockets `192.0.2.7` and `::ffff:192.0.2.7`
  **When** their peers are derived
  **Then** they are the same peer
