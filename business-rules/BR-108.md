## Rule

Each row of the compatibility matrix names the client, the documentation check date, at least one `https` source, `supported`, `not supported` or `unverified` for dynamic registration, CIMD, manual client ID entry and rejection of inconsistent issuer identification, the redirect URI forms with their conditions or `unverified`, the MCP authorization version or `unverified`, and a real-test result in `not tested`, `passed`, `failed`; a fact not read in the cited source on the check date is `unverified`. The matrix states the reference version 2026-07-28 and, per row, whether the stated version equals it.

## Rationale

Client decisions are only as good as the documented facts behind them; unread facts must stay visible as unverified. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-19.

## Examples

- **Given** `docs/mcp-client-compatibility.md`.
  **When** the matrix check runs.
  **Then** six rows exist with valid dates, `https` sources and allowed values.
- **Given** a row whose dynamic-registration value is `maybe`.
  **When** the matrix is parsed.
  **Then** parsing fails.
