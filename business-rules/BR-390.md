# BR-390 — Direct codec calls of the image route

## Rule

`extractImage` decodes an admitted PNG with `PNG.sync.read(bytes, { checkCRC: true })` of `pngjs` and an admitted JPEG with `decode(bytes, { tolerantDecoding: false, maxResolutionInMP: 1048576 / 1000000, maxMemoryUsageInMB: 32 })` of `jpeg-js`, with exactly these option objects; it keeps the existing check that the decoded width, height and data length match the preflight plan. It encodes every attempt with `new PNG({ width, height })` of `pngjs`, `data` set to the current RGBA bitmap, and `PNG.sync.write(png, { deflateLevel: 9, deflateStrategy: 3, filterType: -1, colorType: 6, inputHasAlpha: true })`. Through `kdrive_read`, a 600 × 400 white PNG is returned as a 512 × 341 PNG. `extractImage` does not catch, wrap or translate an exception thrown by `pngjs` or `jpeg-js`: it rejects with that exception unchanged (an `Error` that is not a `ContentFailure`), and `src/extraction-worker.ts` keeps its mapping of such an error to `CONTENT_UNAVAILABLE` unchanged.

## Rationale

The calls and options are the ones Jimp 1.6.1 made, so the image route's output, a user-visible contract (BR-116), stays byte-identical without Jimp, and codec errors keep their existing path (D-2, D-10, ADR-010). Supersedes BR-317, whose purpose (Jimp's schemas on the root Zod) disappears with Jimp. Source: [F-027 v2](../features/F-027-direct-image-codecs.md).

## Examples

- **Given** `pngjs` and `jpeg-js` wrapped by delegating spies
  **When** `extractImage` processes a PNG and a JPEG
  **Then** `PNG.sync.read` received `{ checkCRC: true }`, `decode` received `{ tolerantDecoding: false, maxResolutionInMP: 1.048576, maxMemoryUsageInMB: 32 }`, and every `PNG.sync.write` call received the encode options above
- **Given** a 600 × 400 white PNG
  **When** it goes through `kdrive_read` with `format: image`
  **Then** the result is a 512 × 341 PNG
- **Given** a 4 × 2 colour-type-6 PNG whose first scanline has filter type 5
  **When** `extractImage` runs
  **Then** it rejects with `Error: Unrecognised filter type - 5`, not a `ContentFailure`, and `kdrive_read` returns `CONTENT_UNAVAILABLE`
