## Rule

**v3 (F-048 v1, #110, pending acceptance).** v2 holds with optional diagnostic
path evidence from the same successful path walk or ID-metadata response.
A completed path walk supplies its exact API path. For IDs, use live-tree
`treeItem` normalization, including identity and ancestry consistency; a
validated drive-root directory ID `1` has path `/`. Missing or invalid optional
path evidence is unknown, with no fallback to a rejected raw provider path.
No extra metadata request, parent walk, retry or descendant listing is added.
Mandatory identity/type checks, errors, request counts and budgets remain
unchanged. These paths are diagnostic snapshots and never authorize access.

**v2 (F-044 v1, #88, accepted; the active rule).** v1 holds with two replacements. Remove “a non-directory
intermediate component, zero or several matches for a component” from v1's
rejection list. `resolveDirectory` resolves to `null` when a path component
has zero exact-name matches, several exact-name matches or a non-directory
match. This includes a final file. A unique final directory match still
returns its directory record. Replace “`src/config.ts`
maps any rejection to `PREFLIGHT_FAILED`, and a resolved non-directory to
`ROOT_NOT_RESOLVED`” with: explicit unresolved path results and returned
non-directories map to `ROOT_NOT_RESOLVED (roots)`; upstream failures and
other rejections map to `PREFLIGHT_FAILED (preflight)`. A malformed kDrive
response rejects and gives `PREFLIGHT_FAILED (preflight)`. A malformed
resolver return value keeps the v1 `ROOT_NOT_RESOLVED` mapping. Missing ID
metadata and the 64-component, 1,024-request and 120,000 ms bounds retain
v1 behavior.
`inspectDrive` is unchanged. Names still match exactly and case-sensitively.
Each component uses the same complete listing pages as v1. The request
sequence and count stay unchanged for identical responses. No probe or retry
is added.

v2 is the active rule after acceptance on main `3f6e291` on 2026-11-19 ([#88 acceptance](https://github.com/sstolz/kdrive-mcp-server/issues/88#issuecomment-7005778721)).
The accepted v1 text below is preserved as history; v2 supersedes it.

### v1 (accepted)

`inspectDrive` returns `{id, role}` with the provider role of that drive from one `/2/drive/init?with=drives` request, or role `"absent"` when the drive is not listed. `resolveDirectory` returns `{driveId,id,type}` with the item's own `type` from fresh metadata for an ID selector, and for a path selector walks from root `1` through complete children listings (BR-201) matching each component by exact name and returns the unique final match with its own `type`. It rejects for a missing ID, a non-directory intermediate component, zero or several matches for a component, more than 64 components, more than 1,024 requests or more than 120,000 ms in one preflight. The resulting F-002 codes are those of AC-16 (`src/config.ts` maps any rejection to `PREFLIGHT_FAILED`, and a resolved non-directory to `ROOT_NOT_RESOLVED`).

## Rationale

The server must start only on admin drives and resolvable directory roots, within fixed request and time bounds. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).
