# BR-035 — Derived operation effects

## Rule

The policy derives the complete effect set from a recognized operation kind and validated arguments according to the effect matrix below; callers cannot omit required effects or supply an alternate effect set.

The normalized evidence, matching, effect and paging details in
[F-003 v1](../features/F-003-tree-access-policy.md) remain normative.

Since v2 (F-018): A `replace` operation carries exactly `target`, `destination` and `name`; the core inspects the target and the destination `live`, and authorizes it only when the target is a file whose immediate parent ID equals the destination ID and whose name equals `name` exactly (code-point equality), the destination is an authorized live directory, and the path `destination/name` (equal to the target's current path) is permitted; any difference is denied with zero intent records and zero mutation requests; an operation without `destination` or `name` is invalid. This supersedes the F-003 v1 effect-matrix row "Replace/upload existing file".

## Rationale

Do not let a caller omit an existing source or resulting path check.

## Examples

These are synthetic injected cases, not provider observations.

- **Given** write mode and deny **/secret, **When** creating secret inside permitted directory 11, **Then** dispatch is denied.
- **Given** write mode and deny /r/a/**, **When** replacing file 13 at /r/a/report, **Then** dispatch is denied.

Both examples map to the test or parameter rows named below.
