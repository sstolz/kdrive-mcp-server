# BR-363 — Version unpublished and npm placeholder in place

## Rule

### v3 — accepted (active)

Release-check admits registry state exactly when the npm
and GHCR preflight predicates in the v4 phase matrices hold. Verified by:
AC-38, AC-39, AC-40, AC-41, AC-45.
Change from v2: removes the blanket #91 refusal, accepts an older stable
npm latest, accepts its matching GHCR default before stable image push,
compares stable candidates only against published stable versions, admits
a deprecated stable default for a gated stable fix, and retains the new
run's digest binding in phase npm; beta preflight checks the GHCR default
against the npm stable default in every phase. Every admitted stable advances npm
latest and GHCR latest; beta publication leaves both defaults unchanged.

v3 is the active rule after acceptance on main `d30b3ff` on 2026-11-18
([#91 acceptance](https://github.com/sstolz/kdrive-mcp-server/issues/91#issuecomment-6992434783)).

### v2 — accepted (superseded by v3)

Accepted on main `6a508ab` (#89 comments `89-acceptance-1-claude` and `89-acceptance-2-owner`).

Stable preflight requires npm 200 with readable `versions`
and `time` objects. The candidate is absent from both. npm `latest` is
exactly `0.0.0-placeholder.0`, whose version entry has a non-empty
`deprecated` string. The candidate is strictly greater in SemVer precedence
than every published version in either object except that placeholder.
In `time`, ignore exactly `created` and `modified`. Every other key must
be valid SemVer. Malformed version keys fail closed. Compare numeric
components as exact integers. Build metadata does not affect precedence.
Include published betas, even betas above the candidate's base version.
A readable npm document with non-placeholder `latest` or any stable version
key in `versions` or `time`, except `0.0.0-placeholder.0`, refuses every
release kind in `release-check` with the #91 diagnostic below. This applies
in phases `verify`, `image` and `npm`, with either dry-run value, never to
read-back. This holds even if `latest` was reset to the placeholder. There is no emergency path.
Missing or malformed registry data fails closed. Stable has no npm-404 exemption.

Before stable image publication, both GHCR candidate and `latest` must
return 404. In stable phase `npm`, both must return 200 and resolve to
exactly `RELEASE_IMAGE_DIGEST`. Compute SHA-256 over raw GET response bytes
with the identical Accept list for both tags:
`application/vnd.oci.image.index.v1+json, application/vnd.docker.distribution.manifest.list.v2+json`.
Never compare HEAD digests. Require valid image indexes and fail closed
on missing digests, token errors or unexpected statuses. Keep v1 token
and unexpected-status diagnostics. BR-378 still runs in every phase.
Before first stable, beta retains v1/v2 checks, including npm dry-run 404,
no ordering against published betas, and no new GHCR latest preflight.

### v1 — accepted (superseded by v2)

npm: `GET <registry>/@sstolz%2fkdrive-mcp-server` returning 404 passes only when `RELEASE_DRY_RUN` is `true`; 200 passes only if neither `versions` nor `time` has the key `<version>`; any other status fails. When `RELEASE_DRY_RUN` is `false`, the same request must return 200 (else `npm placeholder missing (P-0)`) and `dist-tags.latest` must name another version whose `deprecated` is a non-empty string (else `npm latest is not a deprecated placeholder (P-0)`). GHCR: a pull token obtained with `GITHUB_TOKEN` (non-200 fails with `unexpected GHCR token status <code>; refer to the owner`), then `HEAD /v2/sstolz/kdrive-mcp-server/manifests/<version>`: in phases `verify` and `image` 404 passes and 200 fails; in phase `npm` 200 passes and 404 fails with `image not pushed`; any other status fails with `unexpected GHCR status <code>; refer to the owner`. These checks and BR-378 run in `release-check` before every publish step.

## Rationale

A version is never published twice, npm `latest` stays on the deprecated placeholder, and an unexpected registry answer stops the run for an owner decision. Source: [F-024 v2](../features/F-024-gated-publication.md).
