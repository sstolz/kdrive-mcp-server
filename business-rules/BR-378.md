# BR-378 — Protected release environment

## Rule

In every phase `release-check` reads, with `GITHUB_TOKEN`, `GET /repos/sstolz/kdrive-mcp-server/environments/release` and its `deployment-branch-policies?per_page=100`. The check `release environment protected` passes only when both return 200, `protection_rules` holds a `required_reviewers` entry with at least one reviewer, `deployment_branch_policy` is exactly `{protected_branches: false, custom_branch_policies: true}`, and the policy list has `total_count` 1 and exactly one entry with `name` `main` and `type` `branch`. A non-2xx status fails with `release environment unreadable <code>; refer to the owner`; any other departure fails with `release environment not protected (P-2)`.

## Rationale

The owner's approval gate is only real if the `release` environment requires a reviewer and admits only `main`; the run fails closed otherwise. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** a `required_reviewers` rule with one reviewer and a single branch policy `main`
  **When** `release-check` runs
  **Then** the check passes
- **Given** the environment endpoint returning 403
  **When** `release-check` runs
  **Then** it fails with `release environment unreadable 403; refer to the owner`
- **Given** a policy list `main` and `dev`
  **When** `release-check` runs
  **Then** it fails with `release environment not protected (P-2)`
