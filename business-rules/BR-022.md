# BR-022 — Cumulative levels and safe feature switches

Statement preserved from [F-002 v1](../features/history/F-002-v1.md); accepted under [F-002 v2](../features/F-002-configuration.md). The v2 CLI diagnostic phase ordering applies without rewriting this rule.

## Rule

Normalize the exact cumulative level `read`, `write` or `share`;
default to `read`. Preserve configured feature switches while computing
`effectiveSharedWrite = sharedWithMe && sharedWrite && mode != read` and
`effectivePublicLinks = allowPublicLinks && mode == share`. Shared reads default
off; shared writes and public links default off; an empty invite-domain list
permits no invitations. These configuration values confer no tool access or
policy decision in this feature.

The source specification's inventory, bounds, grammars, auth matrix, credential
contract, error mapping and preflight port supply the normative details for
this statement; this record does not redefine those tables.

## Rationale

Read is the default and independent switches cannot escalate its permissions.

## Examples

These examples illustrate the accepted rule; they do not replace the source specification or claim a new test execution. Unless a scenario overrides them, local-loader fixtures use explicit drive `7` and token `SYNTHETIC_TOKEN`, with no deployment state. Each verification reference identifies one existing test case or table row.

- **Given** valid synthetic configuration with `mode=read`, `sharedWithMe=true`, `sharedWrite=true`, `allowPublicLinks=true`.
  **When** effective switches are derived.
  **Then** `effectiveSharedWrite=false` and `effectivePublicLinks=false`.
  Verified by: [`switch truth table read/true/true/true`](../tests/config.test.ts).

- **Given** valid synthetic configuration with `mode=write`, `sharedWithMe=true`, `sharedWrite=true`, `allowPublicLinks=true`.
  **When** effective switches are derived.
  **Then** `effectiveSharedWrite=true` and `effectivePublicLinks=false`.
  Verified by: [`switch truth table write/true/true/true`](../tests/config.test.ts).

- **Given** valid synthetic configuration with `mode=share`, `sharedWithMe=true`, `sharedWrite=true`, `allowPublicLinks=true`.
  **When** effective switches are derived.
  **Then** both effective switches are `true`.
  Verified by: [`switch truth table share/true/true/true`](../tests/config.test.ts).

- **Given** valid synthetic configuration with `mode=share`, `sharedWithMe=false`, `sharedWrite=true`, `allowPublicLinks=true`.
  **When** effective switches are derived.
  **Then** `effectiveSharedWrite=false` and `effectivePublicLinks=true`.
  Verified by: [`switch truth table share/false/true/true`](../tests/config.test.ts).

- **Given** valid synthetic configuration with `mode=share`, `sharedWithMe=true`, `sharedWrite=false`, `allowPublicLinks=true`.
  **When** effective switches are derived.
  **Then** `effectiveSharedWrite=false` and `effectivePublicLinks=true`.
  Verified by: [`switch truth table share/true/false/true`](../tests/config.test.ts).

- **Given** valid synthetic configuration with `mode=share`, `sharedWithMe=true`, `sharedWrite=true`, `allowPublicLinks=false`.
  **When** effective switches are derived.
  **Then** `effectiveSharedWrite=true` and `effectivePublicLinks=false`.
  Verified by: [`switch truth table share/true/true/false`](../tests/config.test.ts).

- **Given** valid synthetic configuration with environment `KDRIVE_MCP_MODE=READ`.
  **When** the case-sensitive mode enum is checked.
  **Then** it rejects with `{code: INVALID_VALUE, setting: mode}`.
  Verified by: [`rejects malformed %s %s`](../tests/config.test.ts), row `KDRIVE_MCP_MODE`, `READ`.

- **Given** valid synthetic configuration with environment `KDRIVE_MCP_SHARED_WRITE=true`.
  **When** the CLI/environment boolean grammar is checked.
  **Then** it rejects with `{code: INVALID_VALUE, setting: sharedWrite}`; the accepted true spelling is `1`.
  Verified by: [`rejects malformed %s %s`](../tests/config.test.ts), row `KDRIVE_MCP_SHARED_WRITE`, `true`.

### Additional boundary coverage

These boundary cases exercise the existing accepted F-002 v2 behavior through injected synthetic inputs. Their named tests are implemented in the linked test file.

- **Given** only `KDRIVE_ID=7` and `KDRIVE_TOKEN=SYNTHETIC_TOKEN`, with no mode, sharing, public-link or invitation-domain setting.
  **When** configuration applies defaults and derives effective switches.
  **Then** mode is `read`; `sharedWithMe`, `sharedWrite`, `allowPublicLinks`, `effectiveSharedWrite` and `effectivePublicLinks` are `false`; `inviteDomains` is `[]`.
  Verified by: [`TestBR022_DefaultModeSwitchesAndInviteList — BR-022 v1`](../tests/config-selection-boundaries.test.ts).

- **Given** valid synthetic configuration with explicit `KDRIVE_MCP_INVITE_DOMAINS=''`.
  **When** configuration normalizes the invitation-domain list.
  **Then** `inviteDomains` is `[]`, the configuration's no-invitations setting.
  Verified by: [`TestBR022_ExplicitEmptyInviteList — BR-022 v1`](../tests/config-selection-boundaries.test.ts).

- **Given** valid synthetic configuration with explicit `KDRIVE_MCP_INVITE_DOMAINS=example.com`.
  **When** configuration normalizes the invitation-domain list.
  **Then** `inviteDomains` is exactly `[example.com]`; this remains configuration data without a runtime policy decision.
  Verified by: [`TestBR022_OneInviteDomain — BR-022 v1`](../tests/config-selection-boundaries.test.ts).
