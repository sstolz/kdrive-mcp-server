# BR-417 — Font admission

## Rule

Only fonts selected by a kept `Tf` are read, at most 128 distinct fonts per invocation; a `Tf` naming no font of its resource scope refuses as `CONTENT_UNAVAILABLE`. Every key the projection keeps is type-checked, and a wrong type refuses as `CONTENT_UNAVAILABLE`. Admitted: (a) `Type1`, `MMType1` or `TrueType` simple fonts whose encoding BR-420 resolves; (b) `Type0` with `/Encoding` the name `Identity-H` or `Identity-V`, one `CIDFontType0` or `CIDFontType2` descendant with a `FontDescriptor`, and a `ToUnicode` stream that maps every code the font's kept strings show (a shown code it does not map refuses as `UNSUPPORTED_FORMAT`; a string of odd length shown with it refuses as `CONTENT_UNAVAILABLE`). A `ToUnicode` given as a name, such as `/Identity-H`, refuses as `UNSUPPORTED_FORMAT`. The projected simple font keeps `Type`, `Subtype`, `BaseFont` (a name of at most 127 bytes), `FirstChar`, `LastChar` (integers 0–255), `Widths` (at most 256 finite numbers), `ToUnicode` and the `Encoding` of BR-420; the projected Type0 font keeps `Type`, `Subtype`, `BaseFont`, `Encoding`, `ToUnicode` and one descendant with `Type`, `Subtype`, `BaseFont`, `DW` (a finite number), `W` (an array of at most 65,536 numbers in total, in the `c [w …]` and `c1 c2 w` forms, codes 0–65,535), its `FontDescriptor`, and a `CIDSystemInfo` emitted as `<< /Registry (Adobe) /Ordering (Identity) /Supplement 0 >>` after the source value is checked (a dictionary with `Registry` and `Ordering` strings of at most 64 bytes and an integer `Supplement`). A kept `FontDescriptor` holds `Type`, `FontName`, `FontBBox` (four finite numbers), `ItalicAngle`, `Ascent`, `Descent`, `CapHeight`, `StemV` and `MissingWidth` (finite numbers, each optional except `FontName`), and `Flags` set to the source `Flags` with the Symbolic flag (value 4) cleared and the Nonsymbolic flag (value 32) set; a simple font without a source `FontDescriptor` gets none. `FontFile`, `FontFile2`, `FontFile3` and a stream `CIDToGIDMap` are never emitted. A `ToUnicode` CMap is parsed with the bounded tokenizer: only code space ranges, `bfchar` and `bfrange` entries count; codes are 1 or 2 bytes and keyed by their numeric value; a `bfrange` has a low and high code of the same length that differ only in the last byte, low not above high, and either one destination string, incremented over the range as PDF.js 6.5.438 does, or an array whose length equals the range size; destinations are UTF-16BE strings of 2–64 bytes; when a code is mapped twice the last entry wins; `usecmap` refuses as `UNSUPPORTED_FORMAT`; a CMap has at most 65,536 entries and all admitted CMaps together map at most 262,144 codes. Each admitted CMap is re-emitted canonically as one `bfchar` entry per mapped code in ascending order. Every other font refuses as `UNSUPPORTED_FORMAT`.

## Rationale

Common generators use named font resources, TrueType and Type0 subset fonts (F-034 S09–S11, S21, S25). PDF.js extracts text from encodings and `ToUnicode` without font programs (F-034 Context, finding 3), so programs, the largest parser surface, are never emitted; every kept key is bounded and type-checked, and a Type0 code without a `ToUnicode` mapping refuses because only the program could give it meaning. Source: [F-034 v1](../features/F-034-pdf-extraction-profile.md).

## Examples

- **Given** a Type0 Identity-H font with `ToUnicode` and a `FontFile2` of random bytes
  **When** page 1 is read
  **Then** its text, and the canonical bytes hold no font program
- **Given** a Type0 font without `ToUnicode`
  **When** page 1 is read
  **Then** `UNSUPPORTED_FORMAT` before PDF.js
- **Given** 128 distinct fonts
  **When** page 1 is read
  **Then** its text
- **Given** 129 distinct fonts
  **When** page 1 is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
- **Given** a `ToUnicode` destination of 66 bytes
  **When** page 1 is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
