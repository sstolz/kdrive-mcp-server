# BR-024 — Safe transport and authenticated HTTP configuration

Source: [F-002 v1](../features/history/F-002-v1.md), BR-024, frozen
2026-11-01 21:18:28 UTC after fresh independent approval. v2: [F-002 v3](../features/F-002-configuration.md) (#21), accepted on
main `3fc14c3bbbd57b3c52ca4b74c07a512720f0d627`.

## Rule

v4 (F-028 v2, #3, pending acceptance; v3 stays the accepted rule until then): adds `oauthAllowedClientIdOrigins` to the proxy-only settings and the origin conflicts of BR-291.

Default to `stdio`. Reject explicitly supplied HTTP/OAuth-only
settings in effective stdio configuration, including `insecureNoAuth=true`.
In HTTP mode default host/port to `127.0.0.1:3000`. Authenticated HTTP requires
an HTTPS public URL, OAuth mode/issuer and a nonempty identity allowlist under
the auth matrix below. Reject unsafe/incomplete combinations without discovery
or network I/O. This validates configuration, not OAuth-provider capability.

The source specification's inventory, bounds, grammars, auth matrix, credential
contract, error mapping and preflight port supply the normative details for
this statement; this record does not redefine those tables.

Version 3 (F-019 v1, #103; accepted on main `68209fe`, 2026-11-11): adds `oauthStateFile` to the proxy-only settings.

## Rationale

Reject incomplete or misplaced HTTP/auth settings before any future runtime starts.
