# BR-267 — NotSent before the handshake, MUTATION_UNKNOWN after it

## Rule

A mutation request that fails before its connection's TLS handshake has completed (queue full, abort while queued, DNS failure, BR-191 address refusal, TCP connect or TLS failure) rejects with the gate's branded `NotSent`; any failure from the completed handshake on (write error, socket close, timeout, abort, truncated status line or headers) rejects with an unbranded `Error` whose message is exactly `MUTATION_UNKNOWN`.

## Rationale

Only transport proof that nothing was sent may yield `failed`/`NOT_SENT`; everything else is unknown (F-016 port contract). Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** a DNS failure
  **When** a trash request runs
  **Then** the port throws `NotSent` and the gate result is `failed` `NOT_SENT`
- **Given** a server that closes the socket after reading the request
  **When** a trash request runs
  **Then** the port throws `MUTATION_UNKNOWN` and the gate result is `uncertain`
