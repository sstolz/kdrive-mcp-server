# BR-412 — Cross-reference chain

## Rule

Cross-reference data is read only from the last `startxref` offset and the chain it starts, with no scan for objects and no repair. Each section is either a classic `xref` table with a trailer, or a stream object whose dictionary has `/Type /XRef`, a `/Size`, a `/W` of three integers each 0–8 with `W[1]` at least 1, and an optional `/Index` of at most 4,096 start/count pairs that are ascending, non-overlapping and whose counts total at most `/Size`; its `/Length`, `/Filter`, `/DecodeParms`, `/Size`, `/W`, `/Index` and `/Prev` are direct objects. A classic trailer's `/XRefStm` and every section's `/Prev` are followed; at most 32 sections are read and a section offset seen twice is a cycle. Sections rank newest first, and for each object number the newest section that lists it wins, a free entry included. Within one hybrid section, an in-use table entry wins over the section's `/XRefStm`, while a free table entry, or a number the table does not list, takes the `/XRefStm` entry; the `/XRefStm` entries rank above the section's `/Prev`. The newest trailer gives `/Root`; `/Size` of every section is at most 65,536 and every listed object number is below its section's `/Size`. A decoded cross-reference stream holds exactly the listed entry count times the sum of `/W` bytes. A field of width 0 takes its default: type 1 for the first field, 0 for the third. A type 0 entry is free, type 1 gives a byte offset and generation, type 2 gives an object stream number and index, and any other type is free.

## Rationale

Cross-reference streams (PDF 1.5+), hybrid files, incremental updates and linearized files are the default output of common generators; the F-009 profile refused them (F-034 S05–S07). Reading them by offset only, with a bounded cycle-checked chain, direct stream keys and a checked `/Index`, keeps the interpretation deterministic and bounded; hybrid sections follow ISO 32000-1 §7.5.8.4 so a free table entry never hides an object stream entry (F-034 D-2). Source: [F-034 v1](../features/F-034-pdf-extraction-profile.md).

## Examples

- **Given** a file whose second revision (`/Prev`) replaces page 1's content
  **When** page 1 is read
  **Then** the second revision's text
- **Given** a hybrid section whose table marks the content object free and whose `/XRefStm` lists it in use
  **When** page 1 is read
  **Then** its text
- **Given** a `/Prev` chain A→B→A
  **When** page 1 is read
  **Then** `CONTENT_UNAVAILABLE` before PDF.js
- **Given** 32 cross-reference sections
  **When** page 1 is read
  **Then** its text
- **Given** 33 cross-reference sections
  **When** page 1 is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
- **Given** a cross-reference stream with `/W [1 8 2]`
  **When** page 1 is read
  **Then** its text
- **Given** a cross-reference stream with `/W [1 9 2]`
  **When** page 1 is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
- **Given** a cross-reference stream with `/Index [5 4 0 5]`
  **When** page 1 is read
  **Then** `CONTENT_UNAVAILABLE` before PDF.js
