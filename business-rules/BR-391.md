# BR-391 — Local nearest-neighbour resize

## Rule

`resizeNearest(src, width, height)`, exported by `src/extraction-image.ts`, returns a new bitmap of `width × height` whose data is a new `Buffer` of `width * height * 4` bytes, where the 4 bytes of destination pixel (row `i`, column `j`) equal the 4 bytes of source pixel (row `Math.floor((i * src.height) / height)`, column `Math.floor((j * src.width) / width)`), computed in that operation order. `extractImage` calls it only when the current bitmap's size differs from the attempt's target, and always on the current bitmap (the previous attempt's result), never on the decoded one. For each input of the characterization set (F-027 AC-01), `extractImage` returns the width, height and PNG bytes (SHA-256) recorded on the Jimp 1.6.1 path at the base.

## Rationale

The formula, its operation order and the chained resizing are Jimp's; keeping them makes every halving step sample the same pixels as before, which the characterization digests prove (D-2, ADR-010). Source: [F-027 v2](../features/F-027-direct-image-codecs.md).

## Examples

- **Given** a 3 × 2 bitmap whose pixel `k` holds `[k, k + 10, k + 20, k + 30]`
  **When** `resizeNearest` targets 2 × 1
  **Then** the destination pixels are source pixels 0 and 1, and the source data is unchanged
- **Given** a 4 × 4 bitmap resized to 2 × 2
  **When** the result is resized to 1 × 1
  **Then** the pixel is pixel 0 of the 2 × 2 result
- **Given** a 30 × 1 bitmap
  **When** it is resized to 22 × 1
  **Then** destination column 11 holds source column 15 (`Math.floor((11 * 30) / 22)`), not 14
- **Given** a 600 × 400 colour-type-2 noise PNG of the characterization set
  **When** `extractImage` runs
  **Then** it returns 256 × 170 with the inflated-IDAT and (on linux/amd64) PNG-byte digests recorded on the Jimp path
