# BR-420 — Simple font encoding

## Rule

A simple font's encoding is resolved per shown code, and the projection emits it as `/Encoding << /Type /Encoding /BaseEncoding /WinAnsiEncoding /Differences [...] >>` listing every code the font's kept strings show that the `ToUnicode` CMap does not map, with its resolved glyph name; codes are collected at every execution with the font in effect (BR-419). A source `/Encoding` is checked in every case, even when a `ToUnicode` CMap exists: a name `StandardEncoding`, `WinAnsiEncoding`, `MacRomanEncoding` or `MacExpertEncoding`, or a dictionary with optional `/Type /Encoding`, one of those names as optional `/BaseEncoding` and optional `/Differences` of codes (integers 0–255) and glyph names; any other value refuses as `UNSUPPORTED_FORMAT`, and more than 256 codes or a glyph name over 31 bytes refuses as `LIMIT_EXCEEDED`. The base table is the named one, else (no `/Encoding`, or no `/BaseEncoding`): StandardEncoding for a font with no font program whose `BaseFont`, without a subset prefix, is one of the 12 standard Latin fonts (Times, Helvetica and Courier families) or whose `Flags` have Nonsymbolic set and Symbolic clear; StandardEncoding for a `TrueType` font with a `FontFile2` and Nonsymbolic set; for a `Type1` or `MMType1` font with a `FontFile`, the built-in encoding of its program; otherwise no base table. `/Differences` entries override the base table. The built-in encoding is read only at the first shown code that the `ToUnicode` CMap does not map and that has no `/Differences` entry, so the program of a font whose `/Differences` and `ToUnicode` cover every shown code is never read. It is read from the program's cleartext part only: a direct integer `/Length1` of 1–65,536 bytes (over 65,536 refuses as `LIMIT_EXCEEDED`), decoded by the streaming inflate of BR-414 up to that length, tokenized with the bounded tokenizer up to its first `/Encoding` name, which is followed either by `StandardEncoding def` or by `<n> array` with `n` 1–256, optionally `0 1 255 {1 index exch /.notdef put} for`, `dup <code> /<name> put` groups with each code below `n`, and `readonly def` or `def`; when a code is put twice, the last group wins; more than 256 groups or a name over 31 bytes refuses as `LIMIT_EXCEEDED`; anything else, or no `/Encoding` in that part, refuses as `UNSUPPORTED_FORMAT`, and the encrypted part is never read. The tables are those of PDF.js 6.5.438. A shown code that the `ToUnicode` CMap does not map and that resolves to no glyph name or to `.notdef` refuses as `UNSUPPORTED_FORMAT`. A simple font whose projected `BaseFont`, which the kept `FontName` equals (BR-417), is one of the ten GBK font names that PDF.js 6.5.438 turns into a composite `GBK-EUC-H` font when it has no program and a `WinAnsiEncoding` base (its `chineseFontNames` list, such as `/#CB#CE#CC#E5`) refuses as `UNSUPPORTED_FORMAT`, since PDF.js would return none of its text.

## Rationale

Without its program PDF.js picks a base encoding from `Flags` and the font name, which loses the built-in encoding of pdfLaTeX's Computer Modern fonts (F-034 S26 measured `Hello nal \modern" { PDF` instead of the source text). Resolving each shown code by the PDF rules, reading a Type 1 built-in encoding from the cleartext part only, and emitting every mapping explicitly keeps the text equal to the source without a font parser (F-034 D-5, D-11). The cleartext is read only when a shown code has no other mapping, so fonts whose `/Differences` or `ToUnicode` cover every shown code never reach that reader; a simple font with one of the GBK names PDF.js 6.5.438 reinterprets as a composite `GBK-EUC-H` font refuses, because PDF.js would return none of its text (F-034 D-5). Source: [F-034 v1](../features/F-034-pdf-extraction-profile.md).

## Examples

- **Given** a Computer Modern Type 1 subset with `Flags 4`, no `/Encoding`, no `ToUnicode` and an OT1 built-in encoding
  **When** page 1 is read
  **Then** `Hello ﬁnal “modern” – PDF`, as raw PDF.js reads the source
- **Given** a symbolic TrueType font with a `FontFile2`, no `/Encoding` and no `ToUnicode`
  **When** page 1 is read
  **Then** `UNSUPPORTED_FORMAT` before PDF.js
- **Given** `/Differences` of 256 codes
  **When** page 1 is read
  **Then** its text
- **Given** `/Differences` of 257 codes
  **When** page 1 is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
- **Given** a glyph name of 32 bytes
  **When** page 1 is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
- **Given** a pdfTeX-style `Type1` font with a `FontFile` whose `/Length1` is 70,000, full `/Differences` for its shown codes and no `/BaseEncoding`
  **When** page 1 is read
  **Then** its text, the program never read
- **Given** a nonembedded `Symbol` font with `/Differences` for its shown codes
  **When** page 1 is read
  **Then** its text
- **Given** a simple font whose `BaseFont` is `/#CB#CE#CC#E5`
  **When** page 1 is read
  **Then** `UNSUPPORTED_FORMAT` before PDF.js
