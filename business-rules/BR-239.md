## Rule

The file sink opens its path with `O_WRONLY | O_APPEND | O_CREAT | O_NOFOLLOW | O_CLOEXEC` and creation mode `0600`, then requires by `fstat` a regular file owned by the effective user ID with no group or other permission bit (`mode & 0o077 === 0`); any failure stops startup with a fixed message, without changing the file's mode or owner.

Implementation note (PR #84): the open also passes `O_NONBLOCK`, so that a FIFO with no reader is refused at startup (AC-06) instead of blocking it; it has no effect on regular files. The next BR-239 version folds this flag into the rule.

## Rationale

A planted symlink or a readable file must not receive the audit trail (D-16-8). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** a missing audit file
  **When** the server starts in mode `write`
  **Then** the file exists with mode `0600`
- **Given** a file with mode `0640`
  **When** the server starts
  **Then** startup stops with the fixed message and the mode stays `0640`
