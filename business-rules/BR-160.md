## Rule

Body limits are 262,144 bytes for POST on the MCP endpoint and 32,768 bytes for `/oauth/register`, `/oauth/consent` and `/oauth/token`; every other route and method, including GET and DELETE on any route, accepts no body: a nonzero `Content-Length` or any `Transfer-Encoding` field yields 413 at the body-framing step, without reading the body, and the connection is closed. A `Content-Length` above the limit yields HTTP-layer error 413 `payload_too_large` before authentication and without reading the body; a body that exceeds the limit while being read yields the same 413, stops reading and closes the connection. For POST requests: a `Content-Encoding` other than absent or `identity` yields 415 `unsupported_media_type`; the media type (parameters ignored, case-insensitive) must be `application/json` on the MCP endpoint and `/oauth/register`, and `application/x-www-form-urlencoded` on `/oauth/consent` and `/oauth/token`, else 415 `unsupported_media_type`; a body that is not valid UTF-8, an MCP body that is not valid JSON, or an MCP body whose top-level value is an array (a JSON-RPC batch, D-10) yields 400 `invalid_request`, so each MCP request carries one JSON-RPC message. On the MCP endpoint these checks run after authentication (BR-158/BR-159) except the body-framing checks (`Content-Length`, `Transfer-Encoding`). The router reads the body itself and gives the SDK transport the parsed JSON as `parsedBody`, so the SDK's own `maxRequestBodySize` does not apply and 262,144 bytes is the only MCP body limit.

## Rationale

Bounded bodies, one JSON-RPC message per request and strict framing keep memory and the per-identity count predictable. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-09.

## Examples

- **Given** the MCP endpoint
  **When** a POST body of 262,144 bytes arrives
  **Then** it is accepted.
- **Given** the same endpoint
  **When** a POST body of 262,145 bytes arrives
  **Then** 413 `payload_too_large`.
- **Given** a JSON array of two requests
  **When** it is posted to the MCP endpoint
  **Then** 400 `invalid_request`.
