# BR-369 — Checked npm publish of the verified tarball

## Rule

`release-npm` runs the BR-359 validation first, then requires exactly one `artifacts/sstolz-kdrive-mcp-server-<version>.tgz` whose `package/package.json` has the scoped name and `<version>`, requires `npm --version` `>=11.5.1` (else `npm 11.5.1 or later required`), and prints `release-npm: tarball sha256 <hex>`. When `RELEASE_DRY_RUN` is `false` it exits 1 before publishing with `tarball digest does not match verify` unless `RELEASE_TARBALL_SHA256` equals that digest, with `OIDC environment missing` unless both `ACTIONS_ID_TOKEN_REQUEST_*` variables are set, and with `npm token in environment refused` if any refused npm credential variable of the source specification is present (case-insensitive, including any `NPM_CONFIG_//` prefix). In both modes a `publishConfig` key fails with `publishConfig refused`. It then runs exactly `npm publish ./artifacts/sstolz-kdrive-mcp-server-<version>.tgz --tag beta --access public --ignore-scripts --provenance`, with `--dry-run` appended when `RELEASE_DRY_RUN` is `true`.

## Rationale

npm publishes only the tarball `verify` built and hashed, through trusted publishing with provenance, never with a long-lived token or a lifecycle script. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** dry run `true` and a fake npm answering `11.5.1`
  **When** `release-npm` runs
  **Then** the publish argv ends with `--provenance --dry-run`
- **Given** dry run `false` and `NPM_TOKEN` set
  **When** `release-npm` runs
  **Then** `npm publish` is not called, `npm token in environment refused` prints and the exit is 1
- **Given** a fake npm answering `11.5.0`
  **When** `release-npm` runs
  **Then** `npm 11.5.1 or later required` prints and the exit is 1
