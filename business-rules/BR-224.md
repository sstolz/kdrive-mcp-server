## Rule

Before every `limactl start` (in `golden` and in each `run` cycle), the supervisor self-tests the egress filter with `ops/runner/egress-selftest.sh`: a UDP `sendto` from its own uid to `9.9.9.9:53` must fail at once with `EPERM`; on any other outcome `golden` exits nonzero with a fixed message and a `run` cycle starts no VM and waits the 60-second back-off. `ops/runner/supervise.sh golden` creates the instance from `ops/runner/lima.yaml`, copies `provision.sh`, `Dockerfile`, `compose.yaml`, `entrypoint.sh` and `probe.sh` into the VM, runs `provision.sh`, stops the VM and saves its writable disk as a `0444` golden overlay (the mode guards against mistakes only: the file belongs to the host user, which can change it). `ops/runner/supervise.sh run` loops over one cycle per job: force-stop the VM (`limactl stop -f`); check that no QEMU process of the instance remains (its pid file names no live process); replace its writable disk with a new `qemu-img` overlay backed by the golden overlay; start the VM; request one JIT configuration (BR-223); run the `runner` service in the foreground until it exits. When any step before the runner start fails, including a QEMU process that remains after the stop, no disk is replaced after that failure, no runner is registered or started in that cycle, and the next cycle starts after a fixed back-off of 60 seconds.

## Rationale

Every job starts from the reviewed golden disk on a host whose egress filter is proven active, so nothing persists across jobs (T2, D-03). Source: [F-015 v1](../features/F-015-self-hosted-runner.md).

## Examples

- **Given** stubbed `limactl`, `qemu-img`, `curl` and a self-test reporting `EPERM`
  **When** one `run` cycle completes
  **Then** the calls are self-test, `stop -f`, pid check, overlay from the golden disk, start, JIT request, JIT write, runner
- **Given** a QEMU process that remains after the stop
  **When** the cycle runs
  **Then** no overlay is created and the supervisor sleeps 60 seconds
