## Rule

**v1 (F-016 v1; superseded by v2)**

The run's total deadline is 60,000 ms of monotonic time from the start of the first attempt; each upstream attempt is aborted by the gate after the smaller of 30,000 ms and the time left until that deadline, and is then classified `uncertain`.

**v2 (F-037 v1, #47; accepted on main `8b92e07`)** — The run retains its 60,000 ms monotonic deadline from the start of the first attempt, never reset or extended. Under BR-248 v2 there is only one upstream attempt, aborted after the smaller of 30,000 ms and the time left until that deadline, and then classified `uncertain`. The 60,000 ms ceiling is retained but redundant for this sole attempt; it allows neither another attempt nor an additional wait. A valid 429 received before timeout ends the run under BR-248 v2; late replies cannot change a timed-out result.

## Rationale

MCP clients need a bounded call; an aborted attempt has an unknown effect. Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

v2 keeps the existing deadline bounds rather than broadening the repair into a new deadline contract. It replaces the unreachable second-attempt example and makes the redundant 60,000 ms ceiling explicit. Intent and outcome appends keep their separate bounds. Source: [F-037 v1](../features/F-037-mutation-rate-limit-stop.md), D-5.

## Examples

- **Given** a mutator that never settles
  **When** 30,000 ms pass
  **Then** its signal is aborted and the run is `uncertain`
- **Given** a 429 at 25,000 ms with `Retry-After: 10` and a second attempt that never settles
  **When** the run continues
  **Then** the second attempt is aborted at 60,000 ms and the run is `uncertain` with 2 attempts

v2 examples (the preceding examples describe superseded v1):

- **Given** a sole attempt whose mutator never settles
  **When** 29,999 ms have passed since the attempt started
  **Then** no outcome exists and its signal is not aborted. Maps to `TestBR249_v2_AC06_attempt_deadline_remains_uncertain_without_retry`.
- **Given** that same pending sole attempt
  **When** 30,000 ms have passed
  **Then** its signal is aborted and the run is `uncertain` / `UPSTREAM_UNCERTAIN`, attempts 1, with one intent and one uncertain outcome; a later 429 or 200 changes nothing. Maps to `TestBR249_v2_AC06_attempt_deadline_remains_uncertain_without_retry`.
- **Given** a valid 429 at 25,000 ms with `Retry-After: 10` and a queued second reply that never settles
  **When** the outcome append resolves
  **Then** the run is `failed` / `RATE_LIMITED`, status 429, attempts 1, at 25,000 ms; through 60,001 ms no second attempt or record exists. Maps to `TestBR249_v2_AC06_429_at_25000_ms_never_starts_a_second_attempt`.
