# BR-418 — Weighted text-production admission

## Rule

The F-009 text-production admission holds with weighted string bytes: for each selected page, N is the sum over text-show strings of the string's bytes times `m` of its font, where `m = max(1, ceil(D / 3))` and D is the largest UTF-8 byte length PDF.js can give one code of that font (from the canonical CMap for a `ToUnicode` font; for other fonts the maximum established by exact-pin source checks, 3 unless those checks show more). `U = 8 * (N + O + 1)`, `I = 2 * (S + O + 1)` with S the unweighted string bytes, the sum of U plus 3 per separator is at most B, the sum of I at most 65,536, and a string over 4,096 bytes refuses, all before PDF.js starts.

## Rationale

`ToUnicode` can map one code to several characters, so the F-009 bound of three UTF-8 bytes per glyph no longer holds; weighting each string by its font's largest mapping keeps the static bound before PDF.js starts. Source: [F-034 v1](../features/F-034-pdf-extraction-profile.md).

## Examples

- **Given** a `ToUnicode` font with a 48-byte largest destination and repeated strings whose U sum is exactly B
  **When** the page is read
  **Then** its text
- **Given** the same page with a U sum of B + 1
  **When** the page is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
