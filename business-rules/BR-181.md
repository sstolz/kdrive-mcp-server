## Rule

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11): v1 holds, and a run passes only when also: (7) `docker image inspect` of both the runtime and the smoke image reports health test `[CMD node /app/dist/healthcheck.js]`, interval `10s`, timeout `10s`, start period `30s` and retries `3`; (8) inside the smoke container, `node:http` GETs on `/healthz` with `Host: 127.0.0.1:3000` and with the public URL's `Host` each return `200|application/json|{"status":"ok"}`, and with `Host: attacker.example` return 403; (9) `docker inspect` reports the smoke container's `.State.Health.Status` as `healthy` within 30 s after check (1)'s `http-acceptance listening on` line appears; (10) the BR-180 v2 no-server probe container exits 1 and its log is exactly `healthcheck failed: connection`. Checks (7)–(10) run before the SIGTERM check.

For each platform the smoke run passes only when all hold: (1) `http-acceptance listening on` appears in the container log within 60 s; (2) `docker exec <id> id -u` prints `1000` and `/proc/1/comm` in the container is `node` or `node-MainThread`; (3) a GET from inside the container with `node:http` and the public URL's `Host` on the BR-155 protected-resource metadata URL returns 200 `application/json` whose `resource` equals the public URL; (4) a POST on the MCP endpoint, the same way, with `Content-Type: application/json`, `Accept: application/json, text/event-stream`, a `Content-Length` JSON-RPC `initialize` body, no `Origin` and no `Authorization`, returns 401 with a `WWW-Authenticate` header starting with `Bearer` and containing `resource_metadata=`; (5) `docker stop --time 10` makes Node as PID 1 run F-012 BR-169 `close()` and exit 0, in under 10 s; (6) the runtime checks of BR-173, BR-174 and BR-175 hold.

## Rationale

Behavioural evidence on both architectures that the image starts, authenticates and stops cleanly. Source: [F-013 v2](../features/F-013-http-image.md).
