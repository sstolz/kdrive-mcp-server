## Rule

Before each connection the adapter resolves the host, refuses the connection unless every resolved address is a public unicast address (not loopback, private, link-local, unique-local, carrier-grade NAT, multicast, unspecified, documentation, benchmarking or reserved; an IPv4-mapped `::ffff:0:0/96` address is checked as its embedded IPv4 address; NAT64 `64:ff9b::/96` and `64:ff9b:1::/48`, 6to4 `2002::/16` and Teredo `2001::/32` are refused), connects to a checked address with default TLS certificate and hostname verification for the original host through an adapter-owned `https.Agent` (never the global agent), and ignores proxy environment variables, including when `NODE_USE_ENV_PROXY=1` is set.

## Rationale

A resolver or proxy could steer the bearer token or private bytes to an internal or attacker-chosen address; per-connection checks and default TLS verification close that path. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** the resolver answers `10.0.0.1`
  **When** a request starts
  **Then** `connect` is never called and the call rejects `READ_UNAVAILABLE`.
- **Given** the resolver answers `1.1.1.1`
  **When** a request starts
  **Then** `connect` receives exactly `{host: "1.1.1.1", port: 443, servername: "api.infomaniak.com"}`.
