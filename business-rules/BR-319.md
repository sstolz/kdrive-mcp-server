# BR-319 — make audit target

## Rule

`make audit` (prerequisite `_require-setup`) runs exactly `$(COMPOSE) run --rm dev npm audit --audit-level=high` and exits with npm audit's status. `make help` lists `make audit`. `make check` does not run `audit` (it needs the network advisory service).

## Rationale

Contributors and CI need one Docker-only command that fails on high or critical findings, while `make check` stays offline and deterministic (D-3, D-4). Source: [F-020 v1](../features/F-020-dependency-audit.md).

## Examples

- **Given** the Makefile fixture with a fake `docker` that exits 0
  **When** `make audit` runs
  **Then** the recorded command is `compose run --rm dev npm audit --audit-level=high` and the target succeeds
- **Given** the fake `docker` exiting 1 on `npm audit`
  **When** `make audit` runs
  **Then** the recipe fails with `Error 1` and `make` exits non-zero
- **Given** the Makefile
  **When** `make help` and `make -n check` run
  **Then** help lists `make audit` and no `npm audit` command appears in `check`
