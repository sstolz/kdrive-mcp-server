## Rule

The report, standard output and standard error never contain the access, ID or refresh token, any of their non-empty segments, the authorization code, PKCE verifier or client secret, nor the values of the identity claims `sub`, `email`, `name`, `preferred_username`, `given_name`, `family_name` and `nickname`; only the authorization URL, printed once, may carry `state`, `nonce` and the challenge. Identity appears only as yes/no allowlist lines and the JSON type and value of `email_verified`. Before writing, the command scans the report for each secret value and segment and each identity value of at least 8 characters, and writes nothing and exits nonzero on a hit; failures print a fixed message without stack trace.

## Rationale

Only a redacted report may enter the repository, and low-entropy identifiers must not be confirmable from it. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-16.

## Examples

- **Given** a full synthetic run with distinctive secret and identity values.
  **When** the report is produced.
  **Then** none of them appears and the allowlist lines read yes.
- **Given** a header `typ` equal to the authorization code.
  **When** the report would be written.
  **Then** no file is written and the command exits nonzero.
- **Given** `sub` = `1`.
  **When** the report is produced.
  **Then** the run completes and writes it.
