## Rule

**v4 (F-046 v1, #112, accepted).** v3 holds except that the variables with defaults are exactly `MCP_HTTP_TRUSTED_PROXIES`, `OAUTH_ALLOWED_SUBJECTS` and `OAUTH_ALLOWED_EMAILS`, each using `${NAME:-}` with an empty default. Immediately after `OAUTH_ISSUER`, the service environment contains this exact consecutive block:

```yaml
# Allowlist: set at least one of the two lists (the server refuses both
# empty). Prefer subjects; an e-mail address can be reassigned (SPEC.md).
OAUTH_ALLOWED_SUBJECTS: ${OAUTH_ALLOWED_SUBJECTS:-}
OAUTH_ALLOWED_EMAILS: ${OAUTH_ALLOWED_EMAILS:-}
```

The required/optional and file-secret header lines stay unchanged. The optional-settings header is exactly:

```yaml
# Optional trusted proxies (F-035, accepted on main 703bece) and identity allowlists (F-046) below.
```

Loading checks substitute supplied values or empty defaults for those three variables, RFC 2606 values for required installation variables and temporary synthetic credential-file paths for file-secret references. Subjects only, e-mails only and both lists load as transport `http`, OAuth mode `proxy`, retaining the expected `oauthAllowedSubjects` and `oauthAllowedEmails` arrays. Both lists empty are refused with name `ConfigurationError`, code `MISSING_REQUIRED`, setting `oauthAllowedSubjects` and message `Configuration error [MISSING_REQUIRED] (oauthAllowedSubjects).` Trusted-proxy checks retain both the empty default and `192.0.2.0/24`. All other v3 hardening, routing, secrets and healthcheck requirements hold.

Accepted on actual main `e8ae20d`, 2026-11-19 ([#112 acceptance](https://github.com/sstolz/kdrive-mcp-server/issues/112#issuecomment-7014711154)).

### Accepted rule (through v3)

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11; superseded by v3): v1 holds, and the service has no `healthcheck` key (the image's `HEALTHCHECK` applies, reading `MCP_HTTP_PORT: "3000"`) and a comment line containing `HEALTHCHECK` and `docs/deployment.md`.

`examples/compose.yaml` defines one service whose image is `${KDRIVE_MCP_IMAGE:?…}`, with `user: "1000:1000"`, `read_only: true`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `init: true`, `restart: on-failure:3`, `stop_signal: SIGTERM`, `stop_grace_period` of at least 10 s, no `ports` mapping, environment `KDRIVE_MCP_TRANSPORT: http`, `OAUTH_MODE: proxy`, `MCP_HTTP_HOST: 0.0.0.0` and `MCP_HTTP_PORT: "3000"`, Traefik labels routing a `Host(...)` rule to port 3000, and every credential provided as a Compose file secret mounted under `/run/secrets/` and referenced only by `KDRIVE_TOKEN_FILE`, `OAUTH_UPSTREAM_CLIENT_SECRET_FILE` and `OAUTH_SIGNING_KEY_FILE`; it sets no `KDRIVE_TOKEN` or `OAUTH_UPSTREAM_CLIENT_SECRET` value and no `command`. Its service environment, with every `${NAME:?…}` replaced by an RFC 2606 value and the `*_FILE` paths by temporary synthetic files, is accepted by F-002 `loadConfiguration` with transport `http` and OAuth mode `proxy`.

**v3 (F-035 v1, #46; accepted on main `703bece`)** — v2 holds, and the service environment also has `MCP_HTTP_TRUSTED_PROXIES: ${MCP_HTTP_TRUSTED_PROXIES:-}`, the only variable of the file with a default, directly preceded by a comment line that names `MCP_HTTP_TRUSTED_PROXIES`, exact proxy addresses or a dedicated proxy-only network, and `docs/deployment.md`, and contains no IP address. The v1 loading check replaces this variable by its empty default, and the environment then loads with an empty `httpTrustedProxies`; with the value `192.0.2.0/24` it loads with that one entry.

## Rationale

A safe, generic template that stays valid when the HTTP runtime lands. Source: [F-013 v1](../features/F-013-http-image.md).

## Examples

### v4 — accepted

- **Given** subjects `subject-1` and e-mails unset or empty (v4)
  **When** the resolved Compose environment loads
  **Then** HTTP proxy mode retains `["subject-1"]` and `[]`
- **Given** subjects unset or empty and e-mails `user@example.com` (v4)
  **When** the resolved Compose environment loads
  **Then** HTTP proxy mode retains `[]` and `["user@example.com"]`
- **Given** subjects `subject-1` and e-mails `user@example.com` (v4)
  **When** the resolved Compose environment loads
  **Then** HTTP proxy mode retains both one-entry arrays
- **Given** both lists unset or empty, in all four combinations (v4)
  **When** the resolved Compose environment loads
  **Then** it refuses with `ConfigurationError`, `MISSING_REQUIRED`, setting `oauthAllowedSubjects` and message `Configuration error [MISSING_REQUIRED] (oauthAllowedSubjects).`

### Accepted examples

- **Given** the Compose environment with synthetic credential files
  **When** `loadConfiguration` runs
  **Then** transport is `http` and OAuth mode `proxy`
- **Given** the Compose service
  **When** the examples test parses it
  **Then** it has no `ports` and no `command`

- **Given** the Compose environment with `MCP_HTTP_TRUSTED_PROXIES` unset (v3)
  **When** `loadConfiguration` runs with the variable replaced by its empty default
  **Then** `httpTrustedProxies` is the empty list
- **Given** the Compose environment with `MCP_HTTP_TRUSTED_PROXIES=192.0.2.0/24` (v3)
  **When** `loadConfiguration` runs
  **Then** `httpTrustedProxies` is `["192.0.2.0/24"]`
