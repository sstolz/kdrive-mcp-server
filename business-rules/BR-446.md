## Rule

A request whose header block holds 101 to 2,000 header lines, counted as the name/value pairs Node reports in `rawHeaders` (repeated names counted separately, `Host` included, trailers excluded), is answered with HTTP-layer error 431 `invalid_request` (BR-167 body and headers, plus `Connection: close`), before `handle()` runs and so before the shutdown, target-length, `Host`, authentication, window and body checks, with no body read; a request with exactly 100 header lines is handled as before, and a request with more than 2,000 lines never reaches the adapter: Node refuses it under BR-169 v4.

## Rationale

Without a pinned bound, the header-line count a request may carry is left to Node's default. Node refuses a request over `maxHeadersCount` with its own empty-body 431 that bypasses the router (measured on Node v26.13.0, F-053 v2 Context item 6). With `maxHeadersCount` 2,000 (BR-169 v4), a request of 101 to 2,000 lines reaches the adapter, which answers the standard status in the BR-167 shape and logs one `request_refused`. Source: [F-053 v2](../features/F-053-http-lifecycle-hardening.md), D-5.

## Examples

- **Given** a socket request to `/mcp` with exactly 100 header lines
  **When** it arrives
  **Then** it is handled as before.
- **Given** a socket request to `/mcp` with 101 header lines and a valid token
  **When** it arrives
  **Then** it gets 431 `{"error":"invalid_request"}` with `Connection: close`, no authentication, window count or body read occurs, and one `request_refused` (`route` `mcp`, `status` 431) is emitted.
- **Given** a request with 101 header lines to an unknown path during shutdown
  **When** it arrives
  **Then** it gets the same 431 with `route` `unknown`, not the shutdown 503.
- **Given** a socket request to `/mcp` with 2,000 header lines and a valid token
  **When** it arrives
  **Then** it gets the same 431 and one `request_refused` (`route` `mcp`, `status` 431).
- **Given** a socket request with 2,001 header lines
  **When** it arrives
  **Then** Node answers 431 with an empty body, the router's handler never runs and no `request_refused` is emitted (BR-169 v4).

## Verification

`BR-169 v4 BR-446 AC-12 pins the header count and accepts 100 header lines`
and `BR-446 BR-167 v4 AC-13 refuses more than 100 header lines with 431` in
`tests/http/lifecycle.test.ts` (AC-12, AC-13). Acceptance remains pending on
actual main (#73).
