# BR-268 — Raw port result; the mutator alone validates

## Rule

**v1 (F-017 v1; superseded by v2)**

Once the status line and headers are received, the port returns `{status, retryAfter?, body?}`, where `retryAfter` is the raw `Retry-After` text only when it is at most 32 bytes and `body` holds the bytes of a 2xx body only when it is complete within the BR-194 limits; a non-2xx body is discarded after at most 8 KiB. The port never parses or validates a body: the mutator alone does, and returns the gate reply `{outcome:"response", status, retryAfter?, accepted, value?, created?}` with `accepted:true` only when `body` is present, is JSON with `result` equal to `success`, and its `data` passes the kind's check (BR-272, BR-273); any other 2xx gives `accepted:false`.

**v2 (F-037 v1, #47; accepted on main `8b92e07`)** — The v1 raw-port reply, body validation and 32-byte `Retry-After` bound remain unchanged. The gate never uses a forwarded header to schedule another attempt: a valid 429 terminates as `failed` / `RATE_LIMITED`, status 429, attempts 1 under BR-248 v2, whether `retryAfter` is passed or omitted.

## Rationale

An unchecked 2xx must never become `succeeded`. Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

v2 keeps the bounded raw header for compatibility while replacing the historical retry-wait example with terminal 429 cases. Source: [F-037 v1](../features/F-037-mutation-rate-limit-stop.md), D-3.

## Examples

- **Given** a 200 body larger than 4 MiB
  **When** a trash run ends
  **Then** the result is `uncertain`
- **Given** a 429 with a 33-byte `Retry-After`
  **When** a trash run continues
  **Then** the retry waits 1,000 ms (no `retryAfter` passed)

v2 examples (the preceding examples describe superseded v1):

- **Given** a valid 429 with `Retry-After: 2` or a 32-ASCII-digit value
  **When** a trash run ends
  **Then** the port passes the raw header, but the gate makes exactly one request and returns `failed` / `RATE_LIMITED`, status 429, attempts 1, with no wait. Maps to `TestBR268_v2_TestBR248_v2_AC08_bounded_retry_after_%s_never_replays` (the two bounded-header rows).
- **Given** a valid 429 with a 33-ASCII-digit `Retry-After`
  **When** a trash run ends
  **Then** the port omits `retryAfter` and the gate makes exactly one request with the same terminal result and no fallback wait. Maps to `TestBR268_v2_TestBR248_v2_AC08_bounded_retry_after_%s_never_replays` (the oversized-header row).
