# BR-147 — No Sonar host in active code and the analysed set

## Rule

Active code and configuration never name the Sonar host:
`sonar-project.properties` contains no `sonar.host.url` property (its presence
fails property verification), keeps `sonar.projectKey=kdrive-mcp-server` (the
`main` key; `make sonar-pr` overrides it by scanner argument, BR-148, and
property verification accepts exactly this file in both modes), and keeps
exactly `sonar.sources=src` and `sonar.tests=tests` with no inclusion or
exclusion property, so the analysed file set is exactly the snapshot's files
under `src/` and `tests/` plus `sonar-project.properties`; `scripts/sonar.ts`
contains no `https://` literal whose host is not `github.com`; and before
spawning the scanner the wrapper fails with a fixed message when any file of
that analysed set contains the configured host name (ASCII case-insensitive).
Files outside that set never trigger the check.

## Rationale

Historical records keep the host (D9); the check covers exactly what the scanner uploads. Source: [F-011 v1](../features/F-011-pre-merge-quality-gates.md).

## Examples

- **E-01 — Given** a snapshot whose `src/x.ts` contains `HTTPS://SONAR.EXAMPLE.TEST/dashboard`
  **When** the analysed set is verified
  **Then** it fails with `Analysed sources contain the configured analysis host`.
- **E-02 — Given** a snapshot whose only occurrence is in `runs/x.md`
  **When** the analysed set is verified
  **Then** it passes.

## Verification

- E-02: tests/sonar-analysis.test.ts — `BR-147 ignores records outside the analysed set`.
