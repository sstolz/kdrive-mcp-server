## Rule

Root `1` normalizes to the sentinel root `{id:1,type:"dir",name:"",path:"/"}` with an empty chain only when its `drive_id` equals the requested drive, its `status` member passes the rule below, its `type` is `dir`, its provider `path` is `/` and its `parents` member is absent or an empty array; its `parent_id` is not read. Any other provider item normalizes to a complete live item only when: its `id`, `drive_id`, `parent_id` are positive safe integers and `drive_id` equals the requested drive; `type` is `dir` or `file`; the `status` member is present with the value `null` or `"ok"` (any other value, or an absent member, is not live); the chain is the sentinel root `{id:1,type:"dir",name:"",path:"/"}` followed by the provider `parents` ordered so that each member's `parent_id` is the previous member's `id` (exactly one of provider order or reverse order satisfies this) and the item's `parent_id` is the last member's `id`; and the provider `path` equals the path joined from the chain names and the item name.

## Rationale

Configured-tree authorization rests on complete, consistent ancestry; any gap, cycle, foreign drive or non-live state must fail closed. Source: [F-014 v2](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** file 12 with parents 10 and 11 in either order and path `/Private/docs/a.bin`
  **When** `inspect` runs
  **Then** the item passes `item()` with chain root `1`, 10, 11.
- **Given** the same file with `status` `trashed`
  **When** `inspect` runs
  **Then** it returns `{status:"incomplete"}`.
- **Given** root `1` with path `/`, no `parents` and any `parent_id`
  **When** `inspect` runs
  **Then** it returns the sentinel root with an empty chain.
