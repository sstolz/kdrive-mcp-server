# BR-311 — CIMD families in the state file

## Rule

A CIMD client is never stored as a registered client and never counts against the client bound; its refresh families are stored with the URL as client ID and count against the family bound (BR-303). The store format becomes version 2 (Contract details, ADR-011): the version 1 schema unchanged, with the family row rule extended so that a family's `client_id` either names a client row or meets Contract details "CIMD client ID syntax" with no client row. That syntax stands on its own (no origin, issuer or audience check), so a version 2 file read at startup and a row to be written are checked without the configuration (a family whose `client_id` names no client row and fails that syntax is `OAUTH_STATE_CORRUPT` at load and a failed write at write). A committed transaction that inserts a CIMD family sets `user_version` to 2 in that transaction; the startup transaction (BR-295 v2 step (11)) sets it to 2 when a CIMD family remains after the purge and to 1 otherwise. Between startups the version never goes back to 1: it stays 2 after the last CIMD family is deleted (revocation, expiry purge, eviction) until the next startup transaction. A transaction writes version 2 when the file is at version 2 or the transaction inserts a CIMD family, and version 1 otherwise; its rows are checked against the row rules of that version (BR-298 v2, BR-299 v2). After a restart a CIMD client refreshes without any fetch.

## Rationale

CIMD refresh families must survive a restart without inventing a registration, while files without CIMD stay readable by older releases (D-10, ADR-011). Source: [F-028 v2](../features/F-028-client-id-metadata-documents.md).

## Examples

- **Given** a version 1 state file
  **When** a CIMD client gets a refresh token
  **Then** the write commits, the file holds the family with the URL as client ID and no client row, and `user_version` is 2
- **Given** that file after the family is revoked
  **When** the store is still open
  **Then** `user_version` stays 2 until the next startup, which writes 1
- **Given** a family row with client ID `https://127.0.0.1/c` and no client row
  **When** it is written
  **Then** the write fails and the store latches
