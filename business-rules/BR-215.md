## Rule

`make kdrive-acceptance` runs on an actual main checkout inside the dev Compose service with at most 400 GET requests and 900,000 ms, executes the checks of AC-23–AC-26 in process through `main(deps)` with the production `{lookup, connect}` and a counting `onRequest` observer (BR-216) that records only method, route template and count, plus a packaged-CLI smoke (initialize, tool listing and one permitted read, with no request-log assertion), and prints only a sanitized summary (per-check pass/fail, request counts, durations, byte totals, main SHA) that contains no ID, name, path, cursor, ETag, URL or token. The durations include, measured with a monotonic clock in the acceptance process, the maximum single-request duration per route template and the maximum navigation tool invocation duration; the mechanism adds no seam to production code. "Actual main" means: the target refuses, before any Docker command, unless the worktree is clean and `HEAD` equals the `origin/main` ref the owner fetched beforehand; the orchestrator checks the printed SHA against GitHub's `main` when recording the report. Verified by: AC-21, AC-23–AC-26.

## Rationale

Production acceptance must run on the merged code against designated fixtures, with bounded requests and a sanitized report. Source: [F-014 v2](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** a dirty worktree
  **When** `make kdrive-acceptance` runs
  **Then** it prints `kdrive-acceptance requires a clean worktree.` and no Docker command runs.
- **Given** a clean worktree whose HEAD equals `origin/main`
  **When** `make kdrive-acceptance` runs
  **Then** the acceptance script runs with the SHA passed in.
- **Given** an acceptance run whose slowest children request took 1,879 ms and whose slowest navigation invocation took 9,400 ms
  **When** the sanitized summary is printed
  **Then** it shows 1,879 ms as the children route template's maximum request duration and 9,400 ms as the maximum invocation duration, with no ID, name, path or cursor.
