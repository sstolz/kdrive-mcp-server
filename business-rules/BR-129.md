## Rule

v2 (F-028 v2, #3; accepted on main `aa540d4`; superseded by v3): the consent page content of BR-393 for CIMD clients.

Every valid authorization request shows a consent page; no consent is remembered. The page states the client's `client_name` labelled as self-declared and unverified (or "unnamed client"), the `client_id`, the exact `redirect_uri` of the request and the protected resource (audience), with every value HTML-escaped. It holds one form posting to `<issuer>/oauth/consent` with a hidden one-use consent identifier (32 random bytes) and `decision` `approve` or `deny`. The pending request is stored under that identifier for 600 seconds, bound to the browser cookie of BR-130. Page and error-page responses carry `Cache-Control: no-store`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` and `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'`. The consent handler consumes the identifier on its first presentation whatever the outcome; an unknown, expired or consumed identifier, a missing or mismatched cookie, or a `decision` other than `approve`/`deny` yields a 400 HTML error page. `deny` produces a client redirect with `error=access_denied`; `approve` starts the upstream leg (BR-131).

**v3 (F-030 v1, #23; accepted on main `f747072`; superseded by v4)** — v2 holds, except that the `Content-Security-Policy` value is the BR-401 one (`default-src 'none'; frame-ancestors 'none'; base-uri 'none'; style-src 'sha256-<b64>'`) and the page follows BR-399–BR-402; the v2 example "a registered client's page is unchanged" now reads "a registered client's page carries no BR-393 line".

**v4 (F-031 v1, #31; accepted on main `901f7af`; superseded by v5)** — v3 holds, except: the form posts to `<issuer>/oauth/consent?lang=xx` with the page language (BR-404), used only to choose the language of the consent handler's error pages; "unnamed client" and the "self-declared and unverified" label are the page language's catalogue texts (BR-407); a valid request carrying `lang` may replace an equal pending consent under BR-409.

**v5 (F-032 v1, #33; accepted on main `89be2ba`; superseded by v6)** — v4 holds, except that a consumed identifier with a BR-411 record is answered under BR-411 (2) instead of the 400 page; the identifier stays one-use for every other purpose.

**v6 (F-033 v1, #26; accepted on main `6ef8b55`)** — v5 holds, except that a client name that contains a code point with the Unicode property Bidi_Control (the runtime's `\p{Bidi_Control}`: U+061C, U+200E, U+200F, U+202A–U+202E, U+2066–U+2069), U+2028 or U+2029 is displayed exactly as an absent name: the page language's "unnamed client" text (BR-407), without the self-declared suffix and without any part of the name. This applies to CIMD and registered clients alike, including clients loaded from the state file. The name is still accepted, stored, snapshotted and echoed at registration as before, the display logs no event of its own (a CIMD resolution still logs its one `client_metadata_fetched`), and the rest of the page is unchanged. A name with any other format character (for example U+200B, U+200C, U+200D, U+00AD, U+FEFF or a tag character) is shown as sent, escaped and with the self-declared suffix, as under v5.

## Rationale

A static upstream client plus open registration is the MCP confused-deputy case; explicit consent per authorization prevents silent approvals. Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-08, AC-09.

## Examples

- **Given** a client named `<script>alert(1)</script>`
  **When** a valid authorization request arrives
  **Then** a consent page with the escaped name, the unverified label and the security headers.
- **Given** a pending consent
  **When** `decision=deny` is posted with the bound cookie
  **Then** 302 with `error=access_denied`, `state` and `iss`.
- **Given** a CIMD client
  **When** the consent page is shown
  **Then** it carries the BR-393 content; a registered client's page is unchanged (v2)
- **Given** a registered client (v3)
  **When** the consent page is shown
  **Then** it carries no BR-393 line, and its CSP carries the `style-src` hash of its stylesheet (BR-401)
- **Given** a registered client and `lang=fr` (v4)
  **When** the consent page is shown
  **Then** the form posts to `<issuer>/oauth/consent?lang=fr` and the client is labelled `client sans nom` or with `(déclaré par le client, non vérifié)`
- **Given** a consent approved at `t0` with cookie C (v5)
  **When** the same form is posted again with C at `t0 + 1` s, then at `t0 + 10` s
  **Then** the first repeat gets the same 302 (BR-411) and the second the 400 page
- **Given** a CIMD or registered client named `Pay` U+202E `laPyaP` (v6)
  **When** the consent page is shown
  **Then** the name line holds `unnamed client` and the page contains no part of the name
- **Given** a client named `Pay` U+200D `Pal` (v6)
  **When** the consent page is shown
  **Then** the name is shown as sent, escaped, with the self-declared suffix
