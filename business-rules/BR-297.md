# BR-297 — Fixed startup refusal lines

## Rule

A store refusal at startup raises `HttpStartupError` with code `OAUTH_STATE_UNAVAILABLE`, `OAUTH_STATE_LOCKED`, `OAUTH_STATE_CORRUPT`, `OAUTH_STATE_VERSION` or `OAUTH_STATE_MISMATCH`, before any socket is opened; the process writes exactly that code's fixed line of Contract details to stderr and exits 1. No line contains the path, a configuration value, a row value or an operating-system or SQLite message.

## Rationale

A refusal must tell the operator what to do without leaking the path, a value or a system message into logs. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** a corrupt state file
  **When** `startHttpServer` is called
  **Then** `HttpStartupError` `OAUTH_STATE_CORRUPT`, no socket opened, and the fixed line "The OAuth state file is not a valid OAuth state file." on stderr
- **Given** a locked state file
  **When** `startHttpServer` is called
  **Then** the fixed line "The OAuth state file is in use by another process." without the path
