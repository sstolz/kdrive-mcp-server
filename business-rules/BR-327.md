# BR-327 — Runtime HEALTHCHECK

## Rule

The `runtime` stage of `Dockerfile` has exactly one `HEALTHCHECK` instruction, exactly `HEALTHCHECK --interval=10s --timeout=10s --start-period=30s --retries=3 CMD ["node", "/app/dist/healthcheck.js"]` (exec form, no shell); the `smoke` stage has no `HEALTHCHECK` and inherits it. The runtime stage keeps BR-173's only `RUN` (the Node version test): no package manager, `curl` or `wget` is added.

## Rationale

Docker and Compose learn liveness from the image itself; a 10 s interval keeps the Traefik post-restart gap short, and the exec form keeps the image free of extra tools (D-6, D-7). Source: [F-021 v1](../features/F-021-container-health-check.md).

## Examples

- **Given** the real `Dockerfile`
  **When** the image-policy parser reads it
  **Then** the runtime stage has exactly the BR-327 `HEALTHCHECK` and its only `RUN` is the Node version test
- **Given** a copy with `--interval=30s`
  **When** the checker runs
  **Then** it is rejected
- **Given** a copy with `RUN apt-get install -y curl` in the runtime stage
  **When** the checker runs
  **Then** it is rejected
