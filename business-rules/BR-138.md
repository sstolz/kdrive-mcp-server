## Rule

An access token is a compact JWS signed with the configured key, header `{"alg":"ES256","typ":"at+jwt","kid":<BR-124 kid>}`, payload `iss` (proxy issuer), `sub` (upstream `sub`), `upstream_iss` (upstream issuer), `aud` (audience string), `client_id`, `iat` (now, seconds), `exp` (`iat` + 3600), `jti` (16 random bytes) and, only when the email allowlist is nonempty and the identity has an email, `email` and `email_verified` copied from the ID token. It carries no `nonce` and no `scope`.

## Rationale

Short audience-bound tokens with `kid` limit misuse and let P-12 verify them locally (D-05 identity). Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-19.

## Examples

- **Given** a successful redemption
  **When** the access token is decoded
  **Then** header `ES256`/`at+jwt`/`kid` and exactly the stated claims with `exp - iat = 3600`.
- **Given** an empty email allowlist and an ID token with email
  **When** the access token is decoded
  **Then** it has no `email` claim.
