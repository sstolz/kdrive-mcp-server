## Rule

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11): v1 holds, except that in insecure mode the `/healthz` route of BR-322 also exists (still no OAuth or PRM path).

In insecure mode only the MCP endpoint exists, at the path of `P` (`/` for the origin BR-025 v2 derives, or the path of an explicit `http://127.0.0.1:<port>/<path>` public URL); OAuth and PRM paths yield 404. No credential is required or verified; an `Authorization` header is ignored and stripped (BR-166). The pseudo-identity is used for BR-161, BR-163 and BR-164.

## Rationale

The loopback insecure switch serves only the MCP endpoint and still applies Host, rate and session bounds. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-18.

## Examples

- **Given** insecure mode on `127.0.0.1:3000`
  **When** an unauthenticated initialize is posted to `/`
  **Then** it succeeds.
- **Given** the same server
  **When** `/oauth/token` is requested
  **Then** 404 `not_found`.
