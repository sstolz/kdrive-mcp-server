# BR-145 — Runtime Sonar host selection

## Rule

The Sonar host is selected from exactly one of `SONAR_HOST_URL` or
`SONAR_HOST_URL_FILE`. A value is accepted only when it has no whitespace or
control character and parses as a URL whose protocol is `https:`, with empty
username, password, search and hash, and whose WHATWG serialization
(`URL.href`) equals the value or the value followed by `/`. File mode mirrors
`SONAR_TOKEN_FILE`: an absolute path, physically outside the checkout, not a
final symlink, a readable regular file, and one terminal LF or CRLF removed.
The entry guard rejects an existing or symlinked `.config/sonar-host-url` inside
the checkout before any Docker prerequisite. Every rejection is a fixed message
that never contains the value.

## Rationale

The owner keeps the server address out of the repository; a canonical https form makes the configured host name unambiguous for redaction and the analysed-set check. Source: [F-011 v1](../features/F-011-pre-merge-quality-gates.md).

## Examples

- **E-01 — Given** `SONAR_HOST_URL=https://sonar.example.test/ctx`
  **When** the wrapper loads the host
  **Then** it returns that URL with host name `sonar.example.test`.
- **E-02 — Given** `SONAR_HOST_URL=https://sonar.example.test:443`
  **When** the wrapper loads the host
  **Then** it fails with `Invalid analysis host`.
- **E-03 — Given** `SONAR_HOST_URL_FILE` pointing inside the checkout
  **When** `make sonar-pr` starts
  **Then** it fails before any Docker call.
