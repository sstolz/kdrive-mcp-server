# BR-290 — The `oauthStateFile` setting

## Rule

The F-002 setting `oauthStateFile` (environment `OAUTH_STATE_FILE`, option `--oauth-state-file`, YAML `oauthStateFile`) is an optional nonempty string of at most 4,096 characters without control characters, resolved against the working directory like `auditLog`; unlike `auditLog`, the value `stderr` has no special meaning and names a file. It has no default. It is accepted only when the effective configuration has transport `http`, `insecureNoAuth` false and OAuth mode `proxy`; set explicitly in any other configuration it is refused with `CONFLICTING_SETTINGS` (BR-024 v3). A resolved `oauthStateFile` byte-identical to the resolved `auditLog`, or a resolved `auditLog` byte-identical to the resolved `oauthStateFile` followed by `-journal`, is refused with `CONFLICTING_SETTINGS`.

## Rationale

A persistent store must be opt-in, bounded and confined to the one configuration that runs the proxy, and it must not collide with the audit log it shares a mount with. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** `OAUTH_STATE_FILE=state.sqlite`, transport `http`, authentication on, OAuth mode `proxy`, working directory `/work`
  **When** `loadConfiguration` resolves the settings
  **Then** `oauthStateFile` is `/work/state.sqlite`
- **Given** `OAUTH_STATE_FILE=stderr`
  **When** the configuration is resolved
  **Then** the file `/work/stderr` is named; `stderr` has no special meaning
- **Given** `OAUTH_STATE_FILE` set with transport `stdio`
  **When** the configuration is validated
  **Then** `CONFLICTING_SETTINGS`
- **Given** `auditLog` equal to `<state file>-journal`
  **When** the configuration is validated
  **Then** `CONFLICTING_SETTINGS`
- **Given** a value of 4,097 characters
  **When** the configuration is validated
  **Then** `INVALID_VALUE`
