# BR-360 — Release commit content

## Rule

`RELEASE_SHA` names a commit in the clone and equals `git rev-parse HEAD`; at that commit `VERSION` is exactly `<version>\n`, `package.json` has `name` `@sstolz/kdrive-mcp-server` and `version` `<version>`, and `package-lock.json` has top-level `version` `<version>`. Each mismatch is one failed check.

## Rationale

The published version must be the one recorded in the repository at the approved commit. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** a release commit whose `VERSION`, `package.json` and lockfile all read `0.6.0-beta.1`
  **When** `release-check` runs
  **Then** the commit checks pass
- **Given** `VERSION` `0.6.0-beta.2`
  **When** `release-check` runs for `0.6.0-beta.1`
  **Then** exactly the `VERSION` check fails
