# BR-279 — `kdrive_upload` arguments are strict

## Rule

`kdrive_upload` accepts exactly a strict object with `drive_id?`, `parent_id`, `name`, exactly one of `text` (string) and `base64` (string), `overwrite?` (boolean, default `false`) and `file_id`, where `file_id` is present when and only when `overwrite` is `true`; IDs and `drive_id` follow BR-260 and `name` follows the BR-260 name rule and is a well-formed UTF-16 string (no unpaired surrogate); any other argument set returns `INVALID_ARGUMENTS` with zero `mutate` calls, zero records and zero upstream requests.

Since v2: `name` also equals its Unicode NFC normalization; this check is part of the schema check, so it runs first in the BR-280 order.

## Rationale

A strict shape keeps the overwrite path explicit (`file_id` only with `overwrite:true`) and makes the `file_name` sent by `URLSearchParams` equal the checked name. Source: [F-018 v1](../features/F-018-upload.md).

## Examples

- **Given** `{parent_id:5, name:"n", text:"hi"}`
  **When** `kdrive_upload` is called
  **Then** one `mutate` call with an `upload-new` operation
- **Given** `{parent_id:5, name:"n", text:"hi", overwrite:true}` (no `file_id`)
  **When** `kdrive_upload` is called
  **Then** `INVALID_ARGUMENTS` and zero `mutate` calls
