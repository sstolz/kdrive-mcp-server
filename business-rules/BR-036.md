# BR-036 — Folder descendant effects

## Rule

When denies are nonempty, folder rename, move, trash and restore require a complete traversal proving every relevant descendant's current/original and resulting paths permitted.

The normalized evidence, matching, effect and paging details in
[F-003 v1](../features/F-003-tree-access-policy.md) remain normative.

## Rationale

A permitted folder path cannot hide a forbidden descendant before or after a change.

## Examples

These are synthetic injected cases, not provider observations.

- **Given** directory 11 containing report and deny **/report, **When** trashing directory 11, **Then** dispatch is denied.
- **Given** directory 11 containing report and deny /r/hidden/report, **When** renaming directory 11 to hidden, **Then** dispatch is denied.

Both examples map to the test or parameter rows named below.
