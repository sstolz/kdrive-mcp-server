## Rule

`open` sends `Range: bytes=<start>-<end>` and `Accept-Encoding: identity`; before exposing a body it requires status 206, `Content-Range: bytes <start>-<end>/<size_bytes>`, `Content-Length` equal to `end − start + 1`, and returns the BR-205 normalization of the response ETag; its body reader returns at most `max` bytes per `read`, `null` at end of stream, and destroys the socket on `close`.

## Rationale

A ranged read must prove it returned exactly the requested bytes of the bound version before any byte is exposed. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** `open` of bytes 7–9 answered 206 `bytes 7-9/16` with `Content-Length: 3`
  **When** the body is read with `max` 3
  **Then** it returns the three known bytes, then `null`.
- **Given** the same range answered with `Content-Length: 2`
  **When** `open` runs
  **Then** it rejects `READ_UNAVAILABLE` before any body byte.
