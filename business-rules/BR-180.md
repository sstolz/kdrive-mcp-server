## Rule

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11): v1 holds, with two changes: the smoke container's launch adds exactly `--health-interval=2s` after the hardening flags (the image's health command, timeout, start period and retries apply); and one extra runtime-image container runs `--entrypoint node kdrive-mcp-server:runtime-<arch> /app/dist/healthcheck.js` with the same flags and no server.

`make image-smoke` runs `scripts/image-smoke.sh` once per platform in `IMAGE_PLATFORMS`, against the local `kdrive-mcp-server:smoke-<arch>` and `kdrive-mcp-server:runtime-<arch>`. Every container it starts uses `--network none`, `--read-only`, `--cap-drop ALL`, `--security-opt no-new-privileges:true`, `--tmpfs /run/secrets:uid=1000,gid=1000,mode=0700` and no `--init`, `--privileged` or `-p`/`--publish`. The smoke container is started exactly as `docker run -d <those flags> -e <settings> --entrypoint sh kdrive-mcp-server:smoke-<arch> -c '<gen> && exec node /app/scripts/http-acceptance.ts'`, where `<gen>` is one `node -e` call that writes, with mode 0600, a synthetic EC P-256 signing key (`crypto.generateKeyPairSync('ec', { namedCurve: 'P-256' })`) to `/run/secrets/signing-key.pem`, and 32 random bytes in hex to each of `/run/secrets/upstream-client-secret` and `/run/secrets/kdrive-token`. The runtime checks of BR-173–BR-175 run in containers started with the same flags from `kdrive-mcp-server:runtime-<arch>`; the BR-175 `--http` check runs as `docker run <flags> -e <settings> --entrypoint sh kdrive-mcp-server:runtime-<arch> -c '<gen> && exec node /app/dist/cli.js --http'`. The settings are `MCP_HTTP_HOST=127.0.0.1`, `MCP_HTTP_PORT=3000`, `OAUTH_SIGNING_KEY_FILE` and `OAUTH_UPSTREAM_CLIENT_SECRET_FILE` naming those files, and RFC 2606 names for every URL and identity setting.

## Rationale

No port, network or committed key is needed to smoke-test the image, and Node is PID 1. Source: [F-013 v2](../features/F-013-http-image.md).
