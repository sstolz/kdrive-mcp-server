# BR-314 — Deployment guide and examples for the state file

## Rule

`docs/deployment.md` states in its existing audit-log section that `OAUTH_STATE_FILE` uses the same writable mount, in the step-by-step guide how to enable it, and in Troubleshooting each `OAUTH_STATE_*` line; `examples/compose.yaml` and `examples/config.yaml` add only commented lines for the new setting; every example path of the state file uses the existing `/audit/` mount (for example `/audit/oauth-state.sqlite`), never a prefix that BR-186 forbids; `SPEC.md` §8 "Contrat du mode `proxy`" updates its "Enregistrement" and "Stockage" bullets in the file's language. The BR-184, BR-185, BR-186 and BR-187 v2 tests pass unchanged.

## Rationale

The state file shares the audit mount; the examples must stay inside the reserved hosts and path prefixes of the deployment contract. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** the updated `docs/deployment.md`
  **When** the content test runs
  **Then** the audit-log section, the step-by-step guide and Troubleshooting mention `OAUTH_STATE_FILE` and each `OAUTH_STATE_*` code
- **Given** `examples/compose.yaml` and `examples/config.yaml`
  **When** the content test runs
  **Then** the state lines are comments and use `/audit/oauth-state.sqlite`
- **Given** the BR-184 to BR-187 tests
  **When** they run unchanged
  **Then** they pass
