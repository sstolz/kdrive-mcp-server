## Rule

An MCP POST without `Mcp-Session-Id` whose body is a single JSON-RPC request with method `initialize` creates a transport with a `sessionIdGenerator` returning 32 random bytes base64url (43 characters), `enableJsonResponse: true` and no `eventStore`, and a new `McpServer` from `createNavigationServer` (BR-059 v2) with the injected configuration and dependencies. The session is registered, bound to the request's identity, only when the transport reports the issued ID through `onsessioninitialized`; when no ID is issued, the transport and the server are closed and nothing is registered. The router's `onsessioninitialized` callback never throws: it catches any exception raised while registering (including by the logger's `session_opened` call) and records a failure; after `handleRequest` returns, a recorded failure discards the SDK's response, closes the transport and the server, leaves nothing registered, releases the creation slot (BR-164) and yields HTTP-layer error 500 `server_error`. Without `Mcp-Session-Id`, any other body (including a 2026-07-28 `server/discover` probe, D-14) yields 400 `invalid_request` and creates nothing. A request whose `Mcp-Session-Id` is repeated, does not match the 43-character grammar, is unknown, expired, or bound to another identity yields HTTP-layer error 404 `session_not_found`, identical in all these cases. A DELETE without `Mcp-Session-Id` yields 400 `invalid_request` and closes nothing. A DELETE by the bound identity closes the session. MCP responses that carry a body are JSON (`Content-Type: application/json`), never an SSE stream; a POST whose message is a notification or a JSON-RPC response gets the SDK's 202 without a body. The SDK transport sets `Mcp-Session-Id` on each JSON response that answers a JSON-RPC request within a session, including the `initialize` response; its 202 and its transport-level error responses carry none.

## Rationale

Per-identity sessions with one server each keep continuation handles session-bound and make a foreign session ID indistinguishable from an unknown one. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-12, AC-13, AC-15, AC-22.

## Examples

- **Given** identity A with an initialized session
  **When** identity B presents A's session ID
  **Then** 404 `session_not_found`.
- **Given** a sessionless request with method `server/discover`
  **When** it is posted
  **Then** 400 `invalid_request` and no session is created.
