## Rule

`docs/self-hosted-runner.md` contains these sections, in order: Prerequisites (pinned Lima release and its SHA-256, QEMU, KVM, nftables), Installation (`install.sh`, `--check`, `--uninstall`, BR-233), Host user and egress rules (`host-setup.sh`, and re-running it after a host network change), Runner credential (the D-14 token: fine-grained, this repository only, Administration read and write, expiry at most 90 days; its file of BR-223; rotation before expiry: create the new token, replace the file content, revoke the old token; never pasted elsewhere), Golden disk (`supervise.sh golden`), Service, Repository settings and merge criterion ("Run workflows from fork pull requests" disabled; branch protection and required checks are unavailable on this plan, so a PR is merged only when `ci-result` succeeded on its head and `fork-refusal` did not fail, F-011 D5), Acceptance (the dispatch of BR-229 with the owner canary, and the evidence to record), Secrets exposure (the T1, T4 and T5 residuals of this spec), Updating (runner image digest, Lima image digest, Docker versions, golden rebuild), and Rollback (pause the service and delete the runner registration; restoring hosted runners is a reviewed PR that reverts `runs-on`). It names every file under `ops/runner/`.

## Rationale

The owner operates, rotates and rolls back the runner from one reviewed guide. Source: [F-015 v1](../features/F-015-self-hosted-runner.md).
