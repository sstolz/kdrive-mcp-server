# BR-335 — Issues query

## Rule

The issues stage runs only when at least one condition has status `ERROR`; otherwise no issues request is made and no issues line prints. The issues request sends `componentKeys=<projectKey>`, `resolved=false`, `s=SEVERITY`, `asc=false`, `ps=20`, and adds `inNewCodePeriod=true` only when at least one condition failed and every failed condition's `metricKey` starts with `new_`. v2: it also adds a quality filter derived from the failed conditions. For each failed condition, the `metricKey` with a leading `new_` removed maps as follows: `software_quality_reliability_*` → impact `RELIABILITY`, `software_quality_security_*` → impact `SECURITY`, `software_quality_maintainability_*` → impact `MAINTAINABILITY`; `reliability_*` or `bugs` → type `BUG`; `security_rating`, `security_remediation_effort` or `vulnerabilities` → type `VULNERABILITY`; `maintainability_rating`, `technical_debt`, `sqale_*` or `code_smells` → type `CODE_SMELL`; any other key is unmapped. When every failed condition maps to an impact, the request adds `impactSoftwareQualities=<values>`; when every one maps to a type, it adds `types=<values>`; `<values>` are the distinct mapped values sorted and joined by `,`. When any failed condition is unmapped, or impacts and types are mixed, no quality filter is added. Issues are not bound to the analysed task: they are the project's current open issues, which for `kdrive-mcp-server-pr` may come from another pull request's latest analysis.

## Rationale

Lists the most severe open issues, new code only when every failed metric is new code (D-5, D-9). v2 narrows the list to the issues behind the failed conditions: the v1 real run showed 20 code smells under a failed reliability condition while the seeded reliability issue was hidden (D-13). Source: [F-022 v2](../features/F-022-sonar-gate-summary.md).

## Examples

- **Given** failed conditions `new_violations` and `new_coverage`
  **When** the issues request is built
  **Then** it sends `componentKeys`, `resolved=false`, `s=SEVERITY`, `asc=false`, `ps=20` and `inNewCodePeriod=true`
- **Given** failed conditions `new_reliability_rating` and `coverage`
  **When** the issues request is built
  **Then** it has no `inNewCodePeriod` and no quality filter (`coverage` is unmapped)
- **Given** a failed condition `software_quality_reliability_rating`
  **When** the issues request is built
  **Then** it adds `impactSoftwareQualities=RELIABILITY`
- **Given** failed conditions `new_maintainability_rating` and `new_reliability_rating`
  **When** the issues request is built
  **Then** it adds `types=BUG,CODE_SMELL` and `inNewCodePeriod=true`
- **Given** no `ERROR` condition
  **When** the summary runs
  **Then** no issues request is made and no issues line prints
