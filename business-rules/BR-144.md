# BR-144 — Justified lint suppressions and the bounded tests allowlist

## Rule

Lint suppressions are explicit and justified: each `eslint-disable*` directive
names at least one rule and carries a ` -- <reason>` description; unused disable
directives are lint errors; no rule that the pinned upstream `strictTypeChecked`
or SonarJS `recommended` configuration enables is lowered or disabled by
repository configuration, except the justified entries of a bounded allowlist;
the allowlist applies only to `tests/**/*.ts`, is asserted exactly by the BR-144
test, carries one justification comment per entry in `eslint.config.mjs`, and is
listed with those justifications in the PR body; and no tracked TypeScript file
contains the Sonar line-suppression marker. A directive without rule names, and
any inline ESLint configuration comment, stop the lint run with a fixed error. An
inline configuration comment is a block comment whose text, after leading
whitespace is trimmed, starts with `eslint`, `eslint-env`, `global` or `globals`
followed by whitespace or the end of the comment.

(v1: inline configuration comments were not covered.)

## Rationale

Findings must be fixed or justified where they occur; a silent or blanket suppression would hide exactly the issues the pre-merge gate exists to catch. An inline configuration comment such as `/* eslint <rule>: "off" */` lowers a rule for its whole file, including the rule that would report the comment, so it is caught before any rule configuration applies. Source: [F-011 v2](../features/F-011-pre-merge-quality-gates.md).

## Examples

- **E-01 — Given** a `// eslint-disable-next-line @typescript-eslint/no-floating-promises -- synthetic justified fixture` directive above `Promise.resolve(1);`
  **When** the repository ESLint configuration lints it
  **Then** lint exits 0.
- **E-02 — Given** the same directive without ` -- reason`
  **When** lint runs
  **Then** lint exits nonzero with `kdrive/justified-suppressions`.
- **E-03 — Given** the committed `eslint.config.mjs`
  **When** the effective configuration for `tests/lint-policy.test.ts` is computed
  **Then** exactly the eight allowlisted upstream error rules are lowered.
- **E-04 — Given** `/*eslint\n @typescript-eslint/no-floating-promises: "off" */` above `Promise.resolve(1);`
  **When** lint runs
  **Then** the lint run stops with `Inline ESLint configuration comment`.
- **E-05 — Given** `/* eslintrc-like prose and globalThis notes are not directives */`
  **When** lint runs
  **Then** lint exits 0.
