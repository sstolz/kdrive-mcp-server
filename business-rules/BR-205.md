## Rule

**v1 (F-014 v1; superseded by v2)**

`describe` reads fresh metadata, then issues one download with `Range: bytes=0-0`; it returns `version_bound:true` and `etag` = `"kd1-` + base64url(SHA-256(provider ETag bytes)) + `"` only when the metadata is a live `file` of size ≥ 1, the response is 206 with `Content-Range: bytes 0-0/<size>` equal to the metadata size, and the provider ETag is 1–256 visible ASCII bytes; when the metadata is a valid live item but any of these conditions fails (not a file, size 0, a 2xx download that fails the range or length checks, or an absent or out-of-range ETag) it returns a descriptor whose `etag` is `null`, which the content reader refuses with `VERSION_UNAVAILABLE`.

**v2 (F-038 v1, #47; accepted on main `2ae303c`)** — The v1 conditions and derivation hold except that any provider validator beginning with the case-sensitive prefix `W/` normalizes to `null`, exactly as an absent validator. This applies to both `describe` and `open` (BR-206) through the shared derivation. No prefix stripping, case folding or trimming is performed; other admitted values retain the exact Latin-1 SHA-256/base64url derivation and the existing 1–256 visible-ASCII bound. A weak/absent probe yields `etag:null, version_bound:false` and the content caller refuses `VERSION_UNAVAILABLE` before `open`. A weak/absent ETag on an otherwise valid `open` response yields `etag:null`; after a strong descriptor the content caller refuses `CONTENT_UNAVAILABLE`, closes without reading and publishes no bytes. A different strong ETag still yields `VERSION_CHANGED`.

## Rationale

Version binding needs a strong ETag that changes with the content; deriving it from the opaque provider value hides that value and keeps the scheme versioned. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

v2 prevents a hash from turning a weak validator into an apparent byte-identity guarantee. The existing absent-validator refusal is retained, not replaced by a fallback version. Source: [F-038 v1](../features/F-038-stream-budget-and-weak-etags.md), AC-07–AC-09.

## Examples

- **Given** a 16-byte file whose `bytes=0-0` download is 206 `bytes 0-0/16` with ETag `"opaque-etag-1"`
  **When** `describe` runs
  **Then** it returns `version_bound:true` and `etag` `"kd1-<base64url sha256>"`.
- **Given** the same file with a 257-byte ETag
  **When** `describe` runs
  **Then** it returns `etag:null` and the reader refuses `VERSION_UNAVAILABLE`.

v2 examples (the preceding examples describe superseded v1):

- **Given** a valid 16-byte file with a valid range probe and ETag `W/"x"` or no ETag
  **When** `describe` and a content invocation run
  **Then** the descriptor has `size_bytes:16, etag:null, version_bound:false` and the caller returns `VERSION_UNAVAILABLE` with zero `open` calls. Maps to `TestBR205_v2_AC07_weak_descriptor_matches_absent_validator`.
- **Given** a strong descriptor and valid `open` headers with `W/"x"` or no ETag
  **When** the content caller checks the response
  **Then** both responses have `etag:null`; the caller returns `CONTENT_UNAVAILABLE`, reads zero bytes and closes once. Maps to `TestBR205_v2_AC08_weak_open_matches_absent_validator`.
- **Given** derivation input `W/"x"`, `W/`, undefined, `"x"` or `w/"x"`
  **When** derivation runs
  **Then** the first three return `null`; the last two retain the exact original digest of the unchanged bytes. A strong `"x"` on describe/open preserves the baseline download, and the 256-byte accepted / 257-byte refused boundaries hold. Maps to `TestBR205_v2_AC09_prefix_is_case_sensitive_and_strong_derivation_unchanged`.
