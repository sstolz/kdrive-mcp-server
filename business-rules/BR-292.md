# BR-292 — Memory without the setting, persisted clients and families with it

## Rule

Without `oauthStateFile` every proxy store is in memory (BR-142 v2). With it, registered clients and refresh families (BR-139 v2) are loaded from the file at startup after the BR-302 purge and every change to them is written to it; pending consents, upstream flows, authorization codes and the discovery and JWKS caches stay in memory only and start empty.

## Rationale

Registered clients and refresh families must survive a restart while short-lived flow state stays in memory, which keeps the file small and free of secrets. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** no `oauthStateFile`
  **When** the proxy restarts
  **Then** registered clients and refresh tokens are gone
- **Given** a state file holding a client and a family, and a pending consent in memory
  **When** a new proxy opens the file
  **Then** the client and the family are loaded and the consent, upstream flows and codes start empty
