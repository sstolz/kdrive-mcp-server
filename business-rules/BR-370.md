# BR-370 — Multi-platform image build and gated push

## Rule

`scripts/release-image.sh` (host Docker) runs the BR-359 validation first and exits 1 without calling `docker` when an input fails. It builds target `runtime` of `Dockerfile` for `linux/amd64,linux/arm64` with a `docker-container` Buildx builder whose BuildKit image is pinned by digest, with no `--build-arg`, secret mount, `--cache-from` or `--cache-to`. With `RELEASE_DRY_RUN=true` the build has no `--push`, `--load`, `--output` or `--tag` and no login runs. With `RELEASE_DRY_RUN=false` it logs in to `ghcr.io` with `GITHUB_TOKEN` through `--password-stdin`, builds with `--push`, exactly one `--tag ghcr.io/sstolz/kdrive-mcp-server:<version>` and the labels `org.opencontainers.image.source`, `.version` and `.revision`, and logs out on exit whatever the outcome.

## Rationale

The release image is built cleanly for both platforms and pushed only in the approved job, without a token on the command line or a shared cache. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** dry run
  **When** `release-image` runs
  **Then** one `buildx build` has both platforms and no `--push`, `--tag` or `login`
- **Given** a real run whose build fails
  **When** `release-image` runs
  **Then** `logout ghcr.io` still runs and the exit is non-zero
