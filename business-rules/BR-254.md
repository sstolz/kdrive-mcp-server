## Rule

**v3 (F-054 v2, #139, accepted; the active rule).** The F-054 v2 BR-254 clause table retains every v2 clause except its explicitly replaced failure-precedence clauses. Stdio server/transport and gate close failures are consumed on signal, EOF, transport-failure, SDK-close, start-failure and host-close paths. Session ready and close resolve after consumed failures. Dedicated exit and owned closed wait for gate drain and server close settlement or the existing absolute shutdown deadline: 1,000 ms without a committed run, otherwise 45,000 ms from gate close, selected when cleanup evaluates hasCommitted. No fresh allowance is introduced. When the transport has not started closing, gate/sink cleanup starts as soon as server.close() is called; on server-close rejection or expiry it starts then if needed. Late rejection stays consumed. Each shutdown with a close rejection or expiry offers PROCESS_CLOSE_FAILED exactly once. Dedicated exit selects 1 after drain for a close failure or qualifying process stream latch; the production helper preserves failure precedence through primitive exit, retaining the first deadline and existing flush bounds. Owned closure calls its non-terminating setter only with 1, once per session, for that session's failure, ignoring process stream latches. No failure interrupts committed mutation drain.

**v1 (F-016 v1; superseded by v2)**

Closing the gate refuses new runs at admission, waits for each in-flight run to append or fail its outcome (bounded by that run's total deadline plus two bounded appends, BR-259; with the stderr sink the wait also depends on stderr draining, D-16-7), then closes the sink. On shutdown the composition closes in this order: (1) the transport (HTTP `close()` per BR-169, or the stdio session), (2) the gate, (3) process exit. An HTTP request whose run is in flight at step (1) receives BR-164's 503 while the gate still completes the run and records its outcome; that 503 does not state whether the write was performed, and the audit outcome is the authority.

**v2 (F-039 v1, #47; accepted on main `8bc1780`)** — Gate close refuses new runs, drains in-flight runs through their bounded outcome or append failure, then closes the sink; gate close always resolves and never rejects, including sink/release failures. For either sink, close settles within 5,000 ms from its first call, including active-append drain and owned file release; expiry latches the sink, rejects outstanding appends and resolves closed without claiming a flush. Owned file release starts only after the underlying port write or fdatasync operation itself settles and no operation remains in flight, never merely after append timeout; it gets only the remaining close budget. If a port operation remains pending at close expiry, release is skipped and the fd remains open until process exit, even after late settlement. No further write or sync starts after latching. Concurrent/repeated close calls share completion and never reset the deadline or release twice. Queued appends not yet written reject without I/O on close. Gate close in the guarded production composition is bounded by 45,000 ms from its call (5,000 intent + 30,000 sole attempt + 5,000 outcome + 5,000 sink close); pre-intent work remains guarded at 10,000 ms and cannot commit after gate close. For stdio with no run past intent, the remaining 1,000 ms shutdown deadline also shortens non-committed in-flight appends (including denied) before gate drain, then sink close; neither wait starts a fresh allowance (BR-070 v5). Transport, gate, then process exit and v1's HTTP 503 semantics remain unchanged for dedicated processes. Dedicated stdio routes its exit through the same production helper in src/production.ts as HTTP and other production exit callers, replacing its direct setImmediate/process.exit path. Owned/library compositions only set the exit code, including transport failures, and settle closure without terminating their host; their setter must not call the helper. src/main.ts passes the real deps.exit helper to dedicated src/stdio.ts separately from that setter. The helper accepts exit(code, shutdownDeadline?), an optional absolute monotonic timestamp; HTTP, non-shutdown callers and committed-run shutdown omit it. The helper is idempotent: its first call fixes code/deadline. It sets the requested process.exitCode and arms the ref'd timer before either empty stdout/stderr flush write behind queued output. Completion of both streams races the 250 ms timer from helper entry, capped at max(0, min(250, shutdownDeadline - now())) when supplied. Destroyed streams, error callbacks and synchronous write throws count as that stream's completion; flush errors never throw, emit an unhandled error or change the code. It calls process.exit(code) exactly once, clears the timer when streams win and safely ignores late callbacks/errors; repeated calls cannot write again or reset code/deadline. An exhausted budget calls exit immediately. Dedicated STDIO_OUTPUT_FAILED/STDIO_START_FAILED paths preserve code 1. Non-shutdown callers retain their codes and the same 250 ms cap. Output still queued after 250 ms on a stalled pipe may be lost, or earlier if the remaining stdio budget is shorter. Sink/gate closure never waits for the diagnostic callback or stderr drain; shared stderr is never ended or destroyed. Synchronous fd 2 writes to a file or TTY that block the event loop prevent timers from firing and remain unbounded, outside these guarantees. A write or fdatasync stuck in the libuv threadpool may also hold OS/runtime teardown after process.exit is called; actual termination and release of a retained fd are unbounded in that case. Both OS-level limits are documented, not fixed.

## Rationale

Shutdown must not lose the outcome of a dispatched write (D-16-14). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

v2: Both append waiting and release can stall shutdown. A single close budget preserves result classification and the existing shutdown order within the deployment grace. The shared helper's short 250 ms flush opportunity allows ordinary fire-and-forget startup/fatal messages and the fixed diagnostic to drain promptly without waiting indefinitely; it is a policy cap, not a delivery guarantee or measured latency. Source: [F-039 v1](../features/F-039-bounded-audit-sink.md).

## Examples

- **Given** a committed run and a server close that never settles
  **When** SIGTERM starts shutdown
  **Then** the outcome and sink close precede failure exit at the existing 45,000 ms deadline. Maps to `TestBR254_v3_AC04_stdio_signal_close_rejection_is_contained`.

- **Given** an in-flight run whose mutator settles after `close()`
  **When** `close()` resolves
  **Then** the outcome was recorded before the sink closed
- **Given** the HTTP composition with a committed run
  **When** SIGTERM arrives
  **Then** the client gets 503, the outcome is recorded, then the process exits

v2 examples (the preceding examples describe superseded v1):

- **Given** an active blocked stderr append, a queued record and close at 0 ms
  **When** 5,000 ms elapse
  **Then** the queued record never starts, the active append rejects, close resolves and stderr is not destroyed. Maps to `TestBR254_v2_AC07_sink_close_bounds_drain_and_release`.
- **Given** file append success at 4,000 ms and an owned close that never settles
  **When** 4,999 then 5,000 ms elapse from sink close
  **Then** close is pending then resolves with the latch set; exactly one release was attempted. Maps to `TestBR254_v2_AC07_sink_close_bounds_drain_and_release`.
- **Given** a file append at 0 ms whose underlying write or fdatasync remains pending after append timeout and close at 5,000 ms
  **When** that operation settles at 6,000 ms
  **Then** release starts only after settlement, at most once, with the remaining 4,000 ms close budget and no further write or sync. Maps to `TestBR254_v2_AC07_sink_close_bounds_drain_and_release`.
- **Given** the same underlying operation still pending at the 10,000 ms close deadline
  **When** close resolves and the operation settles at 11,000 ms or never settles
  **Then** release is skipped, the fd stays open until process exit and repeated close causes no I/O or unhandled rejection. Maps to `TestBR254_v2_AC07_sink_close_bounds_drain_and_release`.
- **Given** a sole upstream attempt in flight at gate close
  **When** its 30,000 ms bound and stalled outcome/release bounds elapse
  **Then** the uncertain result is preserved with outcome_unrecorded, and gate close resolves within 45,000 ms. Maps to `TestBR070_v5_AC08_shutdown_keeps_committed_result_semantics`.
- **Given** the real production exit helper with queued stderr output and both flush callbacks firing at 5 and 10 ms
  **When** it is called with code 0 or 1
  **Then** it sets that code, flushes queued output and calls exit once immediately after both callbacks at 10 ms, clearing the fallback timer. Maps to `TestBR254_v2_AC12_real_production_exit_bounds_flush_wait`.
- **Given** the same helper with one or both stdout/stderr callbacks never firing
  **When** fake time advances to 249 then 250 ms
  **Then** the ref'd timer keeps exit pending until 250 ms and calls the primitive once with the requested code; late callbacks never repeat exit. Maps to `TestBR254_v2_AC12_real_production_exit_bounds_flush_wait`.
- **Given** that stalled helper with 100 ms of stdio shutdown budget remaining
  **When** fake time advances to 99 then 100 ms
  **Then** exit remains pending then occurs once at 100 ms; with zero remaining budget it occurs immediately without another wait. Maps to `TestBR254_v2_AC12_real_production_exit_bounds_flush_wait`.
- **Given** the dedicated stdio path through the shared helper, an injected exit primitive and a denied append pending at shutdown with no run past intent
  **When** the remaining 1,000 ms shutdown budget expires
  **Then** the denied result settles, sink/gate close complete and the helper calls exit once without another allowance; owned/library closure controls never terminate their host. Maps to `TestBR070_v5_AC13_denied_append_shares_remaining_stdio_shutdown_budget`.

- **Given** stdout destroyed by transport close, or a flush callback error/write throw
  **When** the other stream completes
  **Then** the helper exits once with the original code, contains late errors, and clears its timer armed before writes. Repeated calls never reset code/deadline. Maps to `TestBR254_v2_AC12_real_production_exit_bounds_flush_wait`.
- **Given** dedicated stdio failure or an owned failing transport
  **When** closure settles
  **Then** dedicated exit receives 1; owned closure only sets 1 without terminating its host. Maps to `TestBR070_v5_AC13_denied_append_shares_remaining_stdio_shutdown_budget`.
