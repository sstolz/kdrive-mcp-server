# BR-434 — Conservative deny-pattern root classification

## Rule

A valid deny pattern is outside configured roots exactly when every configured
root has a known diagnostic path, no applicable root is component-compatible,
and no known configured root has BR-040's raw-prefix relation to the pattern.
The complete criterion is frozen in
[F-048 v1](../features/F-048-deny-pattern-root-warning.md#conservative-compatibility-criterion-br-434-v1).

Patterns starting with `**/` are always potentially useful. For anchored
patterns, compare the complete leading literal components before the first
wildcard component with each root's components: either sequence being a prefix
of the other gives compatibility, provided that a pattern without a whole
component `**` has at least as many components as the root. Comparisons are
case-sensitive and do not normalize Unicode. `/` has zero components.

Independently suppress classification when the raw pattern prefix before the
first `*` or `?` and a configured root path satisfy `startsWith` in either
direction. This BR-040 exception has no component boundary and applies in
every startup mode. With `sharedWithMe=true`, add synthetic `/Shared` for the
component check only; the raw-prefix exception never applies to that synthetic
root. Any unknown configured path suppresses all classifications. Evidence is
bound to resolved drive/folder identities and is a startup snapshot only.

## Rationale

Identify literal API-path mistakes without warning about patterns that can
still match under another root, affect configured-folder sharing, or apply to
received shares. Classification never authorizes access or changes filtering.

## Examples

- **Given** root `/Private/Documents` and `/Documents/Confidential/**`
  **When** classification runs
  **Then** the pattern is outside configured roots.
- **Given** the same root and `/Private/Documents/Confidential/**`
  **When** classification runs
  **Then** it is compatible.
- **Given** the same root and `/Private/Documents2/**`
  **When** classification runs
  **Then** BR-040's character-prefix relation suppresses classification.
- **Given** the same root and `/Shared/Project/**`
  **When** classification runs with received shares enabled
  **Then** synthetic `/Shared` suppresses classification; with received shares
  disabled the pattern is outside configured roots.
- **Given** any configured root with an unknown path
  **When** classification runs
  **Then** no pattern is classified outside configured roots.
