## Rule

An append resolves only after the complete record was passed to one write call and that call wrote every byte, followed, for the file sink, by a successful `fdatasync`, and, for the stderr sink, by an error-free write callback.

## Rationale

An intent must be durable before the write it announces (D-16-7). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** a file sink whose `fdatasync` has not completed
  **When** an append runs
  **Then** the append is still pending
- **Given** a stderr sink whose write callback has not fired
  **When** an append runs
  **Then** the append is still pending
