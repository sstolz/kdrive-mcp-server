## Rule

When the intent append rejects (disk full, permission error, closed stream, latched sink, oversize record), the gate makes zero upstream attempts and returns `failed` with code `AUDIT_UNAVAILABLE` and `attempts:0`.

## Rationale

A write without a durable intent would be unaudited (SPEC §9). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** an intent append failing with `ENOSPC`
  **When** an authorized run starts
  **Then** the mutator is not called and the result is `failed`/`AUDIT_UNAVAILABLE`/`attempts:0`
- **Given** a sink latched after admission
  **When** the run reaches its intent
  **Then** the result is the same and no record is written
