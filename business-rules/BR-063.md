## Rule

**v2 (F-050 v1, #75; pending acceptance).** Successful info output contains
exactly `drive_id`, `id`, `name`, `type`, `path`, `size_bytes`, `modified_at`
from the exact normalized live item authorized in that invocation. Every other
navigation item output keeps the five-field projection. Existing authority,
received terminal checks, structural refusals and getter/toJSON safeguards hold.
Only the private info consumer port projects the two re-validated scalars;
operation parsing, check, dispatch and capability decisions are unchanged.

### Accepted rule (v1, still active until v2 acceptance)

Metadata output is a fixed scalar projection of the exact normalized live item authorized by the policy invocation.

## Rationale

Arbitrary execute responses or custom metadata fields are not authorization evidence. Source: [F-005 v1](../features/F-005-stdio-navigation.md), AC-05.

## Examples

- **Given** authorized file7:3 at /docs/a.
  **When** info reads file3.
  **Then** v1 returns only drive_id,id,name,type,path; pending v2 additionally
  returns size_bytes and modified_at, independently null when unknown.
- **Given** a metadata object with a getter or unchecked execute canary.
  **When** info runs.
  **Then** the getter/execute payload is never serialized or executed.
