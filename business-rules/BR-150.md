# BR-150 — Secrets reach only pristine analysis code

## Rule

During `make sonar` and `make sonar-pr`, only the `analysis` Compose service
receives `SONAR_TOKEN`, `SONAR_HOST_URL` or a credential/host file mount. Snapshot
preparation runs in a `prep` service that reuses the `dev` image and mounts the
checkout read-only with `artifacts/sonar-input` as its only writable bind; every
`docker compose` call of the entry script passes `-f compose.yaml`, and the entry
script refuses Compose override files and `.env` at start and before the
analysis service. With `SONAR_PRISTINE_TAR` (required in CI), the snapshot behind
`current-<pid>` must be physically under `artifacts/sonar-input`, a bidirectional
`diff -r` against the extracted pristine archive (excluding only the generated
root entries) must report nothing, no nested generated name may exist, and the
root `node_modules` must be absent or a symlink to `/workspace/node_modules`. The
mode reaches the wrapper as the fixed `SONAR_ANALYSIS_MODE` (`main` or `pr`) from
the Make target and must match the manifest event; in CI the manifest `commit`
equals `GITHUB_SHA` and its `runId` equals the snapshot directory name. The `dev`
service binds `./.git` read-only at `/workspace/.git` over its checkout bind
(`create_host_path: false`) and the `prep` service keeps `.git` read-only through
its read-only checkout bind; every service whose bind covers the checkout either
binds it read-only or carries that `.git` bind, and no other mount targets
`/workspace/.git` or a path below it. No container code can write Git metadata,
and no Make target writes `.git`.

(v1: `.git` was writable in the `dev` service.)

## Rationale

Third-party build and test code runs during preparation; it must not be able to rewrite what later runs with secrets or what is uploaded. Dependency lifecycle code run by `make setup` could otherwise set `core.fsmonitor` or a hook in `.git`, which the `actions/checkout` post step would execute on the host in the secret-bearing job. Source: [F-011 v2](../features/F-011-pre-merge-quality-gates.md).

## Examples

- **E-01 — Given** a snapshot identical to the pristine archive except generated `coverage/`
  **When** `make sonar-pr` reaches the pre-analysis comparison
  **Then** the analysis service starts.
- **E-02 — Given** a snapshot whose `src/x.ts` was rewritten after coverage
  **When** the comparison runs
  **Then** it fails before the analysis service starts.
- **E-03 — Given** a manifest with event `push` and `SONAR_ANALYSIS_MODE=pr`
  **When** the wrapper runs
  **Then** it fails before spawning the scanner.
- **E-04 — Given** the committed `compose.yaml`
  **When** the service mounts are inspected
  **Then** `dev` carries the read-only `./.git` bind after its checkout bind and `prep` mounts the checkout read-only.
- **E-05 — Given** a mutated `compose.yaml` that adds a writable bind at `/workspace/.git/hooks`
  **When** the service mounts are inspected
  **Then** the check rejects it.
