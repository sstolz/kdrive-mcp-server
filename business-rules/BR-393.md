# BR-393 — CIMD consent page

## Rule

The consent page of a CIMD client shows, before the self-declared name, the client ID URL and on its own line its host (`Client host: <host>`), both HTML-escaped; it states that the name comes from the client's metadata document and is unverified; and when the request's `redirect_uri` is a loopback URI (scheme `http` and host an IPv4 address in `127.0.0.0/8`, `[::1]` or `localhost`) it shows the line `This client redirects to this computer only (loopback).` The page of a registered client is unchanged.

## Rationale

The client name of a CIMD client is self-declared; the client ID and its host are what the user can check (draft consent guidance). Source: [F-028 v2](../features/F-028-client-id-metadata-documents.md).

## Examples

- **Given** a CIMD client named `<b>Claude</b>` and `redirect_uri` `http://127.0.0.1:33418/cb`
  **When** authorize shows the consent page
  **Then** it shows the escaped client ID, `Client host: client.example.com`, the escaped name with the unverified notice and the loopback line
- **Given** the same client with `redirect_uri` `http://localhost.example.com/cb`
  **When** authorize shows the consent page
  **Then** the loopback line is absent
- **Given** a registered client
  **When** authorize shows the consent page
  **Then** the page is byte-identical to the F-010 page
