## Rule

`scripts/ci-changes.sh <event>` reads changed paths, one per line, on stdin and prints exactly two lines, `heavy=<true|false>` then `image=<true|false>`. `heavy=false` only when `<event>` is `pull_request`, the list is non-empty and every path is a records path: under `runs/`, `features/`, `business-rules/` or `architecture-decisions/`, or exactly `learnings.md`, `BACKLOG.md`, `CHANGELOG.md` or `capability-map.md`. `image=false` only when `<event>` is `pull_request`, the list is non-empty and no path is an image input: `Dockerfile`, `.dockerignore`, `package.json`, `package-lock.json`, `tsconfig.json`, `tsconfig.build.json`, `LICENSE`, `NOTICE`, `README.md`, `Makefile`, `scripts/image-smoke.sh`, `scripts/http-acceptance.ts`, `scripts/ci-changes.sh`, `.github/workflows/ci.yml`, or any path under `src/`. Otherwise each value is `true`. `make ci-changes` requires `GITHUB_OUTPUT` and `GITHUB_EVENT_NAME`; on `pull_request` it feeds `git diff --no-renames --name-only -z HEAD^1 HEAD` (NUL converted to newline) to the script; when that `git` command fails, it writes `heavy=true` and `image=true`; it appends the result to `$GITHUB_OUTPUT`.

## Rationale

Records-only PRs skip the costly jobs while every doubt runs everything (D-07). Source: [F-015 v1](../features/F-015-self-hosted-runner.md).

## Examples

- **Given** a `pull_request` listing `runs/x.md` and `BACKLOG.md`
  **When** `ci-changes.sh pull_request` runs
  **Then** it prints `heavy=false` and `image=false`
- **Given** a `push` listing `runs/x.md`
  **When** `ci-changes.sh push` runs
  **Then** it prints `heavy=true` and `image=true`
