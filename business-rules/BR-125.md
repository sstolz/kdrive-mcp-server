## Rule

The metadata handler returns status 200, `Content-Type: application/json` and an RFC 8414 document whose members are exactly: `issuer` (proxy issuer), `authorization_endpoint` (`<issuer>/oauth/authorize`), `token_endpoint` (`<issuer>/oauth/token`), `registration_endpoint` (`<issuer>/oauth/register`), `response_types_supported` `["code"]`, `grant_types_supported` `["authorization_code","refresh_token"]`, `code_challenge_methods_supported` `["S256"]`, `token_endpoint_auth_methods_supported` `["none","client_secret_basic","client_secret_post"]` and `authorization_response_iss_parameter_supported` `true`. It has no `client_id_metadata_document_supported` member. `<issuer>` is the proxy issuer without trailing slash. `metadataPaths` lists, in order, the RFC 8414 path `/.well-known/oauth-authorization-server<issuer path>`, the OIDC path-insertion form `/.well-known/openid-configuration<issuer path>` and the OIDC path-append form `<issuer path>/.well-known/openid-configuration` (duplicates removed when the issuer path is empty); P-12 serves the same document at each.

## Rationale

MCP clients discover the proxy through RFC 8414 metadata; RFC 9207 lets ChatGPT and Codex use stable redirects. Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-02.

## Examples

- **Given** issuer `https://mcp.test/mcp`
  **When** metadata is requested
  **Then** the document lists `https://mcp.test/mcp/oauth/...` endpoints, RFC 9207 `true` and no CIMD member.
- **Given** issuer `https://mcp.test`
  **When** `metadataPaths` is read
  **Then** it holds the RFC 8414 path and one OIDC path.
