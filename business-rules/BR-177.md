## Rule

`make image` first runs `docker buildx version` and fails with a message naming Buildx when it fails. Then, for each platform in `IMAGE_PLATFORMS` (default `linux/amd64 linux/arm64`), it builds the targets `runtime` and `smoke` with `docker buildx build --platform <platform> --target <target> --load`, tagged `kdrive-mcp-server:<target>-<arch>`, with no `--build-arg` and no secret mount; after each load, `docker image inspect --format '{{.Os}}/{{.Architecture}}'` must equal `<platform>`, else it fails naming the tag. It never calls `image-binfmt`.

## Rationale

Both architectures are built locally and verified without any registry. Source: [F-013 v1](../features/F-013-http-image.md).

## Examples

- **Given** a stub docker whose loaded image reports `linux/arm64`
  **When** `make image IMAGE_PLATFORMS=linux/amd64` runs
  **Then** it fails naming `kdrive-mcp-server:runtime-amd64`
- **Given** a stub docker reporting `linux/amd64`
  **When** the same command runs
  **Then** it builds `runtime` then `smoke` with `--load` and exits 0
