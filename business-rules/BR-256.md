## Rule

The production composition binds the policy `execute` dependency to the gate executor, which dispatches only the operation of the gate run active in the same async context and returns `{status: "unavailable"}` with no record and no upstream request for any other call; mutation decisions use the F-014 `inspect`, `children` and received evidence and the configured `maxTreeItems`, so that a denied descendant or result path, a reached cap, an exhausted page budget, unproven paging termination, or a path or parent that differs between observations of one decision gives `denied` with zero intent records and zero upstream requests.

## Rationale

Mutation decisions must use real production evidence and the executor must only serve its own run (D-16-10). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** `deny=["**/secret","**/secret/**"]` and a folder with a `secret` descendant
  **When** a folder rename runs
  **Then** it is `denied` with no intent and no non-GET request
- **Given** a direct call of the policy `execute` dependency
  **When** no gate run is active
  **Then** it returns `unavailable` with no record and no request
