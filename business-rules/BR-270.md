# BR-270 — No permanent deletion

## Rule

The route table contains no route that permanently deletes an item or empties the trash, and no tool, mutator or acceptance step can issue a `DELETE` on a path containing `/trash`.

## Rationale

Trash stays recoverable; this server never requests permanent deletion. Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** the mutation route table
  **When** it is listed
  **Then** its only `DELETE` template is `/2/drive/{d}/files/{f}`
- **Given** the source tree and the acceptance tooling
  **When** they are scanned
  **Then** no `DELETE` on a `/trash` path is built
