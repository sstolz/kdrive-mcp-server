# BR-278 — Configured roots are protected

## Rule

The policy core denies (`ACCESS_DENIED`) a `trash`, `rename` or `move` operation whose `(drive_id, target ID)` pair equals any configured root pair (root `1` included), so the gate returns `denied` with zero intent records and zero mutation requests; this replaces F-003's sentence "A non-root configured root can be renamed".

## Rationale

A configured root is the operator's boundary; moving or renaming it would silently change the scope. Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** configured roots `101:1` and `101:40`
  **When** `kdrive_trash` targets 40
  **Then** the result is `denied` with no intent record
- **Given** a second configured drive 102 whose root holds an item with ID 40
  **When** that item is renamed
  **Then** the result is `succeeded`
