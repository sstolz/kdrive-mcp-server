# BR-321 — Dependency audit documentation

## Rule

`docs/development.md` no longer states that the audit is not clean; its dependency-audit paragraph names the BR-315 overrides, ADR-009, `make audit` and the CI `audit` job. `SECURITY.md` has a section `## Dependency audit` stating that CI fails on any high or critical `npm audit` finding, that a new one is fixed before a release, not allowlisted, and that the overrides do not apply to an install of the packed tarball (`npm install -g`), which can resolve Jimp's nested Zod 3 again. `CHANGELOG.md` Unreleased has a `### Fixed` line for the advisories and an `### Added` line for `make audit` and the CI job, both citing #104.

## Rationale

Operators and contributors must know the audit contract and the residual tarball-install risk (D-1). Source: [F-020 v1](../features/F-020-dependency-audit.md).

## Examples

- **Given** the updated docs
  **When** the content test runs
  **Then** `docs/development.md` names `make audit` and ADR-009 and has no "audit is not clean" sentence
- **Given** `SECURITY.md`
  **When** the content test runs
  **Then** `## Dependency audit` states the high/critical gate, no allowlist and the `npm install -g` limit
- **Given** `CHANGELOG.md`
  **When** the content test runs
  **Then** Unreleased cites #104 under Fixed and Added
