## Rule

The identity of an accepted ID token is the pair (upstream issuer, `sub`) plus `email` and `email_verified` when present. It is authorized when the pair is in `oauthAllowedSubjects` (paired with the upstream issuer), or when the email allowlist contains `email` exactly and `email_verified` is the boolean `true`. An unauthorized identity produces a client redirect with `error=access_denied`, and no code is created.

## Rationale

Authentication by the provider does not authorize every account; only listed owners obtain codes (D-05). Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-15.

## Examples

- **Given** an ID token for allowed `sub` `user-1`
  **When** the callback completes
  **Then** a code is issued.
- **Given** an allowed email with `email_verified` `"true"`
  **When** the callback completes
  **Then** 302 with `error=access_denied` and no code.
