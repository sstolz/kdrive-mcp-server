## Rule

Every mutation socket retains a payload-free permanent `error` listener
attached when `connect` returns and never removed. On the first error it
records the error and destroys the socket; `exchange()` writes no request
once an error is recorded. A pending mutation settles under BR-267 v1:
branded `NotSent` before handshake completion, unbranded `MUTATION_UNKNOWN`
from completion onward.

## Rationale

Continuous error handling prevents an uncaught socket error during the
handshake-to-request handoff or cleanup without exposing its payload.
Source: [F-051 v1](../features/F-051-transport-edge-cases.md), AC-01–AC-02.

## Examples

- **Given** TLS completion schedules socket destruction with an error before
  the awaited continuation
  **When** the mutation resumes
  **Then** no request bytes are sent, the port rejects with unbranded
  `MUTATION_UNKNOWN` and the gate returns `uncertain` / `UPSTREAM_UNCERTAIN`,
  attempts 1, without replay. A late error neither throws nor emits payload
  output or settles again. Maps to
  `TestBR438_v1_same_tick_secureConnect_error_is_unknown_without_crash`.
- **Given** a socket before handshake completion
  **When** it emits an error
  **Then** the port rejects with branded `NotSent`, the gate returns `failed` /
  `NOT_SENT`, the socket is destroyed and the limiter slot is released, without
  an uncaught exception or payload output. Maps to
  `TestBR438_v1_pre_handshake_error_is_NotSent_without_crash`.
