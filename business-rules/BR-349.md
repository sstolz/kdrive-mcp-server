# BR-349 — Privacy scan summary and internal error

## Rule

After scanning, the last stdout line is `privacy-scan: <h> hits, <f> files, <b> binary skipped, <g> gitlinks skipped, <c> commits, <p> patterns`; the exit status is 0 when `h` is 0, else 1. Any unexpected error (Git failure, read error, exception) is caught by one top-level handler that prints only `privacy-scan: internal error` to stderr and exits 2; no stack, message or partial summary is printed. Every git child process runs with its stderr piped and discarded, never inherited.

## Rationale

A Git or runtime message could quote content; a partial summary could pass for a clean scan. Source: [F-023 v1](../features/F-023-hosted-ci-privacy-scan.md).

## Examples

- **Given** a clean repository
  **When** the scan runs
  **Then** the last line is the summary with `0 hits` and the exit is 0
- **Given** the scan run outside a repository with a valid secret and head
  **When** it runs
  **Then** stdout is empty, stderr is exactly `privacy-scan: internal error` and the exit is 2
