# BR-337 — Sanitized server fields

## Rule

Every server-supplied field is sanitized before printing, in this order: (1) escape — `\` becomes `\\`, and every `Cc` code point (C0, U+007F and C1), U+061C, U+200E–U+200F, U+202A–U+202E, U+2066–U+2069, U+2028, U+2029, every other Unicode `Cf`, `Zl` or `Zp` code point and every lone surrogate (`Cs`) becomes `\uXXXX` (four uppercase hex digits) when at most U+FFFF, else `\u{X…}` (uppercase hex, no padding); (2) redact — `redact(text, token, hostname)`; (3) truncate — `message` to 200 code points and any other field to 100, where the cut never splits an escape sequence or a `[REDACTED]` marker: if the limit falls inside one, the cut moves to its start. The output is unambiguous: a literal backslash is always `\\`.

## Rationale

Neutralizes log injection and the #113 bidirectional-character failure mode, and never leaks a token fragment through truncation (T3, D-7). Source: [F-022 v1](../features/F-022-sonar-gate-summary.md).

## Examples

- **Given** an issue message holding U+202E, U+007F, a lone surrogate U+D800, U+E0001 and a literal backslash
  **When** the summary prints
  **Then** they appear as `\u202E`, `\u007F`, `\uD800`, `\u{E0001}` and `\\`
- **Given** a message of 195 `x` followed by the token
  **When** the summary prints
  **Then** the message is exactly the 195 `x`: the `[REDACTED]` marker that would cross 200 code points is cut whole
