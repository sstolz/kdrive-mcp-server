# BR-018 — Explicit bounded YAML input

Statement preserved from [F-002 v1](../features/history/F-002-v1.md); accepted under [F-002 v2](../features/F-002-configuration.md). The v2 CLI diagnostic phase ordering applies without rewriting this rule.

## Rule

Read YAML only when `--config` explicitly selects it. Enforce the
source-format, syntax and size limits below; perform no `.env` loading, file
search, interpolation, execution, YAML tags, merge keys or alias expansion.
Imports of the configuration module perform no I/O. Source readers and the
process environment/argv are injectable so tests never depend on deployment
state. Read only the explicitly selected YAML and credential files.

The source specification's inventory, bounds, grammars, auth matrix, credential
contract, error mapping and preflight port supply the normative details for
this statement; this record does not redefine those tables.

## Rationale

Prevent configuration discovery, expansion or import-time side effects.

## Examples

These examples illustrate the accepted rule; they do not replace the source specification or claim a new test execution. Unless a scenario overrides them, local-loader fixtures use explicit drive `7` and token `SYNTHETIC_TOKEN`, with no deployment state. Each verification reference identifies one existing test case or table row.

- **Given** valid synthetic environment settings for drive `7`, no `--config` argument and an injected file-reader spy.
  **When** configuration loads.
  **Then** the reader is never called; configuration does not search for YAML or `.env` files.
  Verified by: [`checks structures before winning values and reads no implicit files`](../tests/config.test.ts), no-reader-call assertion.

- **Given** `--config settings.yaml` with injected YAML `driveIds: [7, 8]` and valid synthetic credentials.
  **When** configuration loads.
  **Then** the configured drive list is `[7, 8]`.
  Verified by: [`checks YAML primitive shapes even when overridden, but only winning scalar content`](../tests/config.test.ts), valid numeric YAML-list assertion.

- **Given** `--config settings.yaml --mode read` with YAML `mode: [read]`.
  **When** YAML primitive shapes are checked.
  **Then** it rejects with `{code: INVALID_VALUE, setting: mode}` even though CLI would replace the value.
  Verified by: [`checks YAML primitive shapes even when overridden, but only winning scalar content`](../tests/config.test.ts), overridden primitive-shape assertion.

- **Given** `--config settings.yaml --mode read` with YAML `mode: BAD`.
  **When** the valid YAML scalar shape is accepted and winning content is selected.
  **Then** the effective mode is `read`; losing scalar content is not validated.
  Verified by: [`checks YAML primitive shapes even when overridden, but only winning scalar content`](../tests/config.test.ts), overridden scalar-content assertion.

- **Given** explicit YAML `mode: &a read` with CLI `--mode read`.
  **When** YAML structure is parsed.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}`; an override does not permit anchors.
  Verified by: [`rejects forbidden YAML structure %s`](../tests/config.test.ts), row `mode: &a read`.

- **Given** explicit YAML `unknown: x` followed by `mode: {}`.
  **When** YAML syntax and structure are checked.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}` before the unknown key.
  Verified by: [`orders YAML structural, unknown-key and primitive failures and bounds bytes`](../tests/config.test.ts), nested-map assertion.

- **Given** explicit YAML `unknown: x` followed by `mode: []`.
  **When** YAML unknown keys are checked after structural validity.
  **Then** it rejects with `{code: UNKNOWN_SETTING, setting: configFile}` before the recognized mode's primitive shape.
  Verified by: [`orders YAML structural, unknown-key and primitive failures and bounds bytes`](../tests/config.test.ts), unknown-key assertion.

- **Given** an explicitly selected real fixture containing exactly 65,536 ASCII `#` bytes.
  **When** the bounded YAML reader and parser run.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}` because a comment-only document is not the required mapping; it does not report a byte overflow.
  Verified by: [`maps real YAML failures without decoding excerpts or reading credential files`](../tests/config.test.ts), 65,536-byte fixture.

- **Given** the same explicit fixture containing 65,537 ASCII `#` bytes.
  **When** the bounded YAML reader runs.
  **Then** it rejects with `{code: LIMIT_EXCEEDED, setting: configFile}` before parsing the comment-only document.
  Verified by: [`maps real YAML failures without decoding excerpts or reading credential files`](../tests/config.test.ts), 65,537-byte fixture.

- **Given** explicit YAML `mode: read` repeated as a second key `mode: share`.
  **When** YAML structure is parsed.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}` for duplicate keys.
  Verified by: [`rejects forbidden YAML structure %s`](../tests/config.test.ts), row `mode: read\nmode: share`.

- **Given** explicit YAML `mode: !custom read`.
  **When** YAML structure is parsed.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}` for a custom tag.
  Verified by: [`rejects forbidden YAML structure %s`](../tests/config.test.ts), row `mode: !custom read`.

- **Given** explicit YAML `mode: *a`.
  **When** YAML structure is parsed.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}` for an alias.
  Verified by: [`rejects forbidden YAML structure %s`](../tests/config.test.ts), row `mode: *a`.

- **Given** explicit YAML `<<: {}`.
  **When** YAML structure is parsed.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}` for a merge key.
  Verified by: [`rejects forbidden YAML structure %s`](../tests/config.test.ts), row `<<: {}`.

- **Given** explicit YAML `[]`.
  **When** the document shape is checked.
  **Then** it rejects with `{code: CONFIG_SYNTAX, setting: configFile}` because the top-level document is not a mapping.
  Verified by: [`rejects forbidden YAML structure %s`](../tests/config.test.ts), row `[]`.

### Additional boundary coverage

These boundary cases exercise the existing accepted F-002 v2 behavior through injected synthetic inputs. Their named tests are implemented in the linked test file.

- **Given** explicit `--config settings.yaml` selecting ASCII bytes `mode: read`, LF, `#`, then 65,524 `x` characters, exactly 65,536 bytes.
  **When** configuration loads the bounded YAML mapping.
  **Then** it accepts the document and effective mode is `read`.
  Verified by: [`TestBR018_ValidYaml65536Accepted — BR-018 v1`](../tests/config-selection-boundaries.test.ts).

- **Given** explicit `--config settings.yaml` selecting ASCII bytes `mode: read`, LF, `#`, then 65,525 `x` characters, exactly 65,537 bytes.
  **When** configuration reads the selected YAML.
  **Then** it rejects with `{code: LIMIT_EXCEEDED, setting: configFile}` before parsing the otherwise valid mapping.
  Verified by: [`TestBR018_ValidYaml65537Rejected — BR-018 v1`](../tests/config-selection-boundaries.test.ts).
