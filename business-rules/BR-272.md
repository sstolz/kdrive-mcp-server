# BR-272 — Folder-create check

## Rule

The `create` check accepts a `data` file object whose `id` is a positive safe integer, `type` is `dir`, `name` equals the requested name and `parent_id` equals the destination ID; the mutator then returns `created` equal to that `id` and `value` `{drive_id, id}` with the new ID.

## Rationale

A server-side rename or another parent means the checked path was not the created one (D-17-9). Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** a 200 with `{id:77, type:"dir", name:"new", parent_id:40}` for a create of `new` in 40
  **When** the run ends
  **Then** it is `succeeded` with `value` `{drive_id:101, id:77}` and the outcome record `created:77`
- **Given** a 200 whose `name` is `new (1)`
  **When** the run ends
  **Then** it is `uncertain`
