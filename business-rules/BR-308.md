# BR-308 — CIMD document validation and snapshot

## Rule

A fetched body is a valid document when it is a JSON object (UTF-8, no byte-order mark) such that: `client_id` is byte-identical to the fetched URL; it has no `client_secret` and no `client_secret_expires_at` member; the token endpoint method resolves to `none` (when `token_endpoint_auth_methods_supported` is present it is an array of strings that contains `none`; otherwise `token_endpoint_auth_method` is absent or `none`; when both are present the singular value is in the array); `redirect_uris` is a nonempty array of strings of which at least one matches an entry of the current `oauthAllowedRedirectUris` under BR-126; `grant_types` is absent (meaning `authorization_code` and `refresh_token`) or an array of strings that contains `authorization_code`; `response_types` is absent or an array of strings that contains `code`; `client_name` is absent or a string of 1–200 characters without control characters. Redirect URIs that match no allowlist entry, and grant and response types other than `authorization_code`, `refresh_token` and `code`, are ignored, not refused. The client used by the authorization request has the matching redirect URIs (at most the first 10 in document order), the kept grant types and the name; every other member is ignored and never stored, logged or displayed. The pending consent, the pending upstream flow and the authorization code each carry a snapshot of this resolved client (kept redirect URIs, kept grants, whether `refresh_token` is kept, name), taken at the resolution; the client is never re-resolved later in the flow (consent submission, callback, code redemption), whatever the cache then holds. An invalid document is a terminal failure.

## Rationale

Only documents that bind themselves to their URL, use no shared secret and stay within the redirect allowlist may authorize; filtering is lenient as in the draft (D-3, D-11). Source: [F-028 v1](../features/F-028-client-id-metadata-documents.md).

## Examples

- **Given** a document with a `client_secret`, a different `client_id` or `response_types` `["token"]`
  **When** authorize resolves it
  **Then** the 400 page, no redirect, `client_metadata_refused` `document`
- **Given** a document with two allowlisted and three other redirect URIs and grants `["authorization_code","refresh_token","urn:x"]`
  **When** authorize resolves it
  **Then** the request reaches consent and a non-allowlisted `redirect_uri` gets the 400 page
- **Given** a request authorized with a document keeping `refresh_token`
  **When** the cached document is replaced by one without it before redemption
  **Then** the code still yields a refresh token
