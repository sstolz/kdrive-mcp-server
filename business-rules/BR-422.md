# BR-422 — Peer of an OAuth request

## Rule

The peer of a request on an OAuth route is derived from the socket's remote address `S`, as Node reports it, and the BR-421 list `T`: (1) normalise `S`: drop its IPv6 zone index (`%…`), parse the full address, and convert IPv4-mapped IPv6 to IPv4, including hexadecimal mapped forms; an IPv4 address never matches an IPv6 entry of `T`, nor the reverse; compare full addresses against trusted prefixes, never addresses already grouped to `/64`; (2) when `T` is empty or `S` is not inside an entry of `T`, the peer address is `S`, and no forwarding header is read; (3) otherwise the `X-Forwarded-For` field lines are joined in order with commas and split on commas, each element is trimmed of spaces and tabs, and the elements are examined from the rightmost, at most 32 of them; first validate each raw trimmed element as an IPv4 address in dotted-decimal form without leading zeros or an IPv6 address without brackets, port or zone (uppercase and uncompressed IPv6 and dotted or hexadecimal IPv4-mapped forms are valid); an invalid or empty element ends the walk before normalisation, so a header zone is never stripped; then normalise each valid element to its full address, converting mapped IPv6 to IPv4, and compare it against `T`; the peer address is the first examined valid element outside `T`, which ends the walk; when none is found before an invalid element, the leftmost element or the 32nd, it is the leftmost valid element examined, or `S` if none was valid (no header, an empty one, or an invalid rightmost element); (4) only after the walk, group the final peer address: the peer is the IPv4 address itself, or the first 64 bits of an IPv6 address; two IPv6 addresses whose first 64 bits are equal are the same peer; a socket without a remote address is the one peer `unknown`; (5) the `Forwarded`, `X-Real-IP` and other `X-Forwarded-*` headers are never read, and the peer serves only the BR-162 v3 windows.

## Rationale

The per-peer windows of BR-162 v3 need a client identity that a client cannot choose: the socket address by default, and the address a listed proxy observed itself when the request comes through one. Walking `X-Forwarded-For` from the right stops before any client-supplied element; IPv6 is grouped per `/64` so that one host cannot spread over 2^64 peers (F-035 D-4). Source: [F-035 v1](../features/F-035-oauth-proxy-hardening.md).

## Examples

- **Given** an empty trusted list and socket `127.0.0.1`
  **When** a request carries `X-Forwarded-For: 203.0.113.9`
  **Then** the peer is `127.0.0.1`
- **Given** trusted list `127.0.0.1` and socket `127.0.0.1`
  **When** a request carries `X-Forwarded-For: 198.51.100.1, 203.0.113.9`
  **Then** the peer is `203.0.113.9`
- **Given** trusted list `127.0.0.1` and socket `127.0.0.1`
  **When** a request carries `X-Forwarded-For: junk`
  **Then** the peer is `127.0.0.1`
- **Given** trusted list `127.0.0.0/8` and socket `127.0.0.1`
  **When** `X-Forwarded-For` holds `198.51.100.1` followed by 31 elements `127.0.0.3`, then by 32
  **Then** the peer is `198.51.100.1`, then `127.0.0.3`
- **Given** sockets `2001:db8:1:2::1` and `2001:db8:1:2::5%eth0`
  **When** their peers are derived
  **Then** they are the same peer, and `2001:db8:1:3::1` is another
- **Given** sockets `192.0.2.7` and `::ffff:192.0.2.7`
  **When** their peers are derived
  **Then** they are the same peer

- **Given** trusted list `2001:db8::9/128`
  **When** sockets `2001:0DB8:0:0:0:0:0:9` and `2001:db8::a` send `X-Forwarded-For: 203.0.113.9`
  **Then** only the exact full address trusts the header; its neighbour uses its own `/64` peer
- **Given** trusted socket `127.0.0.1`
  **When** XFF contains `2001:DB8::9`, expanded `2001:0DB8:0:0:0:0:0:9`, or `fe80::1%eth0`
  **Then** the first two yield the same IPv6 peer; the zone is invalid and the peer is the socket
- **Given** trusted list `127.0.0.1,203.0.113.0/24` and socket `::ffff:127.0.0.1`
  **When** XFF is `198.51.100.1, ::ffff:cb00:7109`
  **Then** the mapped hop is skipped as trusted and the peer is `198.51.100.1`
- **Given** trusted list `2001:db8::/33`, then list `10.128.0.0/9`
  **When** boundary sockets send XFF `203.0.113.9`
  **Then** `2001:db8:7fff::1` and `10.128.0.1` trust it; `2001:db8:8000::1` and `10.127.255.255` ignore it
- **Given** trusted list `::/8` and socket `::ffff:192.0.2.7`
  **When** XFF is `203.0.113.9`
  **Then** the header is ignored and the peer is IPv4 `192.0.2.7`
