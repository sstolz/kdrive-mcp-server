# BR-038 — Empty-deny optimization

## Rule

An empty deny list causes no descendant traversal, while all identity, membership, evidence and operation-level checks remain required.

The normalized evidence, matching, effect and paging details in
[F-003 v1](../features/F-003-tree-access-policy.md) remain normative.

## Rationale

Avoid a traversal that cannot add deny information while retaining all other checks.

## Examples

These are synthetic injected cases, not provider observations.

- **Given** write mode and empty denies, **When** renaming permitted directory 11, **Then** authorization succeeds without children requests.
- **Given** read mode and empty denies, **When** trashing permitted directory 11, **Then** authorization fails without children requests.

Both examples map to the test or parameter rows named below.
