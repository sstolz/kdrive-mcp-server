## Rule

Except the authorization URL, every provider-controlled value written to the report or the terminal is cut to 200 characters, stripped of control characters and written in a Markdown code span with backticks replaced; an OAuth `error` code is written only when it matches `^[A-Za-z0-9_.-]{1,64}$`, else as `invalid`; `error_description`, `error_uri` and response bodies are never written.

## Rationale

A hostile provider must not inject Markdown, terminal escapes or arbitrary text into the evidence. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-18.

## Examples

- **Given** an `error` of `access_denied`.
  **When** the report is written.
  **Then** it shows `access_denied`.
- **Given** an `error` of `bad code!`.
  **When** the report is written.
  **Then** it shows `invalid`.
- **Given** an `issuer` with a backtick, a newline, `\x1b31m` and 500 characters.
  **When** the report is written.
  **Then** it holds one code span of at most 200 characters without control characters.
