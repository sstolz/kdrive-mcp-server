# BR-326 — Container health probe

## Rule

`node /app/dist/healthcheck.js` (source `src/healthcheck.ts`) imports only `node:http`, reads only the environment variable `MCP_HTTP_PORT`, reads no file and opens no other connection; it sends the request through a dedicated `http.Agent` with no proxy, so proxy variables (`NODE_USE_ENV_PROXY`, `HTTP_PROXY`, `NO_PROXY`) never redirect it. The port is 3000 when `MCP_HTTP_PORT` is unset; otherwise it is parsed exactly as the server's own `integer` parser (`src/config-schema.ts`): the value matches `^\d+$` and its number is a safe integer from 1 to 65535 (so `03000` is port 3000), else the probe fails with code `port` without connecting. It sends one `GET /healthz` to `127.0.0.1:<port>` with `Host: 127.0.0.1:<port>` (the parsed number), no credential and no cookie, follows no redirect, and reads at most 1,024 body bytes within a 5,000 ms deadline measured from the start of the request. It exits 0 with no output when the status is 200 and the body is exactly `{"status":"ok"}`, or when the status is 429 and the body is exactly `{"error":"rate_limited"}`. Otherwise it writes exactly one line `healthcheck failed: <code>` to stderr and exits 1, with `<code>`: `port` for an invalid port; `connection` when the connection fails, is reset, closes before the complete response, or the response cannot be parsed as HTTP; `timeout` when the deadline passes before the status line or before the end of the body; `status` for any status other than 200 and 429 (3xx included); `body` for a 200 or 429 whose body differs from the expected one or exceeds 1,024 bytes.

## Rationale

A compiled, unit-tested probe needs no shell, `curl` or `wget` in the image, follows the server's own port parsing, and treats the handler's own 429 as alive so an anonymous flood cannot mark the container unhealthy (D-5, D-6, D-8). Source: [F-021 v1](../features/F-021-container-health-check.md).

## Examples

- **Given** a loopback server answering 200 `{"status":"ok"}` on the port of `MCP_HTTP_PORT`
  **When** the probe runs
  **Then** it exits 0 with no output
- **Given** `MCP_HTTP_PORT=65536`
  **When** the probe runs
  **Then** stderr is `healthcheck failed: port` and it exits 1 without connecting
- **Given** nothing listening on the port
  **When** the probe runs
  **Then** stderr is `healthcheck failed: connection` and it exits 1
- **Given** a server that answers 301 with a `Location`
  **When** the probe runs
  **Then** stderr is `healthcheck failed: status` and no second request is sent
