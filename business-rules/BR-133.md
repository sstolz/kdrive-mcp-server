## Rule

The upstream ID token is accepted only when it is a compact JWS without `crit`, whose `alg` is in the F-008 BR-098 list, whose signature verifies against a usable key (BR-107) of the upstream JWKS whose `kid` equals the token's `kid` when both carry one, whose `alg` equals the token's `alg` when the key carries one, and whose key type and curve match the `alg` (RSA for `RS*`/`PS*`, P-256 for `ES256`, P-384 for `ES384`, `OKP` Ed25519 for `EdDSA`/`Ed25519`); whose `iss` equals the upstream issuer exactly; whose `aud` equals the upstream client ID or is an array containing it; whose `azp`, when present (and necessarily when `aud` is an array of more than one member), equals the upstream client ID; whose `nonce` equals the flow's nonce; whose `exp` is a number later than now; whose `iat` is a number; whose `nbf`, when present, is not later than now; and whose `sub` is a nonempty string of at most 255 bytes. No clock tolerance is applied. The JWKS is cached for at most 3,600 seconds; when the token carries a `kid` that no cached usable key matches, it is refetched at most once per 60 seconds; a token without `kid` triggers no refetch. A rejected ID token produces a client redirect with `error=server_error`. The upstream access token, refresh token and ID token are discarded after this check and never stored, returned or logged.

## Rationale

The upstream ID token is the only identity evidence; a weak check would let anyone mint proxy tokens. Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-14.
