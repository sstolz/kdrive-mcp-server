# BR-428 — Published tool purpose and continuation descriptions

## Rule

Every registered MCP tool publishes the exact tool description composed from the catalog in F-042 v1, including its purpose, result form, continuation guidance where applicable and the preserved mandatory notices.

Source: [F-042 v1](../features/F-042-mcp-tool-descriptions.md), frozen v1;
implementation and actual-main acceptance remain pending.

## Rationale

AI clients need enough trusted server guidance to select a tool and continue a bounded result without guessing. Existing unofficial, untrusted-content, mutation, upload and admission cautions remain intact. The untrusted-data notice immediately follows the purpose text, before result/continuation guidance, to reduce its exposure to client truncation.

## Examples

- **Given** read mode
  **When** the client lists tools
  **Then** exactly ten tools have their exact catalog descriptions and no mutation is advertised. Maps to `TestBR428_AC01_all_registered_tool_descriptions`.
- **Given** write or share mode
  **When** the client lists tools
  **Then** all sixteen have their exact descriptions, including the unchanged mutation cautions. Maps to `TestBR428_AC01_all_registered_tool_descriptions` and `TestBR428_AC03_existing_notices_and_sentences_preserved`.
- **Given** any published tool description
  **When** the mandatory notice N is located
  **Then** it follows P immediately and its exclusive UTF-8 byte end offset equals the byte length of the independent catalog literal `<name>. P N`; paged tools use P N C and mutations P N R U. Maps to `TestBR428_AC03_existing_notices_and_sentences_preserved`.
- **Given** invalid mutation arguments or invalid upload encoding when invokeMutation is called directly
  **When** the controller refuses before the gate
  **Then** MCP text contains bare INVALID_ARGUMENTS, not a JSON operation result, and the gate is not called; a read-mode controller refusal similarly returns bare ACCESS_DENIED. Maps to `TestBR428_AC03_mutation_result_fields_match_guidance`.
- **Given** a mutation gate admission refusal
  **When** its result is compared with the published description
  **Then** the result has result, code and attempts 0 without op; R promises result and attempts and makes op, code, status, value, audit and message applicable fields, with no continuation cursor. Maps to `TestBR428_AC03_mutation_result_fields_match_guidance`.
- **Given** an uncertain mutation whose outcome audit append fails
  **When** its result is compared with the published description
  **Then** the result includes op, audit outcome_unrecorded and message, as allowed by R, with no continuation cursor. Maps to the same test.
- **Given** a filtered empty page with has_more true
  **When** the client follows the description
  **Then** next_cursor resumes in the same session; the empty page is not mistaken for completion. Maps to `TestBR428_AC04_guidance_matches_continuation_results`.
- **Given** the terminal page or terminal text/byte chunk
  **When** the result is published
  **Then** has_more is false and no next cursor/offset is present. Maps to `TestBR428_AC04_guidance_matches_continuation_results`.
