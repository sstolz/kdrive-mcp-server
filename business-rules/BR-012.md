# BR-012 — Fresh bound coverage

## Rule

v2 (F-011, accepted on main `bc09d56`; v1 below is kept for history):

Container Vitest coverage is unchanged from v1, and Sonar regenerates coverage
in its exact analysed snapshot: the committed trusted `main` commit for
`make sonar`, or the pull-request merge commit for `make sonar-pr`, where the
snapshot's non-generated content is proven equal to the pristine
`git archive "$GITHUB_SHA"` by the BR-150 comparison (in CI) rather than by
`.git` state. Missing, stale, failed or mismatched ("mismatched" means
provenance between the manifest and the inputs, not tamper evidence: coverage
data is produced by the tests themselves) reports are rejected before upload.
(v1: committed-main snapshot only.)

v1 (accepted):

container Vitest uses matching pinned V8 coverage, includes every
`src/**/*.ts`, writes nonempty relative-path LCOV and machine-readable source,
test, config and lockfile digests. Failing tests yield no reusable success marker.
Sonar regenerates coverage in its exact committed-main snapshot and rejects
missing, stale, failed or mismatched reports before upload.

## Rationale

a report only establishes coverage for the inputs actually tested.

## Examples

These concrete scenarios illustrate the unchanged rule and its boundaries; they are verification targets, not new test execution results or a replacement for the full contract.

| Example | Given                                                                                                          | When                                                                   | Then                                                                                                      |
| ------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| E-01    | **Given** a synthetic project containing executed `src/example.ts` and unexecuted `src/unexecuted.ts`.         | **When** V8 coverage runs.                                             | **Then** LCOV includes the unexecuted source with a zero-hit line.                                        |
| E-02    | **Given** successful coverage for fixture run `run-one`.                                                       | **When** coverage verification checks `run-one`, then `different-run`. | **Then** the matching run verifies, while the different run rejects; LCOV uses relative `src/example.ts`. |
| E-03    | **Given** successful `run-one` coverage, followed by a change to `src/example.ts`.                             | **When** the verifier rechecks `run-one`.                              | **Then** verification rejects the changed input digest.                                                   |
| E-04    | **Given** successful `run-one` coverage, followed by a change to `tests/example.test.ts`.                      | **When** the verifier rechecks `run-one`.                              | **Then** verification rejects the changed input digest.                                                   |
| E-05    | **Given** successful `run-one` coverage, followed by a change to `package-lock.json`.                          | **When** the verifier rechecks `run-one`.                              | **Then** verification rejects the changed input digest.                                                   |
| E-06    | **Given** successful `run-one` followed by test runner exit 1 for `run-two`.                                   | **When** coverage creation fails for the second run.                   | **Then** neither the old nor new run has reusable success metadata.                                       |
| E-07    | **Given** a synthetic runner exits 0 but emits LCOV consisting of empty text.                                  | **When** coverage creation validates that report.                      | **Then** it rejects the unusable report despite test exit 0.                                              |
| E-08    | **Given** a synthetic runner exits 0 but emits LCOV consisting of `SF:/outside/source.ts` followed by LF.      | **When** coverage creation validates that report.                      | **Then** it rejects the unusable report despite test exit 0.                                              |
| E-09    | **Given** a synthetic runner exits 0 but emits LCOV consisting of `TN:` followed by LF.                        | **When** coverage creation validates that report.                      | **Then** it rejects the unusable report despite test exit 0.                                              |
| E-10    | **Given** successful coverage whose LCOV is changed to zero-hit output or whose metadata is changed to `null`. | **When** coverage verification checks the fixture after each mutation. | **Then** both corrupted evidence variants reject.                                                         |
