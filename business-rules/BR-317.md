# BR-317 — Jimp runs on the root Zod

## Rule

Pending supersession (F-027 v2, #12): BR-390 supersedes this rule; on the acceptance of F-027 its status becomes `superseded by BR-390`. Until then v1 below stays the accepted rule on `main`. On the F-027 branch its tests are removed except the 600 × 400 route test, kept as `TestBR390_codec_calls image route resizes a 600 x 400 PNG to 512 x 341`.

With the lockfile of BR-316, `@jimp/types` and `@jimp/plugin-resize` resolve `zod` to the same module as the root package (`require.resolve("zod")` from each package directory equals the root resolution). Through the executed image route, a 600 × 400 PNG is extracted and resized to 512 × 341, as on the base; a direct `image.resize` with `w: -1` throws an error that is an instance of the root `zod` `ZodError`, and `JimpClassSchema.safeParse` (exported by `@jimp/types`, not called by `@jimp/core` at run time) refuses a bitmap whose `data` is neither a `Buffer` nor a `Uint8Array`.

## Rationale

Jimp declares `zod ^3.23.8`; the override is safe only while Jimp's runtime schemas behave the same on Zod 4, so an upgrade that relies on a Zod 3-only API fails these tests (D-1). Source: [F-020 v1](../features/F-020-dependency-audit.md).

## Examples

- **Given** the installed dependencies
  **When** `zod` is resolved from `@jimp/types` and `@jimp/plugin-resize`
  **Then** each equals the root resolution
- **Given** a 600 × 400 PNG
  **When** it goes through `kdrive_read` with `format: image`
  **Then** the result is a 512 × 341 PNG
- **Given** a 2 × 2 Jimp image
  **When** `image.resize({ w: -1 })` runs
  **Then** it throws an instance of the root `ZodError`
- **Given** `{ bitmap: { data: "x", width: 1, height: 1 } }`
  **When** `JimpClassSchema.safeParse` runs
  **Then** `success` is false
