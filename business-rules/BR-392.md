# BR-392 — Install check of the packed tarball

## Rule

`make install-check` (prerequisites `_require-setup` and `build`) runs exactly `$(COMPOSE) run --rm -T dev node scripts/install-check.ts` and exits with its status; `make help` lists it; `make check` does not run it (it needs the npm registry). `scripts/install-check.ts` uses Node built-ins only. It copies `dist/`, `LICENSE`, `NOTICE`, `README.md` and `package.json` into a new temporary directory, runs `npm pack --json --ignore-scripts --prefer-online` there (timeout 120 s) and requires exactly one tarball, then runs `npm install --global --prefix <new empty directory> <tarball> --ignore-scripts --no-audit --no-fund --prefer-online` (timeout 600 s). Each `npm` command runs through `execFileSync` with that `timeout`; a timeout or a non-zero exit is an `npm` failure. It then calls the exported collector `collectInstalled(prefix)`, which walks every directory named `node_modules` under the prefix at every depth: each entry is read with `lstat`; an entry whose name starts with `.` is skipped; an entry `@<scope>` that is a directory is read one level further for its `<name>` entries; a `<name>` or `@<scope>/<name>` directory with a `package.json` is one installed package `{ name, version, path }` (name and version from that `package.json`, `version` `null` when absent or not a string, `path` relative to the prefix), and its own `node_modules`, if any, is walked the same way; a symbolic link is never followed and is collected as `{ name, version: null, path, symlink: true }`, `name` being its directory-entry name (with its scope). It prints one line per collected `zod` with its version and path. It exits 0 only when at least one `zod` is collected, every collected `zod` has a version `>=4.6.6` (a prerelease of 4.6.6, `null` or an unparseable version counts as below), no collected name starts with `@jimp/`, and no entry is a symbolic link; otherwise, and when any `npm` command fails, it prints each finding and exits 1. It removes its temporary directories in every case. The verdict is computed by an exported pure function over the collected list.

## Rationale

npm `overrides` and the lockfile do not reach an install of the packed tarball; only a real install from the registry shows the tree users get, so the CI `audit` job checks it (D-4, ADR-010). Source: [F-027 v2](../features/F-027-direct-image-codecs.md).

## Examples

- **Given** collected lists `[zod 4.6.7]` and `[zod 4.6.6]`
  **When** the verdict function runs
  **Then** both pass
- **Given** `[zod 4.6.7, zod 3.25.76 under @jimp/types]`
  **When** the verdict function runs
  **Then** it fails naming `zod` 3.25.76 and its path
- **Given** a temporary tree with a scoped package four `node_modules` levels deep and a symbolic link `e` to a directory outside the tree
  **When** `collectInstalled` runs
  **Then** it returns every package with its relative path and `e` as a symlink entry, and never the `zod` behind the link
- **Given** the Jimp tree before the codec switch
  **When** `make install-check` runs against the registry
  **Then** it exits 1 listing `zod` 3.25.76 under `@jimp/types` and `@jimp/plugin-resize` and the `@jimp/*` packages
