# BR-375 — Release Make targets

## Rule

`release-check`, `release-npm` and `release-verify` depend only on the container-config guard and run exactly `$(COMPOSE) run --rm -T` with every variable passed by name (`-e NAME`), then `dev node scripts/release.ts <check|npm|verify>`, with exactly the variable lists of the source specification (`GITHUB_ACTIONS` in all three). After it exits 0, `release-npm`, only when `RELEASE_DRY_RUN` is `true` and `GITHUB_OUTPUT` is set, appends exactly one line `tarball-sha256=<hex>` to `$GITHUB_OUTPUT`. `release-setup` depends only on the guard and runs `$(COMPOSE) build dev` then `$(COMPOSE) run --rm -T dev npm ci --ignore-scripts`. `release-image` runs `/bin/sh scripts/release-image.sh`. None of the five is a prerequisite of another; all are in `.PHONY` and `make help`; `scripts/release.ts` imports only `node:` modules.

## Rationale

The release scripts run in the pinned container with no third-party code and receive only the variables they need. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** the Makefile
  **When** the test reads the three `scripts/release.ts` recipes
  **Then** each `-e` list equals its named constant exactly
- **Given** `scripts/release.ts`
  **When** its imports are read
  **Then** every specifier starts with `node:`
