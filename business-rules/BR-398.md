# BR-398 — Acceptance state directory documentation

## Rule

`docs/oauth-proxy.md`, section "Owner-run acceptance composition", states that `HTTP_ACCEPTANCE_STATE_DIR` is optional, that without it a restart loses every client and login, the directory requirements of BR-397 (absolute, outside the checkout and the secrets directory, owned by the dev container user, mode `0700`, holding nothing but the state file and its journal), that on Linux the host account that owns the directory must have the uid the dev image was built with (`DEV_UID=… make setup`, `docs/development.md`), otherwise the server stops with `OAUTH_STATE_UNAVAILABLE`, that one tunnel and the same `MCP_PUBLIC_URL` must be kept across restarts (a new tunnel URL needs a new `MCP_PUBLIC_URL`, which fails with `OAUTH_STATE_MISMATCH`; then delete `oauth-state.sqlite` and its `-journal` while stopped and start over), that it is a credential store (delete `oauth-state.sqlite` and its `-journal` while stopped to revoke everything), shows the command `HTTP_ACCEPTANCE_SECRETS_DIR=/abs/secrets HTTP_ACCEPTANCE_STATE_DIR=/abs/state make http-acceptance`, and lists the F-028 owner-run steps of F-029; the `make help` line for `http-acceptance` names `HTTP_ACCEPTANCE_STATE_DIR`.

## Rationale

The owner runs the F-028 restart check by hand; the uid, tunnel and revocation rules are not visible from the refusals alone. Source: [F-029 v2](../features/F-029-acceptance-launcher-oauth-state.md).

## Examples

- **Given** `docs/oauth-proxy.md`
  **When** the content test reads the owner-run section
  **Then** it holds every BR-398 statement, the command and the owner-run steps
- **Given** `make help`
  **When** it prints the `http-acceptance` line
  **Then** the line names `HTTP_ACCEPTANCE_STATE_DIR`
