# BR-294 — Exclusive lock for a single instance

## Rule

The store holds an exclusive lock on the file from startup to close (`locking_mode=EXCLUSIVE`, `busy_timeout` 0, then one `BEGIN EXCLUSIVE` transaction at open). A second process opening the same file stops at startup with `OAUTH_STATE_LOCKED` without changing the file. Because the lock is a POSIX `fcntl` lock that any close of a descriptor on the same file in the process releases, the process never opens the path or `<path>-journal` other than through SQLite from the moment SQLite opens the path until the store is closed: the BR-293 identity check and the BR-295 size check use `lstat` only, and the BR-293 creation descriptor and the BR-295 header-read descriptor are closed before SQLite opens the path.

## Rationale

Two processes writing one file would corrupt it and desynchronise revocations. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** a store open in process A
  **When** process B opens the same file
  **Then** B stops with `OAUTH_STATE_LOCKED` and the file is unchanged
- **Given** process A closed its store
  **When** process B opens the file
  **Then** the open succeeds
