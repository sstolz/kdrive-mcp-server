## Rule

An MCP request's credential comes only from the `Authorization` header. An `access_token` query parameter yields 400 HTTP-layer error `invalid_request` with `WWW-Authenticate: Bearer error="invalid_request", resource_metadata="<PRM URL>"`, whatever the header. Otherwise, no `Authorization` value, or one whose scheme is not `Bearer` (case-insensitive), yields 401 HTTP-layer error `unauthorized` with `WWW-Authenticate: Bearer resource_metadata="<PRM URL>"`. A `Bearer` value that does not match `Bearer 1*SP b64token` (RFC 6750 §2.1; this includes a repeated `Authorization` header, since `,` and space are outside `b64token`) yields the 400 above. A token longer than 4,096 bytes yields the 401 of BR-159 without calling the verifier.

## Rationale

The credential comes only from the Authorization header, as RFC 6750 and the MCP authorization rules require. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-06.

## Examples

- **Given** a request without `Authorization`
  **When** it reaches the MCP endpoint
  **Then** 401 `unauthorized` with `Bearer resource_metadata="<PRM URL>"`.
- **Given** `?access_token=x`
  **When** a request reaches the MCP endpoint
  **Then** 400 `invalid_request`.
