## Rule

The validator accepts an access token only when it is a compact JWS with `alg` in `RS256`, `RS384`, `RS512`, `PS256`, `PS384`, `PS512`, `ES256`, `ES384`, `EdDSA`, `Ed25519`, no unknown `crit`, a signature verified by a usable JWKS key, `iss` equal to the issuer, `aud` equal to or containing the audience, a non-empty string `sub` (else `malformed`), `exp` later than now (else `expired`) and any `nbf` not later than now, with no clock tolerance; any other token is rejected with status 401. A non-canonical configured audience is a configuration error.

## Rationale

P-12 reuses the exact validator that qualified the provider, so qualification cannot pass with weaker rules than production. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-08, AC-09.

## Examples

- **Given** a token whose `exp` equals now.
  **When** it is validated.
  **Then** it is rejected with 401 `expired`.
- **Given** a token whose `exp` is one minute after now.
  **When** it is validated.
  **Then** it is accepted.
- **Given** audience `https://mcp.test:443/mcp`.
  **When** a validator is created.
  **Then** creation throws a configuration error.
