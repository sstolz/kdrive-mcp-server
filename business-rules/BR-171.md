## Rule

The acceptance composition `scripts/http-acceptance.ts`, run by `make http-acceptance` in the dev Compose service: (1) serves authenticated proxy mode through `startHttpServer` with the real upstream OIDC port and, as navigation dependencies, a synthetic in-memory drive and resolver, with a fixed synthetic placeholder in place of the kDrive credential and no kDrive call; (2) obtains the upstream client secret and the signing key only through F-002's `oauthUpstreamClientSecretFile` and `oauthSigningKeyFile`, and refuses to start, with a fixed message, when `oauthUpstreamClientSecret` is supplied inline; (3) is started by a Make recipe that publishes its port on the host's `127.0.0.1` only; (4) writes each BR-167 and BR-143 logger event as one JSON line `{"event":<name>, ...fields}` to stderr; (5) is absent from the published package. The CLI is unchanged.

**v2 (#63; accepted on main `7b8b52d`; superseded by v3)** — v1 above holds, and in addition: (6) the Make recipe `http-acceptance` only calls `scripts/http-acceptance-entry.sh` (POSIX `sh`), which, before any Docker command or Make prerequisite (including `build`), refuses with exit status 1 and exactly one fixed stderr line, never containing the selected path or any file content, in this order (first failure wins): the BR-150 Compose guard (`A Compose override or .env file exists in this checkout; analysis refused.`); `secrets` exists at the checkout root as a file, directory or symlink, dangling included (`A secrets path exists in this checkout. Move the acceptance secrets outside the checkout.`); `HTTP_ACCEPTANCE_SECRETS_DIR` unset, empty, not starting with `/`, containing `:` or a newline, or having a `.` or `..` path component (`Set HTTP_ACCEPTANCE_SECRETS_DIR to an absolute directory outside the checkout.`); the directory cannot be listed, or the value without trailing `/` is a symlink or does not resolve to an existing directory (`The acceptance secrets directory is unavailable.`); its physical path equals, lies under or is an ancestor of the checkout's physical path, or contains `:` or a newline (`The acceptance secrets directory is inside the dev checkout.`); `upstream-client-secret` or `signing-key.pem` is missing, a symlink, not a regular file or not readable (`An acceptance secret file is unavailable.`); the directory holds any other entry, hidden ones included (`The acceptance secrets directory holds other entries.`). (7) On success it runs the `build` target, repeats the Compose guard, then exactly one `compose run` of the `dev` service executing `node scripts/http-acceptance.ts` with the v1 arguments plus `--volume <physical path>:/run/secrets:ro`, `OAUTH_UPSTREAM_CLIENT_SECRET_FILE=/run/secrets/upstream-client-secret` and `OAUTH_SIGNING_KEY_FILE=/run/secrets/signing-key.pem`. No tracked file under `Makefile`, `compose.yaml`, `scripts/` or `docs/` references the former in-checkout path, and no other target or Compose service mounts the directory. `docs/oauth-proxy.md` states that the files must be readable by the dev container user (`DEV_UID`) and shows the variable passed per invocation.

**v3 (F-029 v2, #25; accepted on main `3428df5`)** — v2 holds, except clause (7): the one `compose run` carries the v2 arguments and, only when `HTTP_ACCEPTANCE_STATE_DIR` is set, the two BR-397 arguments (`--volume <physical path>:/run/oauth-state` read-write and `-e OAUTH_STATE_FILE=/run/oauth-state/oauth-state.sqlite`); without it the arguments are exactly the v2 ones. The secrets directory stays the only read-only mount and holds only its two files; the state directory is the only other mount; no other Make target or Compose service mounts either directory, and no tracked file under `Makefile`, `compose.yaml`, `scripts/` or `docs/` names a state path inside the checkout.

## Rationale

The owner needs a way to connect a real client before a production kDrive adapter exists, without a production code path that pretends to serve kDrive. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-23. v2: the secrets were inside the dev checkout, which every dev container mounts read-write, so dependency, test, lint, build and Sonar `prep` code could read them (milestone 0.2 global review M-1); they now come from an external directory mounted read-only for the acceptance run only (F-012 D-20), AC-23 v2 clause and AC-25. v3: the F-028 owner-run claude.ai check restarts the server and needs the F-019 state file, which the launcher could neither receive nor keep; an optional private directory outside the checkout is mounted read-write for that run only ([F-029 v2](../features/F-029-acceptance-launcher-oauth-state.md) D-1).

## Examples

- **Given** a valid secrets directory and no `HTTP_ACCEPTANCE_STATE_DIR` (v3)
  **When** `make http-acceptance` runs
  **Then** the `compose run` arguments are exactly the v2 ones.
- **Given** a valid secrets directory and an empty private state directory (v3)
  **When** `make http-acceptance` runs
  **Then** the `compose run` adds `--volume <physical state path>:/run/oauth-state` and `-e OAUTH_STATE_FILE=/run/oauth-state/oauth-state.sqlite`, with the secrets mount unchanged.

- **Given** an inline upstream client secret
  **When** the composition starts
  **Then** it refuses with its fixed message.
- **Given** the `http-acceptance` Make recipe
  **When** its port is published
  **Then** only with a `127.0.0.1:` host prefix.
- **Given** `HTTP_ACCEPTANCE_SECRETS_DIR` unset
  **When** `make http-acceptance` runs
  **Then** it exits 1 with `Set HTTP_ACCEPTANCE_SECRETS_DIR to an absolute directory outside the checkout.` and no Docker command runs.
- **Given** a `secrets` directory in the checkout and a valid external directory
  **When** `make http-acceptance` runs
  **Then** it refuses with `A secrets path exists in this checkout. Move the acceptance secrets outside the checkout.`
- **Given** a valid external directory holding only the two regular files
  **When** `make http-acceptance` runs
  **Then** `build` runs, then one `compose run` mounting it at `/run/secrets:ro`.
