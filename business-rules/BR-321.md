# BR-321 — Dependency audit documentation

## Rule

v4 (F-027 v2, #12; accepted on main `75bd9bb`): v3 holds with these changes. `docs/development.md`'s dependency-audit paragraph names the BR-315 `minimatch` override, ADR-010, `make audit`, `make install-check` and the CI `audit` job; its Make target table has a row whose first cell is `` `make install-check` `` and whose description says it installs the packed tarball from the registry and is not part of `make check`; and the file contains neither `Jimp` nor `@jimp/` (case-insensitive). `SECURITY.md` `## Dependency audit` keeps the high/critical gate and the no-allowlist sentences and states: (a) from the first release that includes #12, an install of the packed tarball or of the published package (`npm install -g`) resolves no `zod` below 4.6.6, and the CI `audit` job checks this with `make install-check`; (b) in one sentence, that earlier published versions (`0.6.0-beta.1` and older) still resolve the nested Zod 3 (`zod` 3.25.76, GHSA-mrhx-c7xc-m3w5) on such an install, and that their users upgrade to the first release that includes #12 or use the container image, whose `npm ci` install is not affected. The section may name the former image library (Jimp) only in sentence (b); it contains neither `@jimp/` nor `fixed before 1.0`, and no sentence other than (b) contains `Jimp` or `Zod 3`. `CHANGELOG.md` has a `### Fixed` line citing #12 (the tarball install no longer resolves Zod 3) and an `### Added` line citing #12 (the `make install-check` target and its CI step), both matching `#12\b`, both in the first release section citing #12 in file order or, when no release section cites #12, under `## [Unreleased]` (release section as defined in v3). Only the text before the `## [0.6.0-beta.1]` heading is searched for this selection: that section and older ones cite tickets of the archived repository, whose `#12` is another ticket.

v3 (F-025 v1, #2, accepted on main `e857db3`; the active rule): `docs/development.md` no longer states that the audit is not clean; its dependency-audit paragraph names the BR-315 overrides, ADR-009, `make audit` and the CI `audit` job. `SECURITY.md` has a section `## Dependency audit` stating that CI fails on any high or critical `npm audit` finding, that a new one is fixed before a release, not allowlisted, and that the overrides do not apply to an install of the packed tarball (`npm install -g`), which can resolve Jimp's nested Zod 3 again. `CHANGELOG.md` has a `### Fixed` line for the advisories and an `### Added` line for `make audit` and the CI job, both citing #104, located as follows. A release section is a level-2 section whose heading has the form `## [<version>] - <YYYY-MM-DD>`; a heading without the date is not one. A line cites #104 when it matches `#104\b` (`#1040` does not cite #104). If any release section exists, a release section citing #104 must exist, and the first such section in file order has both lines; otherwise `## [Unreleased]` has both.

v2 (F-024 v1): proposed, withdrawn in F-024 v2, never accepted; the number is not reused.

v1 (F-020 v1, accepted; superseded by v3): `docs/development.md` no longer states that the audit is not clean; its dependency-audit paragraph names the BR-315 overrides, ADR-009, `make audit` and the CI `audit` job. `SECURITY.md` has a section `## Dependency audit` stating that CI fails on any high or critical `npm audit` finding, that a new one is fixed before a release, not allowlisted, and that the overrides do not apply to an install of the packed tarball (`npm install -g`), which can resolve Jimp's nested Zod 3 again. `CHANGELOG.md` Unreleased has a `### Fixed` line for the advisories and an `### Added` line for `make audit` and the CI job, both citing #104.

## Rationale

Operators and contributors must know the audit contract and the residual tarball-install risk (D-1). Source: [F-020 v1](../features/F-020-dependency-audit.md).
