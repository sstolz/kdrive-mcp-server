## Rule

Once `startHttpServer` has bound its listener (with any `ListenPort`), the server keeps one `error` listener until `close()` resolves. An `error` event on the listening server never closes the listener, ends a connection, rejects or resolves anything, or ends the process; the server keeps accepting and answering requests. It emits the event `listener_error` with exactly the fields `code` (the error's `code` property when it is a string matching `^E[A-Z0-9]{1,31}$`, else `other`) and `suppressed` (the number of `error` events not logged since the previous `listener_error`, `0` for the first). At most one `listener_error` is emitted per 60,000 ms of the handler clock: an error less than 60,000 ms after the last emit attempt is only counted. An attempt starts a new 60,000 ms window and resets the suppressed count to `0` whether or not the logger throws; a throwing logger otherwise changes nothing. When the clock reads earlier than the last emit attempt, the elapsed time counts as 60,000 ms or more and the event is emitted. A bind error before the listener is bound still yields `LISTEN_FAILED` (BR-153).

## Rationale

Without a post-bind listener an accept-time error such as `EMFILE` is an unhandled `error` event that ends the process. The owner chose to keep serving (D-3); a once-per-minute, payload-free diagnostic keeps an error storm from flooding the log. Source: [F-053 v1](../features/F-053-http-lifecycle-hardening.md), D-3.

## Examples

- **Given** a started server and a recording logger
  **When** it emits `error` with code `EMFILE` at t=0, then a numeric code, then `emfile`, then `EAGAIN` at t=59,999
  **Then** only `{code:"EMFILE", suppressed:0}` is emitted and a following MCP request is answered.
- **Given** the same server
  **When** an `ENFILE` error arrives at t=60,000
  **Then** `{code:"ENFILE", suppressed:3}` is emitted.
- **Given** the clock then reads 1,000 ms before that emit
  **When** an error with code `emfile` arrives
  **Then** `{code:"other", suppressed:0}` is emitted.
- **Given** a logger whose `event` throws and a custom `ListenPort`
  **When** two errors arrive 1 ms apart
  **Then** nothing throws, the second is counted, and the next emit 60,000 ms after the first attempt carries `suppressed:1`.
