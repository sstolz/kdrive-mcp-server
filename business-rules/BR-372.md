# BR-372 — npm read-back

## Rule

`release-verify` runs the BR-359 validation first (no request on failure), then reads the npm package document, retrying up to 20 times 15 seconds apart until every condition holds: `versions` has `<version>`; `dist-tags.beta` equals `<version>`; `dist-tags.latest` is present, differs from `<version>` and names a version whose `deprecated` is a non-empty string; `versions[<version>].dist.attestations` exists.

## Rationale

A release is complete only when the registry serves the version under `beta`, with provenance, and `latest` still on the placeholder. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** a registry where the version appears on the third attempt with everything holding
  **When** `release-verify` runs
  **Then** it passes
- **Given** attestations missing
  **When** `release-verify` runs
  **Then** it fails after the attempts run out
