# BR-285 — `upload-new` response check

## Rule

The `upload-new` check accepts a `data` file object whose `id` is a positive safe integer, `type` is `file`, `name` equals the requested name, `size` equals the payload byte count and `parent_id` is present and equals the destination ID (absent or different gives `accepted:false`, `uncertain`); the mutator then returns `created` equal to that `id` and `value` `{drive_id, id, size, action:"created"}`.

## Rationale

A success is reported only for the file written at the checked path (D-18-9, R-18-5). Source: [F-018 v1](../features/F-018-upload.md).

## Examples

- **Given** a 200 file object with `parent_id` 40, name and size as sent
  **When** the upload-new run ends
  **Then** `succeeded` with `action` `created`
- **Given** a 200 file object without `parent_id`
  **When** the upload-new run ends
  **Then** `uncertain` without `value`
