# BR-330 — Three ordered summary requests

## Rule

The summary makes at most three requests, in order and each only after the previous one succeeded: `GET api/ce/task?id=<ceTaskId>` (success requires `task.status` = `SUCCESS` and a non-empty `task.analysisId`), `GET api/qualitygates/project_status?analysisId=<analysisId>`, then `GET api/issues/search`.

## Rationale

Ties the conditions to the analysed task, not the latest analysis (D-4). Source: [F-022 v1](../features/F-022-sonar-gate-summary.md).

## Examples

- **Given** a task answering `SUCCESS` with `analysisId` `analysis-1`
  **When** the summary runs
  **Then** it requests `api/ce/task`, then `api/qualitygates/project_status?analysisId=analysis-1`, then `api/issues/search`
- **Given** a task answering `PENDING`
  **When** the summary runs
  **Then** it prints `Quality Gate summary unavailable: task stage failed.` and makes no further request
