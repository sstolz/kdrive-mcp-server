# BR-379 — Published tarball equals the verified tarball

## Rule

`release-verify` requires `RELEASE_TARBALL_SHA256` to be 64 lowercase hex characters, else the check `npm tarball matches verify` fails with `verify digest missing` and no tarball is fetched. Once `versions[<version>]` is present, `versions[<version>].dist.tarball` must have the npm registry endpoint's origin (else `npm tarball url refused`); its bytes are fetched with `GET` and hashed with `node:crypto`. The check passes only when the request returns 200 and the digest equals `RELEASE_TARBALL_SHA256`; another digest fails with `npm tarball differs from verify` and a non-200 status with its code only. The check is part of BR-372's retry loop.

## Rationale

The bytes users download from npm must be the tarball the `verify` job built and the owner approved. Source: [F-024 v2](../features/F-024-gated-publication.md).

- **Given** `dist.tarball` on another origin
  **When** `release-verify` runs
  **Then** it fails with `npm tarball url refused` and fetches nothing from that origin
