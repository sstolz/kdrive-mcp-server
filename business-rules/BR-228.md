## Rule

`.github/workflows/ci.yml` has the top-level `concurrency` exactly `{"group": "ci-${{ github.event_name == 'pull_request' && format('pr-{0}', github.event.pull_request.number) || format('run-{0}', github.run_id) }}", "cancel-in-progress": "${{ github.event_name == 'pull_request' }}"}`, so a new run of a PR cancels its superseded run and `push` or `workflow_dispatch` runs are never cancelled by concurrency. The job-level `concurrency` of `sonar` and `sonar-pr` is unchanged.

## Rationale

A superseded PR run stops consuming the single runner, while `main` keeps a complete run per commit (D-09). Source: [F-015 v1](../features/F-015-self-hosted-runner.md).
