## Rule

A request whose header block holds more than 100 header lines, counted as the name/value pairs Node reports in `rawHeaders` (repeated names counted separately, `Host` included, trailers excluded), is answered with HTTP-layer error 431 `invalid_request` (BR-167 body and headers, plus `Connection: close`), before `handle()` runs and so before the shutdown, target-length, `Host`, authentication, window and body checks, with no body read; a request with exactly 100 header lines is handled as before.

## Rationale

`node:http` otherwise keeps at most `maxHeadersCount` header lines and drops the rest silently, so the router never learns that headers were dropped. A fixed bound answered with the standard status makes the limit explicit. Source: [F-053 v1](../features/F-053-http-lifecycle-hardening.md), D-5.

## Examples

- **Given** a socket request to `/mcp` with exactly 100 header lines
  **When** it arrives
  **Then** it is handled as before.
- **Given** a socket request to `/mcp` with 101 header lines and a valid token
  **When** it arrives
  **Then** it gets 431 `{"error":"invalid_request"}` with `Connection: close`, no authentication, window count or body read occurs, and one `request_refused` (`route` `mcp`, `status` 431) is emitted.
- **Given** a request with 101 header lines to an unknown path during shutdown
  **When** it arrives
  **Then** it gets the same 431 with `route` `unknown`, not the shutdown 503.
