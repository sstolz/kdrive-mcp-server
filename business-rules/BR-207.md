## Rule

`inspectDrive` returns `{id, role}` with the provider role of that drive from one `/2/drive/init?with=drives` request, or role `"absent"` when the drive is not listed. `resolveDirectory` returns `{driveId,id,type}` with the item's own `type` from fresh metadata for an ID selector, and for a path selector walks from root `1` through complete children listings (BR-201) matching each component by exact name and returns the unique final match with its own `type`. It rejects for a missing ID, a non-directory intermediate component, zero or several matches for a component, more than 64 components, more than 1,024 requests or more than 120,000 ms in one preflight. The resulting F-002 codes are those of AC-16 (`src/config.ts` maps any rejection to `PREFLIGHT_FAILED`, and a resolved non-directory to `ROOT_NOT_RESOLVED`).

## Rationale

The server must start only on admin drives and resolvable directory roots, within fixed request and time bounds. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).
