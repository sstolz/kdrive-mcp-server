# BR-359 — Release input validation first

## Rule

`RELEASE_VERSION` must match the SemVer 2.0.0 reference expression (else `version is not a SemVer version`) and be exactly `<major>.<minor>.<patch>-beta.<n>` without leading zeros or build metadata (a stable version fails with `stable releases are out of scope (F-024 v1)`, anything else with `unsupported pre-release`); `RELEASE_SHA` must be 40 lowercase hex characters (else `sha is not a full commit id`); `RELEASE_DRY_RUN` must be `true` or `false` (else `dry_run is not a boolean`); for `release-check`, `RELEASE_PHASE` must be `verify`, `image` or `npm` (else `phase is not a release phase`). On any failure only the input lines and the summary print, no Git command, child process or request runs, and the exit is 1. Every `scripts/release.ts` mode and `scripts/release-image.sh` run this validation before any interpolation, child process (including `npm --version`), `docker` call or request.

## Rationale

Untrusted dispatch inputs are validated before they can reach a path, a ref, a URL or a command, and only beta pre-releases are in scope. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** `RELEASE_VERSION=0.6.0`
  **When** `release-check` runs
  **Then** it prints `stable releases are out of scope (F-024 v1)`, the doubles record no request and the exit is 1
- **Given** `RELEASE_VERSION=0.6.0-beta.1` and a 40-hex lowercase sha
  **When** `release-check` runs
  **Then** input validation passes
