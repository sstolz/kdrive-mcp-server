## Rule

In HTTP mode the CLI composes `startHttpServer` with the resolved configuration, the production adapter, `createFetchUpstream` in proxy mode, the production clock and random ports, and a logger writing one JSON event per stderr line; SIGTERM or SIGINT runs the F-012 BR-169 `close()` and exits 0.

## Rationale

The HTTP runtime must compose the accepted F-012 server with the production adapter and close cleanly on signals. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** HTTP insecure-loopback configuration and the injected transport
  **When** an SDK client calls `kdrive_info`
  **Then** the call succeeds and every stderr line is one JSON event.
- **Given** the running server
  **When** the injected signal source emits SIGTERM
  **Then** the server closes and exit is called with 0.
