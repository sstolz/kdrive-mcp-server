# BR-386 — Close settles every waiting call

## Rule

When the controller closes, every waiting call leaves the queue at once and returns `ACCESS_DENIED`, with zero kDrive requests and zero audit records, without waiting for the running invocation to settle; no call takes the slot after close, and all wait timers and abort listeners are removed.

## Rationale

A closed session must not start new work or leave pending promises and timers behind (BR-070, BR-089). Source: [F-026 v1](../features/F-026-bounded-invocation-queue.md).

## Examples

- **Given** a running read whose port never answers, a waiting read and a waiting `mutate`
  **When** the controller closes
  **Then** both waiting calls return `ACCESS_DENIED` before the running read settles, with zero requests and zero records, and no wait timer remains
