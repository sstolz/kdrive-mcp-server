## Rule

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11): v1 holds for every route except the BR-324 loopback allowance on `/healthz`.

Every request is checked for its `Host` value first after BR-169's request-target length check, compared case-insensitively. It passes when it equals the WHATWG URL `host` of `P` (default port omitted) or, only when the WHATWG `port` of `P` is empty, `<hostname of P>:<default port of P's scheme>`; in insecure mode the same forms with hostname `localhost` also pass. When `P` has an explicit port, the default-port form does not pass. An absent `Host`, an empty one or any other value (including a repeated `Host`) yields HTTP-layer error 403 `invalid_host` before any routing, authentication or body read.

## Rationale

Host validation blocks DNS-rebinding requests before any routing, authentication or body read. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-05.

## Examples

- **Given** public URL `https://mcp.test/mcp`
  **When** a request carries `Host: mcp.test:443`
  **Then** it is accepted.
- **Given** the same server
  **When** a request carries `Host: mcp.test:8443`
  **Then** 403 `invalid_host`.
