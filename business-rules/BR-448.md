# BR-448 — Process stream failure classification

## Rule

The process stderr owner contains EPIPE events without changing failure status; every other stderr error event latches process failure, including empty flush writes. Stdout events are contained but never latch. Only a stdio protocol-frame write callback reporting an error latches the registered owner of that output identity, including after transport close. Empty stdout flushes and HTTP stdout never latch. Callback errors and synchronous flush throws count only as flush completion. No error payload is logged or retained. Dedicated exit reads these latches after shutdown obligations and again until primitive exit; owned sessions ignore them.

## Rationale

Containment must preserve mutation drain and accurate dedicated-process failure status.

## Examples

- **Given** stderr EPIPE and a successful shutdown
  **When** dedicated exit flushes
  **Then** exit remains 0. Maps to `TestBR254_v3_TestBR448_AC08_failure_survives_exit_flush`.
- **Given** a late protocol-frame callback failure during committed drain
  **When** the outcome and sink close finish
  **Then** dedicated exit selects 1. Maps to `TestBR254_v3_TestBR447_TestBR448_AC09_stdout_failure_during_drain`.
- **Given** a non-EPIPE stderr event during flush
  **When** the primitive exit runs
  **Then** status is 1. Maps to `TestBR254_v3_TestBR448_AC08_failure_survives_exit_flush`.
