# BR-370 — Multi-platform image build and gated push

## Rule

### v2 — accepted (active)

Accepted on main `6a508ab` (#89 comments `89-acceptance-1-claude` and `89-acceptance-2-owner`).

The v1 validation-first, pinned BuildKit, runtime target,
two-platform build, cache and build-argument restrictions remain unchanged.
A dry run builds without login, push, load, output or tags. A real run
logs in with `GITHUB_TOKEN` through stdin and builds with `--push`, the
existing source, version and revision labels, and exactly the references
selected by BR-368 v2. Stable uses two `--tag` arguments on one build;
beta uses one. The real build writes a buildx `--metadata-file`.
For stable only, parse the metadata as JSON and validate the exact
top-level `containerimage.digest` value as `sha256:<64 lowercase hex>`.
Do not use a line-based parser. Refuse newline-bearing values and decoy
`digest` keys instead of the required value. After validation, print exactly
once to stdout `release-image: image digest sha256:<hex>` and expose it as
the `publish-image` job output `image_digest`.
Pass that output (empty for beta) as `RELEASE_IMAGE_DIGEST` only via
`publish-npm`'s `make release-check` and `read-back`'s `make release-verify`; add `publish-image` to read-back dependencies. The image
recipe writes `image_digest=<digest>` to `GITHUB_OUTPUT` after validation.
The workflow exposes `steps.release-image.outputs.image_digest` as
`needs.publish-image.outputs.image_digest`. Beta behavior stays unchanged. Reject a missing
or malformed digest before image requests. Dry builds produce no digest
requirement. Logout still runs on exit, including build failure.

### v1 — accepted (superseded by v2)

`scripts/release-image.sh` (host Docker) runs the BR-359 validation first and exits 1 without calling `docker` when an input fails. It builds target `runtime` of `Dockerfile` for `linux/amd64,linux/arm64` with a `docker-container` Buildx builder whose BuildKit image is pinned by digest, with no `--build-arg`, secret mount, `--cache-from` or `--cache-to`. With `RELEASE_DRY_RUN=true` the build has no `--push`, `--load`, `--output` or `--tag` and no login runs. With `RELEASE_DRY_RUN=false` it logs in to `ghcr.io` with `GITHUB_TOKEN` through `--password-stdin`, builds with `--push`, exactly one `--tag ghcr.io/sstolz/kdrive-mcp-server:<version>` and the labels `org.opencontainers.image.source`, `.version` and `.revision`, and logs out on exit whatever the outcome.

## Rationale

The release image is built cleanly for both platforms and pushed only in the approved job, without a token on the command line or a shared cache. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** dry run
  **When** `release-image` runs
  **Then** one `buildx build` has both platforms and no `--push`, `--tag` or `login`
- **Given** a real run whose build fails
  **When** `release-image` runs
  **Then** `logout ghcr.io` still runs and the exit is non-zero
