# BR-403 — Error page layout

## Rule

An error page has the title and `<h1>` `Authorization error`, then the unchanged `ERROR_TEXT` sentence of its kind in its own `<p>`, then the fixed paragraph `This request was not completed. If your application is not connected, return to it and start the connection again.`; it contains no request value (BR-143) and keeps its status (400 or 503).

**v2 (F-031 v1, #31; accepted on main `901f7af`)** — v1 holds in the page language: title, `<h1>`, the error sentence of the kind and the fixed paragraph are the catalogue texts of the page language (BR-407); no request value, status unchanged, no switcher.

## Rationale

An error page must say what to do next without echoing any request value (BR-143). Source: [F-030 v1](../features/F-030-oauth-proxy-page-design.md).

## Examples

- **Given** an authorize request with `client_id` `<x>`
  **When** the handler answers
  **Then** a 400 page with `The authorization request is invalid.` and the fixed paragraph, without `<x>`, `&lt;x&gt;` or the `redirect_uri`
- **Given** a full consent store
  **When** authorize answers
  **Then** a 503 page with the `busy` sentence and the fixed paragraph
- **Given** a consent POST to `/oauth/consent?lang=fr` with an unknown identifier (v2)
  **When** the handler answers
  **Then** a 400 page titled `Erreur d'autorisation` with the French `consent` sentence and the French fixed paragraph, without a switcher
