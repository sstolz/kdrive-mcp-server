## Rule

`scripts/sonar-entry.sh` (targets `sonar`, `sonar-pr`, `quality`) refuses, before any Docker command or Make prerequisite, a checkout in which `secrets` exists at the root as a file, a directory or a symlink (dangling included), with exit status 1 and its existing fixed message `A supported credential or host path exists in this checkout. Use an isolated clean checkout.` BR-014 v2 and BR-150 are otherwise unchanged.

## Rationale

The Sonar `prep` snapshot's clean-tree check ignores git-ignored paths, so an old in-checkout `secrets/` directory could reach analysis-side code. Refusing the reserved path keeps the former acceptance secrets out of every local analysis run (F-012 D-20). Source: [F-012 v2](../features/F-012-authenticated-http.md), AC-26.

## Examples

- **Given** a `secrets` directory at the checkout root and a valid external `SONAR_TOKEN_FILE`
  **When** `make sonar` runs
  **Then** it exits non-zero with `A supported credential or host path exists in this checkout. Use an isolated clean checkout.` and no Docker command runs.
- **Given** a dangling `secrets` symlink at the checkout root
  **When** `make quality` runs
  **Then** it refuses with the same message before `check`.
- **Given** no `secrets` path at the checkout root and valid selections
  **When** `make sonar` runs
  **Then** the BR-014 v2 and BR-150 steps run unchanged.
