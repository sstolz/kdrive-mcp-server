# BR-415 — Canonical projection

## Rule

The canonical document holds exactly: a Catalog with `Type` and `Pages`; every Pages node with `Type`, `Kids`, `Count` and `Parent` except at the root; every page with `Type`, `Parent`, its `MediaBox` (its own, or the nearest inherited one) and `Resources` and `Contents`; a trailer with `Size` and `Root`. A selected page's `Resources` holds only `Font`, with the fonts BR-417 admits under canonical names `/K1`, `/K2`, … numbered in the order of first selection in the invocation (one name per indirect font object, or per direct font dictionary at its place, whatever resource name or Form selected it), and its `Contents` is the one stream BR-416 builds, with no filter. A selected page with no `/Contents` gets an empty content stream. A page that is not selected gets empty `Resources` and an empty content stream, and its content and resources are not read. Every other key, object and stream of the source, XObjects included, is left out. The page tree keeps its source order and count, so `total_pages` is unchanged.

## Rationale

Generators add keys and objects that text extraction does not read (F-034 S03, S14–S17); leaving them out admits those files and keeps actions, JavaScript, annotations, attachments and XObjects away from PDF.js. Canonical font names make one font object one resource whatever name or Form selected it (F-034 S22). Reading only the selected pages reads less untrusted data. Source: [F-034 v1](../features/F-034-pdf-extraction-profile.md).

## Examples

- **Given** a three-page file with `/OpenAction` JavaScript and a Type3 font on page 3
  **When** pages `[1, 2]` are read
  **Then** their text with `total_pages` 3, and the canonical bytes hold no `/OpenAction`
- **Given** the same file
  **When** page `[3]` is read
  **Then** `UNSUPPORTED_FORMAT`
