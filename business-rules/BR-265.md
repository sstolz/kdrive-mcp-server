# BR-265 — Missing or incomplete trash evidence

## Rule

`inspect(target, "original-trash")` returns `{status:"missing"}` for a trash-metadata 404 `object_not_found`, and `{status:"incomplete"}` without the second `GET` when the trash `status` is not exactly `trashed` (`trash_inherited` included), the metadata has a `drive_id` member different from the requested drive, or it lacks a valid ID equal to the target, type, name, positive `parent_id` or canonical `path`; it returns `{status:"incomplete"}` when the former parent is missing, trashed, not a directory, not normalizable, or its joined path differs from the trash `path`.

## Rationale

Anything short of a provable original location fails closed. Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** trash metadata with `status` `trash_inherited`
  **When** `inspect` runs
  **Then** it returns `incomplete` after one GET
- **Given** a former parent renamed since the deletion (joined path differs)
  **When** `inspect` runs
  **Then** it returns `incomplete` after two GETs
