## Rule

Every MCP request, including those carrying a session ID, is verified with the F-010 verifier at the injected clock's current time. A 401 result (F-008 BR-098 v1, BR-099 v1, F-010 BR-141 v1: malformed, algorithm, signature, issuer, audience, expired, not yet valid, ID token) yields 401 HTTP-layer error `invalid_token` with `WWW-Authenticate: Bearer error="invalid_token", resource_metadata="<PRM URL>"`. A 403 `identity` result (BR-100 v2) yields 403 HTTP-layer error `access_denied` without `WWW-Authenticate`. No response distinguishes rejection reasons, and no `error_description` is sent.

## Rationale

Every request is verified, and no response distinguishes the rejection reasons. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-07, AC-08.

## Examples

- **Given** an expired token
  **When** it is sent to the MCP endpoint
  **Then** 401 `invalid_token` with an identical body to any other rejection.
- **Given** a valid token for an identity outside both allowlists
  **When** it is sent
  **Then** 403 `access_denied` without `WWW-Authenticate`.
