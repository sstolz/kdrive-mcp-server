## Rule

`createAccessTokenValidator` accepts an optional `upstreamIssuer` (BR-100 v2). With it, a token whose `upstream_iss` is absent or not equal to it is rejected with 401 `issuer` right after the `iss` check, the subject allowlist is matched against (`upstreamIssuer`, `sub`), and the success identity is (`upstreamIssuer`, `sub`); without it, F-008 behaviour is unchanged. The proxy verifier is that validator created with the proxy issuer, the audience, a JWKS holding only the public key of the configured signing key (with its `kid`), both allowlists and `upstreamIssuer` set to the upstream issuer; it never accepts an upstream token.

## Rationale

One validator keeps one set of algorithm, ID-token and expiry rules for proxy tokens (BR-100 v2). Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-19, AC-23.

## Examples

- **Given** a proxy token
  **When** it is verified at `exp - 1 s`
  **Then** it is accepted with identity (upstream issuer, `sub`).
- **Given** a proxy token without `upstream_iss`
  **When** it is verified
  **Then** 401 `issuer`.
