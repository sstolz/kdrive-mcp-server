# BR-395 — CIMD operator documentation

## Rule

`docs/oauth-proxy.md` gains a section "Client ID Metadata Documents (`OAUTH_ALLOWED_CLIENT_ID_ORIGINS`)" stating: CIMD is off while the list is empty; the entry grammar; that a nonempty list advertises CIMD to every client and that claude.ai, Claude iOS, Claude Desktop, ChatGPT and Codex then use CIMD with no documented fallback to dynamic registration, so the list holds the document origin of every CIMD-capable client in use or stays empty; that an origin is listed only when its vendor controls every path under it (no multi-tenant hosting where third parties can publish files under the origin), because any document under a listed origin is accepted; that one client may use several document URLs under one origin (for example a per-callback document), which is why origins, not URLs, are listed; the origin discovery procedure of Contract details; that a document's redirect URIs are still limited to `OAUTH_ALLOWED_REDIRECT_URIS`, which acts only at authorization: removing a URI from it does not cut off a CIMD client already holding a refresh family; the fetch limits of BR-306, BR-307 and BR-309; that the fetch ignores proxy variables, so CIMD is unusable where egress must go through a proxy, and that `NODE_EXTRA_CA_CERTS` extends the CAs trusted for the fetch; that removing an origin is the only cut-off for its clients, effective at the restart that applies it (refresh tokens refused, families purged), while access tokens already issued to those clients stay valid until they expire (one hour) unless the signing key is replaced; that the state file moves to version 2 while it holds a CIMD family and that an older release then refuses it with `OAUTH_STATE_VERSION` (operator action: remove the origins, start this release once, then downgrade); and the accepted residual risks of D-8. `docs/deployment.md` lists the variable; `.env.example` (or the deployment example that lists the OAuth variables) has it empty; `SECURITY.md` names the SSRF limits; the client matrix notes that the proxy advertises CIMD only with a nonempty list.

## Rationale

A nonempty list switches every CIMD-capable client at once, so the operator needs the discovery procedure, the limits and the downgrade path before enabling it (D-2, D-12). Source: [F-028 v2](../features/F-028-client-id-metadata-documents.md).
