# BR-026 — Explicit guarded credential sources

Source: [F-002 v1](../features/history/F-002-v1.md), BR-026, frozen
2026-11-01 21:18:28 UTC after fresh independent approval.

## Rule

**v2 (F-047 v1, #111, pending acceptance).** The accepted v1 source-selection
and guarded-read contract holds, with this file normalization: selected token,
upstream-secret and signing-key files are read under their raw byte limits
(16,384 bytes for token/upstream-secret, 65,536 for signing-key), their maximal
leading and trailing U+0020/U+0009/U+000D/U+000A sequences are removed, an empty
result gives `CREDENTIAL_INVALID`, the unchanged content checks follow on the
result, and inline environment values are never trimmed.

BR-026 v1 remains accepted and active until v2 acceptance on actual main.
BR-023 v4 raw budgets are unchanged, including discarded padding. Fatal UTF-8
and ASCII-control checks still apply to text secrets; signing bytes stay opaque
locally and retain BR-124 v2 parsing. No other Unicode whitespace, BOM or NUL
is trimmed. Failures expose only the existing code and setting, without
content, paths, lengths or trim counts; no normalization is logged.

### Accepted rule (v1, historical contract)

Load a required nonempty Infomaniak credential from the selected
environment value or explicit file reference. Permit the proxy upstream secret
from the selected environment value or explicit file reference, and its signing
material only by explicit file reference. Reject raw secrets in CLI/YAML,
conflicting selectors and invalid credential data under the file contract below.
Read nothing from unselected credential sources. No secret is generated,
copied to the repository, written to disk or passed as an argument.

The source specification's inventory, bounds, grammars, auth matrix, credential
contract, error mapping and preflight port supply the normative details for
this statement; this record does not redefine those tables.

## Rationale

Read only selected bounded credentials without raw CLI/YAML secrets or discovery.
