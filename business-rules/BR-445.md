## Rule

A tool call, resource read or `mutate` call carried by an HTTP request is _started_ once it holds its controller's slot: the BR-383 `start` step has run, which sets its invocation deadline (BR-384), either at arrival on a free slot or on a slot handed to it. When the BR-166 v2 disconnect signal aborts while such a call has not started (it is waiting under BR-380, or arrives with the signal already aborted), the call leaves the queue at once or does not join it and returns `ACCESS_DENIED` (tool error `isError:true`, resource read protocol error `-32000`), with zero kDrive requests, zero dependency calls and zero audit records (no intent appended); its wait timer and listeners are removed, and the calls behind it keep their order and move up (as BR-385). The disconnect listener is removed in the same BR-383 step in which the call takes the slot, so it is never attached while the call runs. A call that has started is unaffected by the disconnect: it runs until it settles under its existing bounds, a gate run keeps every BR-258 v2 and BR-250 semantics, including a committed write and its audit outcome, and its result is discarded by the adapter. A disconnect emits no new event and no HTTP response is written for it. When the disconnect and a slot release fall in the same synchronous step, the BR-383 order decides: a call that took the slot first is started. This reverses F-026 D-8 for calls that have not started.

## Rationale

A queued call, a write included, from a client that already disconnected would otherwise still run up to 12 s later (F-026 D-8). The owner reversed that accepted residual risk for calls that have not started, and kept started calls running so a committed write keeps its audit outcome. Source: [F-053 v1](../features/F-053-http-lifecycle-hardening.md), D-4.

## Examples

- **Given** a tool call waiting behind a held invocation of the same session
  **When** its client destroys the connection
  **Then** it returns `ACCESS_DENIED` with zero kDrive requests and zero audit records.
- **Given** a `mutate` call waiting behind a held read
  **When** its client disconnects
  **Then** no intent is appended, the mutator never runs, and the next waiter takes the slot in order.
- **Given** a started gate run held before its intent append
  **When** its client disconnects
  **Then** it appends its intent, commits and audits as without a disconnect.
- **Given** a disconnect signal already aborted
  **When** a call arrives on a free slot
  **Then** it does not start and returns `ACCESS_DENIED`.
