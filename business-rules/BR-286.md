# BR-286 — `replace` response check

## Rule

The `replace` check accepts a `data` file object whose `id` equals the target ID, `type` is `file`, `name` equals the requested name, `size` equals the payload byte count and `parent_id` is present and equals the destination ID; the mutator then returns `value` `{drive_id, id, size, action:"replaced"}` and no `created`; a 2xx whose `id` differs from the target, or whose `parent_id` is absent or different, gives `accepted:false` (`uncertain`).

## Rationale

`conflict=version` selects the file by folder and name, so a different ID means another file was written (D-18-2, R-18-2). Source: [F-018 v1](../features/F-018-upload.md).

## Examples

- **Given** a 200 file object with `id` 41 for target 41
  **When** the replace run ends
  **Then** `succeeded` with `action` `replaced`
- **Given** a 200 file object with `id` 42 for target 41
  **When** the replace run ends
  **Then** `uncertain`
