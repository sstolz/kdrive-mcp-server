## Rule

Discovery accepts only an issuer that is an absolute `https` URL without query, fragment or userinfo; it fetches `<issuer without trailing slash>/.well-known/openid-configuration` and `<issuer origin>/.well-known/oauth-authorization-server<issuer path without trailing slash>`, keeping any port. A document is usable only when it is a JSON object whose `issuer` equals the configured issuer exactly, and discovery is usable when at least one document is usable.

## Rationale

A provider must be identified by its exact issuer before any capability is trusted; a lookalike or mis-scoped document must not qualify it. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-01, AC-02.

## Examples

- **Given** issuer `https://idp.test:8443/realm/`.
  **When** discovery runs.
  **Then** it requests `https://idp.test:8443/realm/.well-known/openid-configuration` and `https://idp.test:8443/.well-known/oauth-authorization-server/realm`.
- **Given** an OIDC document whose `issuer` is `https://idp.test/` for configured issuer `https://idp.test` and an RFC 8414 response 404.
  **When** discovery runs.
  **Then** no document is usable and discovery is unusable.
- **Given** an OIDC document whose `issuer` equals `https://idp.test` and an RFC 8414 response 404.
  **When** discovery runs.
  **Then** discovery is usable.
- **Given** issuer `https://u@idp.test`.
  **When** the command starts.
  **Then** it is refused before any request.
