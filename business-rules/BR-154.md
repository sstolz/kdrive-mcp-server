## Rule

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11): v1 holds, and the route table also contains `/healthz` (GET) per BR-322; a non-GET method on it yields 405 with `Allow: GET`.

In authenticated mode the routes are exactly: the MCP endpoint at the path of `P` (POST, DELETE); the PRM URL path (GET); each F-010 `metadataPaths` entry (GET); `<path of P>/oauth/register` (POST), `<path of P>/oauth/authorize` (GET), `<path of P>/oauth/consent` (POST), `<path of P>/oauth/callback` (GET) and `<path of P>/oauth/token` (POST). Routes match the target path byte-exactly, without decoding, dot-segment resolution or trailing-slash tolerance; a target path that does not start with `/` (absolute-form, `*`) matches no route. Any other path yields HTTP-layer error 404 `not_found`; another method on a known path yields 405 `method_not_allowed` with `Allow` listing the methods above (a GET on the MCP endpoint therefore yields 405 with `Allow: POST, DELETE`). `HEAD` is not supported.

## Rationale

A fixed, byte-exact route table keeps routing free of normalization differences between the proxy and the server. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-03.

## Examples

- **Given** public URL `https://mcp.test/mcp`
  **When** a GET reaches `/mcp`
  **Then** 405 `method_not_allowed` with `Allow: POST, DELETE`.
- **Given** the same server
  **When** a request targets `/mcp/` or `/%6Dcp`
  **Then** 404 `not_found`.
