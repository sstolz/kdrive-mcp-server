# BR-338 — Summary time limit and preserved exit code

## Rule

The summary runs with its own timer of min(60 s, remaining time before the 900 s analysis deadline − 5 s), is not run under the outer analysis deadline abort path, and the process exit code after a summary always equals the scanner's nonzero exit code, returned by the summary path itself. Any exception inside the summary is caught and prints exactly `Quality Gate summary unavailable: internal error.`; a `fetch` that throws (synchronously or not) is a network error of its stage (BR-332), not an internal error. The timer is computed after the BR-329 metadata check: with unverified metadata only the no-metadata line prints; with verified metadata and a computed timer of 0 or less, the summary prints the time-limit line once, makes no request and returns the scanner code. When the summary timer expires, exactly one terminal line `Quality Gate summary unavailable: time limit reached.` prints; it takes precedence over the stage line of the aborted stage, which is then not printed.

## Rationale

The summary must never change the failure outcome or delay the job past its deadline (T5, D-10). Source: [F-022 v1](../features/F-022-sonar-gate-summary.md).

## Examples

- **Given** a scanner exit 3, a `PENDING` task and a log sink throwing on its first summary line
  **When** `runAnalysis` runs
  **Then** it returns 3 and prints `Quality Gate summary unavailable: internal error.`
- **Given** a scanner exit 2 with 30 s left and a conditions request pending at 25 s
  **When** `runAnalysis` runs
  **Then** it returns 2 and prints exactly one `Quality Gate summary unavailable: time limit reached.`
- **Given** 4 s left and valid task metadata
  **When** the summary runs
  **Then** it prints the time-limit line once and makes no request
