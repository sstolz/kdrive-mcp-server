# BR-322 — Health route

## Rule

The handler has a route `/healthz` (route name `health`) in authenticated and insecure modes. It is added after every route that exists today, so when the MCP endpoint path is exactly `/healthz` the MCP route keeps the path and no health route exists. A request whose path is exactly `/healthz` (any query string) is answered by the first rule that applies, in this order: (1) while the server closes, BR-169's 503 `temporarily_unavailable`; (2) a target over BR-169's 8,192 bytes, 414 `invalid_request`; (3) a `Host` refused by BR-324, 403 `invalid_host`; (4) any method other than `GET`, `HEAD` included, 405 `method_not_allowed` with `Allow: GET`; (5) a `Content-Length` that is not all zeros, or any `Transfer-Encoding`, BR-160's 413 `payload_too_large` with `connection: close`; (6) a full BR-325 window, 429 `rate_limited`; (7) otherwise status 200. A path other than an existing route's (for example `/healthz/` or `/HEALTHZ`) still yields 404 `not_found` after the `Host` check. The handler's `Response` for the 200 has exactly the headers `content-type: application/json`, `cache-control: no-store` and `x-content-type-options: nosniff` and the 15-byte body `{"status":"ok"}`; on the wire, the BR-170 adapter and `node:http` add only `content-length`, `date`, `connection` and `keep-alive`.

## Rationale

Docker, Compose and orchestrators need a liveness signal that works in both modes without credentials; the PRM route is absent in insecure mode and needs the public `Host` (D-1, D-3). Source: [F-021 v1](../features/F-021-container-health-check.md).

## Examples

- **Given** an authenticated handler with public URL `https://mcp.test/mcp`
  **When** `GET /healthz` arrives with the public `Host`
  **Then** 200 with body `{"status":"ok"}` and exactly the three BR-322 headers
- **Given** the same handler
  **When** `HEAD /healthz` arrives
  **Then** 405 `method_not_allowed` with `Allow: GET`
- **Given** the same handler
  **When** `GET /healthz` arrives with `Content-Length: 5`
  **Then** 413 `payload_too_large` with `connection: close`
- **Given** a public URL `https://mcp.test/healthz`
  **When** `GET /healthz` arrives
  **Then** the MCP route answers 405 with `Allow: POST, DELETE`
