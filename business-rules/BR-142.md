## Rule

All proxy state (clients, pending consents, upstream flows, codes, refresh families, discovery and JWKS caches) lives in the memory of one proxy instance; a new instance starts empty, so its token handler answers 401 `invalid_client` to a client registered with a previous instance and its verifier accepts access tokens of a previous instance only when created from the same key. Each store holds at most 1,000 live entries; expired entries are purged before a write. A full client store evicts the client with the oldest last use (registration, authorization or token request) together with its codes and refresh families; a full consent, flow or code store refuses the new entry (consent: 503 HTML error page; flow: client redirect `temporarily_unavailable`; code: client redirect `server_error`); a full family store evicts the family with the oldest creation.

Version 2 (F-019 v1, #103; accepted on main `68209fe`, 2026-11-11): state is in memory only without `oauthStateFile` (BR-292); purge also follows BR-302; a full store's eviction is written to the file in the transaction of the entry that caused it; a latched store (BR-299) answers 503 as stated there.

## Rationale

v1 is single-instance in memory; bounds keep open registration from exhausting memory until P-12 rate limits exist. Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-24, AC-25.

## Examples

- **Given** instance A issued tokens
  **When** instance B starts with the same key
  **Then** B answers 401 `invalid_client` for A's client and accepts A's access token until `exp`.
- **Given** 1,000 live pending consents
  **When** another authorization request arrives
  **Then** 503 HTML until entries expire.
