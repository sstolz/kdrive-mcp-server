## Rule

Each paged collection response exposes only a bounded authorized batch with continuation exactly when the session retains unfinished work.

## Rationale

A successful bounded page must never imply exhaustion while known work remains. Source: [F-006 v1](../features/F-006-filtered-pagination.md).

## Examples

- **Given** five empty nonterminal ordinary pages.
  **When** a collection runs.
  **Then** items are empty and has_more is true with an opaque cursor.
- **Given** the fifth page is terminal on the final scope.
  **When** a collection runs.
  **Then** has_more is false and next_cursor is absent.
