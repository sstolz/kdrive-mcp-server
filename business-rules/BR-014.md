# BR-014 — Official scanner with the existing Project analysis token

## Rule

v2 (F-011, accepted on main `bc09d56`; v1 below is kept for history):

BR-014 v1 holds with these changes: the scanner host comes only from the
validated runtime host (BR-145), never from a tracked file or a constant; the
scanner child receives it as `SONAR_HOST_URL` in its environment allowlist; task
metadata `serverUrl` must equal the configured host without one trailing `/`;
the project key is `kdrive-mcp-server` for `make sonar` and
`kdrive-mcp-server-pr` for `make sonar-pr` (BR-148); and captured output
redacts the host name as well as the token (BR-146). `make sonar` still accepts
only trusted clean exact `main` on `local`, `push` or `workflow_dispatch` and
rejects `pull_request` and `pull_request_target`.

v1 (accepted):

explicitly enabled analysis uses the pinned official scanner alone
for HTTPS authentication, analysis and built-in Quality Gate waiting on the
reviewed existing kdrive server/key. No custom Sonar REST requests, broader
credential, target mutation, project creation or branch/PR flags. Preserve
trusted clean exact-main provenance, immutable read-only source/fresh LCOV,
non-root separate work/cache volumes, 300-second gate wait and 15-minute total
deadline. Scanner receives runtime SONAR_TOKEN only, from one selected environment
or explicitly mounted external file mode. The file remains outside the dev
checkout bind. Both sonar/quality run the POSIX supported-path/mount-safety guard
before any dev/test Make prerequisite: reject an existing/symlinked in-checkout
`.config/qube-token`, internal physical-path selector or final file symlink.
No token copying, discovery, host content reading, dev/test exposure,
arguments, persistence or raw logging. Report exact scanner output after literal
credential redaction and fail on nonzero scanner/gate/network/timeout outcomes.
Validate official report project/server/task fields from a fresh unique path,
bind the invocation to the trusted SHA/run/source/LCOV manifest and pass the
trusted SCM revision. Built-in successful waiting and exit 0 prove the gate,
without invented report SHA/gate fields. One shared 15-minute deadline includes
preparation/coverage and terminates owned active work with no later upload.

## Rationale

use the already provisioned Project analysis token without requiring
Browse/admin rights or hiding actionable scanner errors. Target selection is
explicit; privacy is neither independently established nor changed.
