## Rule

Browser binding uses the cookie `__Host-kdrive-oauth` with attributes `Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=600` and no `Domain`. Its value is 32 random bytes. The authorize handler reuses the incoming value when exactly one well-formed `__Host-kdrive-oauth` cookie is present, and otherwise sets a new one. Every response that creates cookie-bound state (the consent page and the upstream redirect of BR-131) carries `Set-Cookie` with the bound value and `Max-Age=600`, so the cookie lives at least as long as the state it protects. A pending consent and an upstream flow store the SHA-256 of the value, and a presentation matches only when the request carries exactly one well-formed `__Host-kdrive-oauth` cookie whose SHA-256 equals the stored one (constant-time comparison).

## Rationale

Binding consent and state to the browser defeats login CSRF and injected callbacks. Source: [F-010 v1](../features/F-010-oauth-proxy.md), AC-09, AC-12.

## Examples

  **Then** 400 HTML and the consent is consumed.
- **Given** authorize at t, approval at t + 599 s
  **When** the callback arrives at t + 1,198 s with the re-sent cookie
