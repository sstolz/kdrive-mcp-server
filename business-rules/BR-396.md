# BR-396 — Launcher settings filter

## Rule

`scripts/http-acceptance.ts` exports `acceptanceSettings(env)`, which returns exactly the non-empty values of the BR-171 settings (`MCP_PUBLIC_URL`, `MCP_HTTP_HOST`, `MCP_HTTP_PORT`, `OAUTH_ISSUER`, `OAUTH_ALLOWED_SUBJECTS`, `OAUTH_ALLOWED_EMAILS`, `OAUTH_UPSTREAM_CLIENT_ID`, `OAUTH_UPSTREAM_CLIENT_SECRET`, `OAUTH_UPSTREAM_CLIENT_SECRET_FILE`, `OAUTH_SIGNING_KEY_FILE`, `OAUTH_ALLOWED_REDIRECT_URIS`, `OAUTH_ALLOWED_CLIENT_ID_ORIGINS`) plus `OAUTH_STATE_FILE`, and no other name; `main()` passes `acceptanceSettings(process.env)` as the only `env` of `startAcceptance`, with no other option.

## Rationale

The launcher dropped `OAUTH_STATE_FILE`, so the proxy kept its state in memory and a restart lost every client; one exported filter, used by `main()`, lets a rehearsal drive the same settings path as the owner run (learnings 2026-11-14). Source: [F-029 v2](../features/F-029-acceptance-launcher-oauth-state.md).

## Examples

- **Given** every BR-396 name with a value, `OAUTH_STATE_FILE=""`, `KDRIVE_TOKEN`, `OAUTH_MODE` and `HOME`
  **When** `acceptanceSettings` reads it
  **Then** the result holds exactly the BR-171 names with their values
- **Given** the same environment with `OAUTH_STATE_FILE=/run/oauth-state/oauth-state.sqlite`
  **When** `acceptanceSettings` reads it
  **Then** the result also holds `OAUTH_STATE_FILE` and never `KDRIVE_TOKEN`, `OAUTH_MODE` or `HOME`
