# BR-397 — Acceptance state directory guard and mount

## Rule

`scripts/http-acceptance-entry.sh`, after the BR-171 v2 checks and before any Docker command or Make prerequisite, refuses with exit status 1 and exactly one fixed stderr line that never contains a path or file content, in this order (first failure wins): (1) `OAUTH_STATE_FILE` is non-empty in its environment (`Do not set OAUTH_STATE_FILE; set HTTP_ACCEPTANCE_STATE_DIR to persist the acceptance OAuth state.`); when `HTTP_ACCEPTANCE_STATE_DIR` is unset or empty, no further state check runs and no state directory is mounted; otherwise (2) the value does not start with `/`, contains `:` or a newline, or has a `.` or `..` path component (`Set HTTP_ACCEPTANCE_STATE_DIR to an absolute directory outside the checkout.`); (3) the value without trailing `/` is a symlink or does not resolve to an existing directory, or the directory is not readable, writable and searchable (`The acceptance state directory is unavailable.`); (4) its physical path equals, lies under or is an ancestor of the checkout's physical path, is `/`, or contains `:` or a newline (`The acceptance state directory is inside the dev checkout.`); (5) its physical path equals, lies under or is an ancestor of the secrets directory's physical path (`The acceptance state directory overlaps the secrets directory.`); (6) its mode grants any permission to group or others, read through POSIX `find -perm` (ACLs are not read) (`The acceptance state directory is not private.`); (7) it holds an entry, hidden ones included, other than `oauth-state.sqlite` and `oauth-state.sqlite-journal` (`The acceptance state directory holds other entries.`); (8) either of those two entries exists and is a symlink or not a regular file (`An acceptance state file is unavailable.`). On success the single `compose run` adds `--volume <physical path>:/run/oauth-state` (read-write) and `-e OAUTH_STATE_FILE=/run/oauth-state/oauth-state.sqlite`. The checks and the mount are not atomic (accepted residual risk).

## Rationale

The state file is a credential store: it must not land in the read-write dev checkout that F-012 D-20 took credentials out of, must not overlap the read-only secrets mount, and an owner who expects persistence must never get a silent in-memory run (F-029 D-1 to D-3). Source: [F-029 v1](../features/F-029-acceptance-launcher-oauth-state.md).

## Examples

- **Given** `OAUTH_STATE_FILE` set and a valid state directory
  **When** `make http-acceptance` runs
  **Then** it exits 1 with `Do not set OAUTH_STATE_FILE; set HTTP_ACCEPTANCE_STATE_DIR to persist the acceptance OAuth state.` and no Docker command runs
- **Given** a state directory with mode `0750`
  **When** `make http-acceptance` runs
  **Then** it exits 1 with `The acceptance state directory is not private.`
- **Given** an empty state directory with mode `0700` outside the checkout and the secrets directory
  **When** `make http-acceptance` runs
  **Then** `build` runs, then one `compose run` adding `--volume <physical path>:/run/oauth-state` and `-e OAUTH_STATE_FILE=/run/oauth-state/oauth-state.sqlite`
