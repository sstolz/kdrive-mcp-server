## Rule

The record identity is `{"kind":"stdio"}` for the stdio server, `{"kind":"oauth","iss":…,"sub":…}` from the verified identity bound to the HTTP session, and `{"kind":"insecure"}` for the loopback unauthenticated HTTP mode; a gate run without one of these identities is refused at admission as `failed` with code `AUDIT_UNAVAILABLE`.

## Rationale

Every write must name who asked for it, from a verified identity only. Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** the stdio runner
  **When** a run is recorded
  **Then** its identity is `{"kind":"stdio"}`
- **Given** a run without identity
  **When** it starts
  **Then** it is refused `AUDIT_UNAVAILABLE` before policy evaluation
