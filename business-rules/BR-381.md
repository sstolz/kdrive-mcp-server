# BR-381 — A full queue refuses with SERVER_BUSY

## Rule

When 4 calls are already waiting, an arriving call returns `SERVER_BUSY` at once, with zero kDrive requests and zero audit records, and the 4 waiting calls and the running invocation are unaffected.

## Rationale

The queue bounds memory and latency per session (F-026 D-2); a refusal before any request is safe to retry. Source: [F-026 v1](../features/F-026-bounded-invocation-queue.md).

## Examples

- **Given** a running read and 3 waiting calls
  **When** a call arrives
  **Then** it joins as the fourth waiting call
- **Given** a running read and 4 waiting calls
  **When** a tool call, a resource read or a `mutate` arrives
  **Then** it gets `SERVER_BUSY` at once (resource read: protocol error `-32000` `SERVER_BUSY`) with zero requests and zero records
