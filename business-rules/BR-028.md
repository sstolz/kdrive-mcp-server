# BR-028 — Separate local preparation from resolved readiness

Source: [F-002 v1](../features/history/F-002-v1.md), BR-028, frozen
2026-11-01 21:18:28 UTC after fresh independent approval.

## Rule

**v2 (F-014 v1, pending acceptance).** `LocalConfiguration` and `ResolvedConfiguration` stay separate exported types; unit and CI tests use injected readers/resolvers/transports and synthetic credentials only, and a real credential is used only by the owner-run targets of BR-211 and BR-215.

v1 below stays the accepted rule until v2 is accepted on actual main.

### v1 (accepted)

Separate `LocalConfiguration` from `ResolvedConfiguration` in
exported TypeScript types: the former retains root selectors and the latter
exists only after BR-021 succeeds. No production adapter, listener or OAuth
verification is added. Tests use injected readers/resolvers and synthetic
credentials only; executable tests use isolated synthetic fixture files and
an explicit environment. Retain all applicable foundation gates and run the
complete Docker/Make local gate and mandatory PR CI before independent review.

The source specification's inventory, bounds, grammars, auth matrix, credential
contract, error mapping and preflight port supply the normative details for
this statement; this record does not redefine those tables.

## Rationale

Do not confuse synthetic validation or typed configuration with a delivered adapter or server.

## Examples

These examples use injected synthetic data and record no new execution.

- **Given** `LocalConfiguration` from drive IDs `7,8` and selectors
  `7:42,8:/Folder,7:/Alias`, **When** TypeScript checks assignment directly
  to `ResolvedConfiguration`, **Then** assignment is rejected. Mapping:
  [config-preflight.test.ts](../tests/config-preflight.test.ts),
  `typeBoundary`, the `@ts-expect-error` assignment marked BR-028, checked by
  `make typecheck`.
- **Given** that same local configuration, **When** preflight uses injected
  admin results for drives `7` and `8` and directory ID `42` for each selector,
  **Then** it returns resolved roots `{driveId:7,folderId:42}` and
  `{driveId:8,folderId:42}`, removes `roots`, and calls only the configured
  drives before the three selectors. Mapping: the same file,
  `BR-021 BR-028 inspects only configured drives before roots and collapses resolved aliases`.
- **Given** that same local configuration with no resolver, **When**
  `preflightConfiguration` is called, **Then** it rejects with
  `PREFLIGHT_UNAVAILABLE/preflight` and returns no resolved configuration.
  Mapping: the same file,
  `BR-027 BR-028 rejects absent resolver and sanitizes unexpected callback errors`,
  absent-resolver assertion.
- **Given** drive `7`, synthetic token `SYNTHETIC_CLI` and default stdio,
  **When** the isolated executable runs, **Then** it exits `1`, emits empty
  stdout and exactly
  `Configuration validated locally; stdio runtime is not implemented yet.\n`
  on stderr. Mapping: [cli.test.ts](../tests/cli.test.ts),
  `only validates local %s without listener or protocol`, `stdio` row.
- **Given** the same synthetic environment and CLI
  `--http --insecure-no-auth`, **When** the isolated executable runs, **Then**
  it exits `1`, emits empty stdout and exactly
  `Configuration validated locally; http runtime is not implemented yet.\n`
  on stderr. Mapping: the same case, `http` row.

- **Given** an isolated packed executable, drive `7` and token
  `SYNTHETIC_PACKED`, **When** it runs in either stdio or insecure HTTP mode
  (one example per transport), **Then** it exits `1`, emits empty stdout, and
  reports the selected runtime as unimplemented with the same exact message
  as above. Mapping: [package.test.ts](../tests/package.test.ts),
  `BR-004 real package allowlist excludes synthetic secrets, source, tests and reports`,
  `stdio` / `http` transport loop iterations.

The successful injected result and the missing-resolver refusal delimit
resolved readiness; neither claims a production adapter, listener or provider.
Aggregate quality gates and independent review are acceptance evidence below,
not a unit-test example of runtime readiness.
