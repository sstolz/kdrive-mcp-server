## Rule

The adapter issues only the method/route pairs of the F-017 Route table: `GET` on the F-014 routes and on the trash-metadata route, and `POST` or `DELETE` only on the five mutation routes, all to origin `https://api.infomaniak.com` port 443, IDs rendered as decimal positive safe integers, query values encoded by `URLSearchParams`, `Authorization: Bearer <token>` on that origin only. Verified by: AC-10.

Since v3 (F-018): also `POST` on the upload route `/3/drive/{d}/upload?directory_id={p}&file_name={n}&total_size={s}&conflict={error|version}`, with the query members in that order, encoded by `URLSearchParams`; the observer receives the template `/3/drive/{d}/upload`.

## Rationale

The bearer token must reach only the fixed Infomaniak API origin on known read routes; anything else could redirect or leak the credential. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).

## Examples

- **Given** the adapter with the injected transport
  **When** `inspect` runs for drive 101 file 12
  **Then** one `GET /3/drive/101/files/12?with=path%2Cparents%2Ccapabilities` reaches `api.infomaniak.com` with `Authorization: Bearer <token>`.
- **Given** a permitted trash of file 41 on drive 101
  **When** the mutator runs
  **Then** exactly one `DELETE /2/drive/101/files/41` reaches `api.infomaniak.com` with the bearer token.
