## Rule

A pending hidden read rejects once on stdin `end` with `Input ended`, or stdin `error` with `Input failed`, without returning buffered input or exposing the original error text or stack.

## Rationale

Hidden reads must not hang on EOF or expose buffered secrets or error payloads.
Source: [F-052 v1](../features/F-052-oauth-qualification-proxy-hardening.md).

## Examples

- **Given** a hidden read with empty or nonempty buffered input
  **When** stdin emits `end`
  **Then** it rejects once with `Input ended` and returns no input.
  Maps to `BR-440 v1 AC-05 EOF and errors settle without payload`.
- **Given** a pending hidden read and an error containing synthetic secret text
  **When** stdin emits `error`
  **Then** it rejects with `Input failed`, exposing no error text or input.
  Maps to the same terminal AC-05 test.
- **Given** either hidden reader rejects in the qualification runner
  **When** the runner handles the failure
  **Then** it returns 1, writes no report and prints only the fixed qualification
  failure diagnostic. Maps to `BR-440 v1 AC-05 reader failure stays redacted`.
