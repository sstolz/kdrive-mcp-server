## Rule

Appends in one process are written in call order, one at a time, each as a single write of at most 8,192 bytes to an `O_APPEND` descriptor, so that records from concurrent writers on one local file never share a line.

## Rationale

Concurrent writers on one local file must never corrupt a line (D-16-8). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** two processes appending 1,000 records of 8,000 bytes to one file
  **When** both finish
  **Then** the file has 2,000 parseable lines in per-process order
- **Given** three appends issued at once
  **When** the first write is still pending
  **Then** the second has not started
