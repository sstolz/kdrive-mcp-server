# BR-305 — Acceptable CIMD client IDs

## Rule

A `client_id` that starts with `https://` is a CIMD client ID. It is acceptable only when: it meets every check of Contract details "CIMD client ID syntax"; it is not byte-identical to the proxy issuer, the audience or the upstream issuer; and its origin (`https://host[:port]`, port omitted when 443) is byte-identical to an entry of the current `oauthAllowedClientIdOrigins`. At the authorize handler a CIMD client ID that is not acceptable, or any CIMD client ID while the list is empty, is an unknown client: 400 HTML error page, no redirect, no fetch (BR-128 v3). A `client_id` that does not start with `https://` is looked up among registered clients as today.

## Rationale

Only well-formed URLs under listed origins may trigger a fetch; every other https client ID is refused before any network activity. Source: [F-028 v1](../features/F-028-client-id-metadata-documents.md).

## Examples

- **Given** origins `https://client.example.com`
  **When** authorize receives `https://client.example.com/a/%2e%2e/b`, `https://client.example.com:443/c.json` or `https://other.example.com/c.json`
  **Then** the 400 page, no redirect, `client_metadata_refused` `not_allowed`, and the fetch port is not called
- **Given** the same origins
  **When** authorize receives `https://client.example.com/c.json`
  **Then** the document is fetched once and the request reaches consent
- **Given** an empty list
  **When** authorize receives any https client ID
  **Then** the 400 page as an unknown client and no fetch
