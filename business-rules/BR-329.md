# BR-329 — Summary only with verified task metadata

## Rule

On a nonzero scanner exit, the task metadata is the content of `<work>/runs/<runId>.txt` (the scanner's `metadataFilePath`) when `lstat` reports a regular file (not a symbolic link) of at most 64 KiB, opened with `O_NOFOLLOW`, confirmed by `fstat` on the open handle as a regular file of at most 64 KiB, and read up to 64 KiB + 1 bytes (a read returning more than 64 KiB is treated as absent), otherwise empty; the summary proceeds only when `verifyTaskMetadata(text, mode, host)` accepts it, else it prints exactly `Quality Gate summary unavailable: no verified task metadata.` and makes no request. `<projectKey>` and `<ceTaskId>` used below come only from the verified metadata.

## Rationale

Binds the summary to the analysed task and target, and resists symlink, size and read races (T1, T4). Source: [F-022 v1](../features/F-022-sonar-gate-summary.md).

## Examples

- **Given** a nonzero exit and `runs/<runId>.txt` a symbolic link to a valid metadata file
  **When** the summary runs
  **Then** only `Quality Gate summary unavailable: no verified task metadata.` prints and `fetch` records zero calls
- **Given** a nonzero exit and a regular metadata file for `kdrive-mcp-server` and the configured host
  **When** the scanner returns
  **Then** its metadata is the file content and the summary makes its first request
