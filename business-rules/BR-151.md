# BR-151 — Pristine export and comparison before secrets

## Rule

In the `sonar` and `sonar-pr` jobs, three inline workflow steps declare no `env`
key; the first two run before any step that receives a secret and the third is
the last step of the job: (1) pristine export, before
`make setup`: it fails unless `git rev-parse HEAD` equals `GITHUB_SHA`, then
writes `git archive --format=tar "$GITHUB_SHA"` to `$RUNNER_TEMP/pristine.tar`
and extracts it to `$RUNNER_TEMP/pristine`; (2) comparison, after `make setup`: it
fails unless the root `node_modules` is absent or an empty, non-symlink
directory; it fails when `diff -r --no-dereference --exclude=.git
--exclude=node_modules "$RUNNER_TEMP/pristine" .` reports any difference; it
fails when a nested `node_modules` or `.git` entry exists; and it fails when any
of `GNUmakefile`, `makefile`, a root `*.mk`, a Compose override file, `.env`,
`.config/qube-token` or `.config/sonar-host-url` exists or is a symlink.

Git metadata: the export also fails unless `.git` is a non-symlink directory
without `commondir` or `modules`, and copies each existing `.git/config`,
`.git/config.worktree`, `.git/hooks/` and `.git/info/` (links not followed) to
`$RUNNER_TEMP/git-meta`; an entry absent at export must remain absent. The
comparison also fails when that Git-metadata check finds any difference. (3) The
final step, with the condition exactly `always()`, invokes no `git` command; it
exits 0 when `$RUNNER_TEMP/git-meta` does not exist, and otherwise, when the
Git-metadata check fails, renames `.git` with `mv -T -- .git .git.quarantine`
(fallback `$RUNNER_TEMP/git-quarantine`; never deleted) and exits nonzero, so the
`actions/checkout` post step finds no repository.

(v2: `config.worktree` was refused instead of saved and compared. v1: two steps; `.git` was neither compared nor moved aside.)

## Rationale

`make setup` runs dependency lifecycle scripts with write access to the working tree; the comparison uses a reference they cannot reach. `.git` is read-only in the containers (BR-150 v2); the saved Git metadata and the final step are defence in depth, because the `actions/checkout` post step runs host `git`, which would execute a tampered `core.fsmonitor` or hook, even after a failed step. Source: [F-011 v2](../features/F-011-pre-merge-quality-gates.md).

## Examples

- **E-01 — Given** an unchanged checkout with an empty root `node_modules`
  **When** the export then the comparison run under `bash -eo pipefail`
  **Then** both exit 0.
- **E-02 — Given** a modified `Makefile` committed with `git commit -a` between the steps
  **When** the comparison runs
  **Then** it exits nonzero.
- **E-04 — Given** `core.fsmonitor` set in `.git/config` after the export
  **When** the final step runs
  **Then** it exits nonzero, no `.git` entry remains and `.git.quarantine` holds the moved metadata.
- **E-05 — Given** no export ran (a fork or disabled run)
  **When** the final step runs
  **Then** it exits 0 and `.git` is untouched.
- **E-06 — Given** `.git/hooks` replaced by a symlink to a directory after the export
  **When** the comparison runs
  **Then** it exits nonzero.
- **E-07 — Given** a `.git/config.worktree` holding the keys the checkout writes (`core.sparseCheckout`, `core.sparseCheckoutCone`, `index.sparse`; fixture value `false`), unchanged afterwards
  **When** the export, the comparison and the final step run
  **Then** all three exit 0, `.git` stays in place and the saved copy is byte-identical to `.git/config.worktree`.
- **E-08 — Given** that `.git/config.worktree` at export, then `core.fsmonitor` added to it
  **When** the final step runs
  **Then** it exits nonzero and `.git.quarantine` holds the moved metadata.
- **E-09 — Given** that `.git/config.worktree` at export, then removed
  **When** the comparison runs
  **Then** it exits nonzero.
- **E-03 — Given** `HEAD` different from `GITHUB_SHA`
  **When** the export runs
  **Then** it exits nonzero.
