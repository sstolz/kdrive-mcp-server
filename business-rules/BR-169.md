## Rule

v3 (F-028 v1, #3, pending acceptance; v2 stays the accepted rule until then): step (2) also cancels in-flight CIMD fetches and settles their authorization requests with the 503 page (BR-309).

The `node:http` server uses `requireHostHeader` false (so BR-156 answers a request without `Host`), `headersTimeout` 10,000 ms, `requestTimeout` 30,000 ms, `keepAliveTimeout` 5,000 ms, `maxHeaderSize` 16,384 bytes and `maxConnections` 256. A request target longer than 8,192 bytes yields HTTP-layer error 414 `invalid_request` before the `Host` check. `close()` runs in this order: (1) it stops accepting connections; (2) it closes every session (reason `shutdown`), which settles their in-flight requests with BR-164's 503; (3) it waits until the adapter has finished writing each response settled in step 2, or 1,000 ms, whichever comes first; (4) it ends every remaining connection (`closeAllConnections`); (5) it resolves once the listener is closed. From step 1 on, `handle()` answers every new request with HTTP-layer error 503 `temporarily_unavailable` without `Retry-After` and creates nothing, and an `initialize` already in flight when step 1 starts registers no session: its `onsessioninitialized` callback closes that transport and server and its request gets BR-164's 503. A response settled after step 2 may be cut by step 4; this is accepted (process shutdown).

Version 2 (F-019 v1, #103; accepted on main `68209fe`, 2026-11-11): `close()` step (5) waits until the listener is closed instead of resolving; a new step (6) then closes the OAuth state store when the handler opened one (BR-304), and `close()` resolves after step (6). Steps (1)–(4) and the rest of the rule are unchanged.

## Rationale

Fixed timeouts and bounds limit slow-client and connection exhaustion; an ordered close answers in-flight requests before ending connections. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-19.

## Examples

- **Given** a request target of 8,193 bytes
  **When** it arrives
  **Then** 414 `invalid_request`.
- **Given** a held tool call on a keep-alive connection
  **When** `close()` runs
  **Then** the connection receives a complete 503 and is then ended.
- **Given** an authorization request waiting on a CIMD fetch
  **When** the HTTP server's `close()` runs
  **Then** step (2) cancels the fetch and the request gets the 503 page (v3)
