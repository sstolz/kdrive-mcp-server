# BR-406 — Accept-Language parsing

## Rule

The `Accept-Language` header (all field lines joined as the runtime joins them) is ignored when absent or longer than 256 bytes. Otherwise it is split on `,`; each item, trimmed of spaces and tabs, is a language range (`*` or the ASCII grammar `[A-Za-z]{1,8}(-[A-Za-z0-9]{1,8})*`, compared with ASCII case folding) optionally followed by optional whitespace, `;`, optional whitespace and a weight `q=` / `Q=` of `0`, `0.` plus up to three digits, `1` or `1.` plus up to three `0`. An item that does not match is skipped; an item without a weight has weight 1. A range whose primary subtag (before the first `-`), compared case-insensitively, is `en` or `fr` stands for that language; `*` stands for `en` unless an `en` item has weight 0, then for `fr` unless an `fr` item has weight 0, otherwise for nothing; every other range is ignored, as is every item of weight 0. The result is the language of the remaining item with the highest weight, the first such item on a tie; with no remaining item there is no result.

## Rationale

The browser's language is the owner's chosen default; a strict, bounded parse keeps a hostile header cheap and predictable. Source: [F-031 v1](../features/F-031-oauth-proxy-page-languages.md).

## Examples

- **Given** `Accept-Language: fr-CH, fr;q=0.9, en;q=0.8`
  **When** the header is parsed
  **Then** `fr`
- **Given** `Accept-Language: de-CH,de;q=0.9`
  **When** the header is parsed
  **Then** no result (the page falls back to `en`)
- **Given** `Accept-Language: en;q=0, *`
  **When** the header is parsed
  **Then** `fr`
- **Given** `Accept-Language: fr;q=1.0001`, or a 257-byte value starting with `fr`
  **When** the header is parsed
  **Then** no result
