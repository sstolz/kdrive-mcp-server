# BR-287 — Owner-run `make kdrive-upload-acceptance`

## Rule

`make kdrive-upload-acceptance` follows the BR-276 v1 conditions (actual main checkout, dev Compose service, token through BR-212, `KDRIVE_WRITE_FOLDER` required and checked before any Docker command, mode `write` with that folder as the only root, audit log in a container temporary file, sanitized summary with no ID, name, path, token or content), runs the two phases of the F-018 Acceptance sequence with at most 100 upstream requests within 300,000 ms, and uploads at most 1,048,576 bytes in total.

Since v2: steps 8 and 9 of the Acceptance sequence are replaced by step 8 (v2) and step 9 (v2) of F-018 v2 (NFD refused with zero requests, NFC name stored unchanged, compatibility ligature and off-set children observed).

## Rationale

The real API evidences D-18-9, D-18-10 and D-18-11 before release (D-18-7). Source: [F-018 v1](../features/F-018-upload.md).

## Examples

- **Given** no `KDRIVE_WRITE_FOLDER`
  **When** the owner runs the target
  **Then** it fails with "Set KDRIVE_WRITE_FOLDER to a positive decimal folder ID." before any Docker command
- **Given** `KDRIVE_WRITE_FOLDER=42` on actual main
  **When** the owner runs the target
  **Then** the dev service runs `node scripts/kdrive-upload-acceptance.ts`
