# BR-365 — Release check output

## Rule

`release-check` prints one stdout line per check, `release-check: <check> ok` or `release-check: <check> FAIL <reason>` with a fixed reason, and last `release-check: <k> of <n> checks failed`, exiting 0 when `k` is 0, else 1. No output of any `scripts/release.ts` mode contains a token, an `Authorization` value or a response body; an HTTP failure is reported by status code only.

## Rationale

The log of a public workflow must show what failed without leaking a credential or server text. Source: [F-024 v2](../features/F-024-gated-publication.md).

## Examples

- **Given** doubles echoing the `Authorization` header and answering 500, with token `SYNTHETIC-RELEASE-TOKEN`
  **When** every mode runs
  **Then** no output contains the token or a body
- **Given** all checks passing
  **When** `release-check` runs
  **Then** the last line is `release-check: 0 of <n> checks failed` and the exit is 0
