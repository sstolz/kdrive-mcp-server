## Rule

`make runner-probe` runs `ops/runner/probe.sh network` twice, in the runner container (where job steps run) and in a `--network host --pid host --privileged` container of `kdrive-ci-runner:local` (the VM's own network view), masks the two inputs with `::add-mask::` before any use, and prints one `PASS <id>` or `FAIL <id>` line per probe, where `<id>` never contains an address. Each negative probe is a TCP connection or DNS query with a 5-second limit that passes only when it fails: the VM gateway `192.168.5.2` (the host loopback) on ports 22, 80, 443, 2375, 2376 and the owner canary port 47999; `host.lima.internal` on port 443 (when it resolves); `10.0.0.1`, `172.16.0.1`, `192.168.0.1`, `192.168.1.1` on ports 22 and 443; `169.254.169.254` on port 80; TCP port 80 of `github.com`; a DNS query sent directly to `9.9.9.9:53` (never a recorded resolver, BR-220); TCP port 443 to `2606:4700:4700::1111` and to the IPv6 address `github.com` resolves to, when it has one (no IPv6 egress); and, when given, `lan_target` and `host_target`. A positive DNS probe resolving `github.com` through the VM's own resolver must pass, so the direct-DNS probe is not vacuous. Each positive probe passes on any HTTP response over HTTPS from `https://api.github.com`, `https://github.com`, `https://ghcr.io/v2/`, `https://registry-1.docker.io/v2/`, `https://registry.npmjs.org/` and `https://download.docker.com/`. In the host-network container it also fails a probe `no-host-mount` when `nsenter -t 1 -m cat /proc/self/mounts` (the VM's mount namespace) lists a `9p`, `virtiofs` or `fuse.sshfs` mount. It exits nonzero when any probe fails.

## Rationale

The probes show from both network views of the VM that only public HTTPS and the VM resolver are reachable, without leaking the owner's addresses (T1). Source: [F-015 v1](../features/F-015-self-hosted-runner.md).

## Examples

- **Given** stubbed tools that refuse every connection and two masked inputs
  **When** `probe.sh network container` runs
  **Then** the mask lines come first, every probe line is `PASS` and no id holds an address
- **Given** stubbed tools that accept every connection
  **When** `probe.sh network container` runs
  **Then** `FAIL container-gateway-tcp-47999` is printed and the exit status is nonzero
