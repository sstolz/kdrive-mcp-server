## Rule

The runner registration credential is read by `ops/runner/supervise.sh` only from `$HOME/.config/kdrive-runner/github-token`, which must be a regular non-symlink file owned by the running user with mode `0600` (otherwise the supervisor exits nonzero with a fixed message before any network call). It is sent only to `https://api.github.com` to request a JIT configuration (`POST /repos/sstolz/kdrive-mcp-server/actions/runners/generate-jitconfig`, runner group 1, labels exactly the BR-225 array, name `kdrive-ci-<UTC timestamp>`). Neither the credential nor the JIT configuration appears in a command argument on the host, in a file under the Lima instance or in the supervisor's output; the JIT configuration reaches the VM only on the stdin of `limactl shell`, which writes it to the BR-222 tmpfs file.

## Rationale

The repository-administering credential stays on the host, in one 0600 file, and travels only to the GitHub API on stdin (T4, D-04, D-14). Source: [F-015 v1](../features/F-015-self-hosted-runner.md).

## Examples

- **Given** a credential file of mode 0644
  **When** `supervise.sh run` starts
  **Then** it exits nonzero with its fixed message and makes no call
- **Given** a valid 0600 credential file and stubbed tools
  **When** one cycle runs
  **Then** neither the credential nor the JIT value appears in an argument, an instance file or the output, and the JIT value reaches `limactl shell` on stdin
