# BR-348 — Privacy scan hit lines

## Rule

Each hit prints exactly one stdout line `privacy-scan: hit <location> pattern <n>`, where `<location>` is `<path>:<line>`, `commit <40-hex sha> line <line>` (message), `commit <40-hex sha> added` (changed blobs and paths of that commit; one hit per commit and pattern), `commit <40-hex sha> identity` (author or committer name or e-mail), `pr-title:<line>` or `pr-body:<line>`. When the path itself matches any pattern, `<location>` is `file #<k>:<line>` with `k` the 1-based index in `git ls-files` order, and one extra line `privacy-scan: hit path file #<k> pattern <n>` is printed. No output ever contains matched text, a pattern, or text around a hit.

## Rationale

Printing a hit's text would republish the leak in a public log (T3, D-5). Source: [F-023 v1](../features/F-023-hosted-ci-privacy-scan.md).

## Examples

- **Given** a tracked path `dir/<token>.txt` at index 2 holding the token on line 2
  **When** the scan runs
  **Then** `hit path file #2 pattern 1` and `hit file #2:2 pattern 1` print and no output holds the token
