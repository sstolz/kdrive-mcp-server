# BR-304 — Single owner and one close of the store

## Rule

The HTTP handler opens the store (BR-152 v2), holds its only reference and exposes `closeStore()`; the store is closed exactly once: by the HTTP server's `close()` calling `closeStore()` as BR-169 v2 step (6), after the listener has closed and before that `close()` resolves, which also covers `LISTEN_FAILED`; and, when the proxy construction throws, by the handler before the error leaves `createHttpHandler`. The handler's own `close()` (BR-169 v2 step (2)) does not close the store. A closed store releases its lock, and a write on it is a BR-299 failure. Step (6) catches any throw from `closeStore()`: the store counts as closed and the server's `close()` still resolves; further calls do nothing.

## Rationale

The lock must be released on shutdown, once, and a late write must fail visibly. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** a running server with a state file
  **When** `close()` is called
  **Then** the listener closes, then the store closes once, then `close()` resolves
- **Given** `closeStore()` throwing
  **When** the server's `close()` runs
  **Then** `close()` still resolves
- **Given** a closed store
  **When** a write is attempted
  **Then** a BR-299 failure
