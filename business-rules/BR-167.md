## Rule

v2 (F-021 v1, #105; accepted on main `e208996`, 2026-11-11): v1 holds, and `request_refused` `route` may also be `health`; a 200 `/healthz` response emits no event.

No HTTP response header or body, error message or logger call produced by this feature contains a client bearer token, the kDrive credential, the upstream client secret, signing-key material, an upstream token, a session ID (except in the `Mcp-Session-Id` header of a response to a request within that session, including the one that creates it) or an identity value. The optional logger is also given to `createOAuthProxy`, so it receives the BR-143 events with their fields; the only events this feature adds are `request_refused` (fields: `route`, one of `mcp`, `prm`, `as_metadata`, `register`, `authorize`, `consent`, `callback`, `token` or `unknown`; `status`; `error` code), `session_opened` (`count`; `requested_protocol`, the `initialize` `params.protocolVersion` when it matches `^\d{4}-\d{2}-\d{2}$`, else `other`) and `session_closed` (`reason`: `deleted`, `idle`, `lifetime`, `evicted` or `shutdown`; `count`). Each HTTP-layer error response this feature sends (every row of the Contract details status table, including BR-164's 503 and BR-170's 500) emits exactly one `request_refused`, whose `status` and `error` are that response's; `route` names the route whose path the target path matches byte-exactly (BR-154), else `unknown`. Responses produced by the SDK transport or an F-010 handler emit none. `session_opened` is emitted once per registered session and `session_closed` once per closed session; `count` is the number of registered sessions after that change.

## Rationale

Responses and logs must not expose secrets, tokens, session IDs or identities. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-14, AC-17, AC-19.

## Examples

- **Given** canary values for every secret
  **When** every refusal path runs with a capturing logger
  **Then** no response or log entry contains a canary.
- **Given** a refused request
  **When** it is answered
  **Then** exactly one `request_refused` carries its route, status and error code.
