# BR-336 — Issue lines

## Rule

After every successful issues stage, even with zero issues, the summary prints exactly `Quality Gate issues: current open issues of <projectKey> (may include another analysis of this project).`. The returned issues are first filtered: only those whose `component` equals `<projectKey>` or starts with `<projectKey>:` are kept, the others are dropped. Then the first 20 kept issues (even when the server returns more) each print as `- issue <severity> <type> <rule> <file>:<line> <message>`, where `<file>` is the `component` with a leading `<projectKey>:` removed, `:<line>` is omitted when `line` is absent or not a positive integer; when `severity` or `type` is absent, the pair `<severity> <type>` is replaced by the first 3 `impacts` items whose `softwareQuality` and `severity` are both strings, printed as `<softwareQuality>:<severity>` joined by `,`, or by `-` when there is none. The total is `paging.total`, falling back to `total`, else the number of kept issues; a total is used only when it is a non-negative integer number, otherwise the next source applies; when it exceeds the number of printed issues, the summary adds `- <total − printed> more issues not shown`.

## Rationale

Shows the open issues of the analysed project only, bounded, with the omitted count (D-6, D-9). Source: [F-022 v1](../features/F-022-sonar-gate-summary.md).

## Examples

- **Given** 3 issues of the project and `paging.total` 25
  **When** the summary prints
  **Then** the issues header, 3 `- issue` lines and `- 22 more issues not shown`
- **Given** an issue without `severity` and `type` with impacts MAINTAINABILITY/HIGH and RELIABILITY/LOW
  **When** the summary prints
  **Then** `- issue MAINTAINABILITY:HIGH,RELIABILITY:LOW typescript:S1 src/f1.ts:1 m1`
- **Given** 25 issues whose first 5 belong to another project and no total
  **When** the summary prints
  **Then** 20 issue lines from the sixth issue on and no `more issues not shown` line
