# BR-343 — Deny-pattern secret format

## Rule

The secret is parsed like the archive's `deny-patterns.txt`: split on `\n` (a trailing `\r` removed), each line trimmed; empty lines and lines starting with `#` are skipped; every other line is one JavaScript regex compiled with flags `giu`. A pattern's number is its 1-based physical line in the secret, comments and blank lines included.

## Rationale

Compatibility with the archive's list lets the owner reuse it; numbers by physical line let the owner find a pattern without the output naming it (D-4, D-5). Source: [F-023 v1](../features/F-023-hosted-ci-privacy-scan.md).

## Examples

- **Given** a secret with a comment on line 1, a blank line 2, patterns on lines 3 and 5, CRLF endings
  **When** it is parsed
  **Then** exactly two patterns result, numbered 3 and 5, each with flags `giu`
