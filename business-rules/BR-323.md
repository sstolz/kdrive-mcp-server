# BR-323 — Health route independence

## Rule

The `/healthz` response does not depend on `Authorization`, `Cookie`, `Origin`, `Mcp-Session-Id`, the query string, the number of sessions, the OAuth state or the mode: it never calls the token verifier, the OAuth proxy, the upstream port, the OAuth state store, the session registry or any kDrive port, reads no request body, sets no cookie and emits no logger event when it returns 200.

## Rationale

A liveness route must not be an oracle for authentication or configuration state, must not amplify anonymous requests into outbound calls, and must not flood the log (D-2, D-3). Source: [F-021 v1](../features/F-021-container-health-check.md).

## Examples

- **Given** an authenticated handler with an open session
  **When** `GET /healthz` arrives with a valid `Authorization` and that `Mcp-Session-Id`
  **Then** the response is byte-identical to one without them, no spy is called and no event is logged
- **Given** an insecure handler with no session
  **When** `GET /healthz` arrives
  **Then** the same 200 response as in authenticated mode
