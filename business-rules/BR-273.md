# BR-273 — Cancellable-action check

## Rule

The `rename`, `move`, `trash` and `restore` check accepts a `data` object whose `cancel_id` is a string of 1–256 bytes and `valid_until` is a finite number; the mutator then returns `value` `{drive_id, id}` with the target ID, and no result, record or diagnostic contains the `cancel_id`.

## Rationale

The cancel token has no client use and must not leak (D-17-8). Source: [F-017 v1](../features/F-017-controlled-tree-mutations.md).

## Examples

- **Given** a 200 with `{cancel_id:"CANCELMARK-0001", valid_until:1800000000}` for a rename of 41
  **When** the run ends
  **Then** it is `succeeded` with `value` `{drive_id:101, id:41}` and no output holds the `cancel_id`
- **Given** a 200 whose `valid_until` is `1e999`
  **When** the run ends
  **Then** it is `uncertain`
