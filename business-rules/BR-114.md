## Rule

PDF extraction accepts only the bounded preflight profile and never starts PDF.js on unsupported, malformed or over-budget containers.

**v2 (F-034 v1, #4, pending acceptance; v1 stays the accepted rule until then)** — v1 holds with the profile of F-034: PDF extraction accepts only input that passes BR-412–BR-420, never starts PDF.js on unsupported, malformed or over-budget input, and PDF.js only ever receives the canonical projection of BR-415, never source bytes. The header is `%PDF-1.0` to `%PDF-1.7` or `%PDF-2.0` at byte 0 followed by an end of line. Checks run in this processing order and the first check that fails decides the refusal: the header; the cross-reference chain from the last `startxref`, newest section first (BR-412); the trailer, including `/Encrypt`; the Catalog and the page tree in tree order; then each selected page in ascending page number, its `Contents` references with the decoded length each one uses (BR-416), then its content tokens in order, where a `Do` of a Form runs that Form's checks, its use of decoded bytes included, at that token (BR-419), the first `Tf` that selects a font runs that font's checks at that token (BR-417, BR-420), the first shown code that needs a Type 1 built-in encoding reads it at that token (BR-420), and each emitted canonical token runs the running checks of BR-418 at that token; then the final weighted U of BR-418. An object, stream or CMap is checked when the step that needs it first resolves it. A failing check refuses with `LIMIT_EXCEEDED` when it is a declared or computed ceiling of F-009 or F-034, every bound of the table "Ceilings added by F-034" included, whatever the wording of the BR that states it (the count or size that passes the ceiling fails); the computed size of a Flate inline image is a consistency check, not a ceiling, and Flate output over it refuses as `CONTENT_UNAVAILABLE` (BR-416); with `UNSUPPORTED_FORMAT` when the file is well-formed but uses a feature outside the profile (encryption, an unadmitted filter, font, encoding, glyph name or operator, an inline image of unknown length) or fails an F-009 operand check (arity, type, the 1,000,000 numeric bound, the 32-level `q` nesting of BR-416), which keeps its F-009 code and is not a ceiling; and with `CONTENT_UNAVAILABLE` when the file contradicts its own structure (an offset that does not hold the object it names, a cycle, a length that overruns its data, a missing required object or resource).

## Rationale

Compressed source size alone does not bound parser expansion or text production. Source: [F-009 v1](../features/F-009-bounded-content-reading.md). v2: the closed v1 profile refused 18 of 20 synthetic files carrying one common generator feature each; a projection admits them, and the Forms, inline images and Type 1 built-in encodings of spec review 1, while PDF.js still sees only bounded canonical input ([F-034 v1](../features/F-034-pdf-extraction-profile.md), ADR-012).

## Examples

- **Given** classic xref, one Flate page stream and simple Helvetica WinAnsi.
  **When** admission runs.
  **Then** bounded canonical uncompressed bytes reach PDF.js.
- **Given** a4097-byte Flate expansion with budget4096.
  **When** preflight runs.
  **Then** LIMIT_EXCEEDED occurs before PDF.js.
- **Given** a PDF 1.5 file with a cross-reference stream, an object stream and a Type0 `ToUnicode` font (v2)
  **When** page 1 is read
  **Then** its text is returned and PDF.js receives no `/XRef`, `/ObjStm` or font program
- **Given** a well-formed file with `/Encrypt` (v2)
  **When** page 1 is read
  **Then** `UNSUPPORTED_FORMAT` before PDF.js
- **Given** a header `%PDF-1.7` followed by a space instead of an end of line (v2)
  **When** page 1 is read
  **Then** `UNSUPPORTED_FORMAT` before PDF.js
- **Given** a file with an unknown operator on page 1 and a `/Prev` cycle (v2)
  **When** page 1 is read
  **Then** `CONTENT_UNAVAILABLE` (the cross-reference chain is checked first) before PDF.js
