# BR-057 — Single guarded facade

## Rule

All received-share protected operations and exposed collection entries pass through the same immediate single-use guarded facade as ordinary configured-tree operations.

The detailed frozen evidence, capability, cache and effect contracts in
[F-004 v1](../features/F-004-received-share-policy.md) are normative.

## Rationale

Tools, resources and batches need one immutable immediate authorization boundary.

## Examples

These are synthetic injected examples, not provider observations.

- **Given** permitted child8:24 and fake tool/resource consumers, **When** dispatching each consumer, **Then** both use checked protected execution.
- **Given** an independent batch with later unknown target8:999, **When** dispatching the batch, **Then** no batch protected execution occurs.

Each example maps to the named parameter row/group below, in the same order.
