## Rule

`make runner-reset-mark` leaves in the VM a file `/var/lib/kdrive-reset-sentinel`, a Docker volume `kdrive-reset-sentinel`, an image tag `kdrive-reset-sentinel:local`, a running container named `kdrive-reset-sentinel`, a file `kdrive-reset-sentinel` in the parent of `$GITHUB_WORKSPACE` and a file `kdrive-reset-sentinel` in `$RUNNER_TEMP`. `make runner-reset-check` fails when any of them exists, or when the parent of `$GITHUB_WORKSPACE` holds an entry other than the current checkout.

## Rationale

Two consecutive jobs prove that nothing left by one job survives into the next (T2). Source: [F-015 v2](../features/F-015-self-hosted-runner.md).

## Examples

- **Given** no sentinel, and runner-owned entries in `RUNNER_TEMP`
  **When** `probe.sh reset-check` runs
  **Then** it succeeds
- **Given** a sentinel file in the parent of `$GITHUB_WORKSPACE`
  **When** `probe.sh reset-check` runs
  **Then** it fails
