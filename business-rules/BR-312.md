# BR-312 — Store events and no leak

## Rule

The proxy adds the events `store_write_failed` (fields `handler`, `store`) and `store_loaded` (fields `clients`, `families`, logged once at startup with the counts after purge). Under BR-143 v2 no event, response or startup line contains the state-file path, a row value or an SQLite, JSON-parser or operating-system message.

## Rationale

Operators need to see the load and the latch, and logs must carry nothing that identifies a row or the path. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** a file with live and expired rows
  **When** the store opens
  **Then** one `store_loaded` event with the counts after the purge
- **Given** every refusal path
  **When** the logger and stderr are captured
  **Then** no event or line contains the path, a row value or an SQLite message
