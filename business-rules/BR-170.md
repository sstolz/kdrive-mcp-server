## Rule

The `node:http` adapter turns each incoming request into a Web `Request` (method as received; headers built by appending every field of `rawHeaders` in order; body streamed from the socket, except for GET and HEAD, whose `Request` has no body because a Web `Request` cannot carry one (BR-160 refuses their framing); a fixed placeholder URL that the router never reads) and calls `handle(request, target)` with the raw request target. It writes the response status, headers (each `Set-Cookie` as its own field) and body unchanged. Any exception thrown in the request path (the adapter, the router, an F-010 handler, `createNavigationServer` or the SDK transport) yields HTTP-layer error 500 `server_error` when no response has started (otherwise the connection is closed), carries nothing of the error, and later requests are still served. When the adapter writes a response while the request body has not been fully received (`IncomingMessage.complete` is false), the response carries `Connection: close` and the adapter ends the connection after writing it, so the connection is not kept alive to drain an unread body.

## Rationale

Header repetition, dot segments and unread bodies behave differently in Node and in Web objects; raw data at the adapter keeps every rule exact. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-03, AC-05, AC-09, AC-15, AC-19.

## Examples

- **Given** a handler that throws
  **When** a request reaches it
  **Then** 500 `server_error` without error text and the next request is served.
- **Given** a chunked POST to `/unknown` left unterminated
  **When** the 404 is written
  **Then** it carries `Connection: close` and the connection is then closed.
