## Rule

`ops/runner/lima.yaml` has exactly the top-level keys `vmType`, `arch`, `plain`, `mounts`, `portForwards`, `hostResolver`, `ssh`, `containerd`, `cpus`, `memory`, `disk` and `images` (any other key, for example `additionalDisks`, `vmOpts`, `firmware` or `networks`, is rejected), and `hostResolver`, `ssh` and `containerd` have exactly the sub-keys listed here. It defines the VM with: `vmType: "qemu"`, `arch: "x86_64"`, `plain: true`, `mounts: []`, exactly one `portForwards` entry `{"guestIPMustBeZero": false, "guestIP": "0.0.0.0", "guestPortRange": [1, 65535], "proto": "any", "ignore": true}`, `hostResolver.enabled: false`, `ssh.localPort: 60022`, `ssh.loadDotSSHPubKeys: false`, `ssh.forwardAgent: false`, `ssh.forwardX11: false`, `containerd.system: false`, `containerd.user: false`, `cpus: 4`, `memory: "8GiB"`, `disk: "60GiB"`, and exactly one `images` entry with `arch: "x86_64"`, an `https://` location and a `digest: "sha256:<64 hex>"`.

## Rationale

A VM definition that shares nothing with the host (no mount, no port forward, no extra network, no host resolver, no agent forwarding) is the isolation boundary of T1; the exact key sets stop a later key from widening it. Source: [F-015 v1](../features/F-015-self-hosted-runner.md).
