# BR-387 — Parallel calls and SERVER_BUSY are documented

## Rule

**v1 (F-026 v1; active, unchanged)**

README "Key limits" and the section `## Parallel tool calls` of `docs/mcp-client-compatibility.md` state that one call per session runs at a time, that up to 4 further calls wait in arrival order for at most 12 seconds, and that `SERVER_BUSY` means the call was refused before any kDrive request, so it is safe to retry (writes included) once an earlier call has completed. `CHANGELOG.md` `## [Unreleased]` has a `### Fixed` line citing #16.

**v2 (F-043 v1 frozen, #67; pending acceptance)**

README "Key limits" and the section `## Parallel tool calls` of `docs/mcp-client-compatibility.md` state that one call per session runs at a time, that up to 4 further calls wait in arrival order for at most 12 seconds, and that `SERVER_BUSY` means the call was refused before any kDrive request, so it is safe to retry (writes included) once an earlier call has completed. `CHANGELOG.md` selects the first release section whose body cites #16 anywhere, in file order; if no such release section exists, it selects `## [Unreleased]`. The selected section has a bullet under `### Fixed` whose line starts with `- #16 `. A release section has a heading of the form `## [<version>] - <YYYY-MM-DD>`, using the F-025 version/date grammar; an undated heading is not a release section. A citation matches `#16\b`, so `#160` does not cite #16. Only text before the `## [0.6.0-beta.1]` heading is searched, as in BR-321 v4: that section and older sections use archived ticket numbers.

## Rationale

`SERVER_BUSY` is the documented retryable refusal (F-026 D-3); clients and operators need its meaning and the queue bounds. Source: [F-026 v1](../features/F-026-bounded-invocation-queue.md).

v2 changes only the changelog location so release promotion preserves the
documentation contract. Source: [F-043 v1](../features/F-043-queue-changelog-release-sections.md).
