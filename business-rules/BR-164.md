## Rule

A session closes after 1,800 seconds without a request bound to it or 86,400 seconds after creation, whichever comes first; expired sessions are closed before each session lookup or creation. Each identity holds at most 8 sessions: when a ninth registers, that identity's session with the oldest last request is closed. The process holds at most 64 sessions, counting creations in progress: an `initialize` beyond that, after closing expired ones, yields HTTP-layer error 503 `temporarily_unavailable` with `Retry-After: 60` before anything is created. Closing a session closes its transport and its `McpServer`; its ID then yields 404 (BR-163). A request bound to a session that closes, for any reason, while the request is in flight (other than the DELETE that closes it) is answered with HTTP-layer error 503 `temporarily_unavailable` without `Retry-After`, and the result of its call is discarded; the router does not wait on the SDK transport, which never settles such a request after `close()` (D-18).

## Rationale

Bounded sessions and an answer for every in-flight request keep memory and connection slots bounded. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-14, AC-19.

## Examples

- **Given** a session idle for 1,799 seconds
  **When** a request carries its ID
  **Then** it is served.
- **Given** the same session idle for 1,800 seconds
  **When** a request carries its ID
  **Then** 404 `session_not_found`.
- **Given** 64 registered sessions
  **When** an `initialize` arrives
  **Then** 503 with `Retry-After: 60` and nothing is created.
