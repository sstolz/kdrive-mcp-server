# BR-418 — Producer admission

## Rule

The F-009 text-production admission holds with weighted string bytes, counted on the canonical content stream of each selected page, so every Form execution counts its strings and operators again: N is the sum over text-show strings of the string's bytes times `m` of the font in effect at that point of the canonical stream (for a Form that shows text before its own `Tf`, the font its caller set, at each execution), where `m = max(1, ceil(D / 3))`; S is the number of shown codes: string bytes for a simple font, string bytes divided by two for a Type0 font (whose codes are two bytes, BR-417), so a two-byte code counts as one possible item; O is the number of operators in the canonical content stream. D of a font is the largest of: the UTF-8 length of each canonical `ToUnicode` destination (an unpaired surrogate counts 3 bytes); for each glyph name in the font's canonical `/Differences`, 4 when the name starts with `u` and has 6 characters, or 7 characters without the prefix `uni`, else 3; and 1. `U = 8 * (N + O + 1)`, `I = 2 * (S + O + 1)`, the sum of U plus 3 per separator is at most B, the sum of I at most 65,536, and a string over 4,096 bytes refuses. These checks run while the canonical content is emitted: at each emitted token, the canonical bytes emitted so far, the 4,096-byte string check, S, O, the sum of I and the sum of U computed with `m = 1` (both sums including the current page's `+ 1` terms and separator) are updated, and the token that makes one of them pass its ceiling refuses there as `LIMIT_EXCEEDED`, before the next token is read. Only the sum of U with each font's final `m`, known once every shown code is collected, is checked after the last selected page. All refusals happen before PDF.js starts.

## Rationale

`ToUnicode` can map one code to several characters and a glyph name can give a character above U+FFFF, so the F-009 bound of three UTF-8 bytes per glyph no longer holds; weighting each string by its font's largest mapping, pinned to the canonical CMap and the glyph-name forms PDF.js 6.5.438 reads, and counting every Form execution on the canonical stream keep the static bound before PDF.js starts. Source: [F-034 v1](../features/F-034-pdf-extraction-profile.md).

## Examples

- **Given** a `ToUnicode` font with a 48-byte largest destination and repeated strings whose U sum is exactly B
  **When** the page is read
  **Then** its text
- **Given** the same page with a U sum of B + 1
  **When** the page is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
- **Given** a text-show string of 4,096 bytes
  **When** the page is read
  **Then** its text
- **Given** a text-show string of 4,097 bytes
  **When** the page is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
- **Given** a Form of 1,000 `0 Tc` operators drawn 4,096 times through nested `Do`s
  **When** page 1 is read
  **Then** `LIMIT_EXCEEDED` at the token whose operator makes the sum of I pass 65,536, with no later token emitted and PDF.js never started
- **Given** a Type0 page whose sum of I, counting each two-byte code once, is 65,536
  **When** the page is read
  **Then** its text
- **Given** the same page with a sum of I of 65,537
  **When** the page is read
  **Then** `LIMIT_EXCEEDED` before PDF.js
