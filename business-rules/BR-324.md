# BR-324 — Loopback Host allowance on /healthz

## Rule

For a target path equal to `/healthz` (when BR-322's route exists), the BR-156 v2 `Host` check also passes, case-insensitively, the loopback forms `127.0.0.1`, `localhost` and `[::1]`, each bare or followed by `:` and 1 to 5 ASCII digits. Every other `Host` (absent, empty, repeated, another name, an IP other than these) yields 403 `invalid_host` before any BR-325 window is counted.

## Rationale

A static image `HEALTHCHECK` cannot know the public host when the deployment uses `--config`; allowing loopback only on a constant route keeps BR-156's DNS-rebinding protection elsewhere (D-4). Source: [F-021 v1](../features/F-021-container-health-check.md).

## Examples

- **Given** the authenticated handler
  **When** `/healthz` arrives with `Host: 127.0.0.1:3000`
  **Then** 200
- **Given** the authenticated handler
  **When** `/healthz` arrives with `Host: 127.0.0.1:123456`
  **Then** 403 `invalid_host`, and no health window is counted
- **Given** the authenticated handler
  **When** `GET /.well-known/oauth-protected-resource/mcp` arrives with `Host: 127.0.0.1:3000`
  **Then** 403 `invalid_host` as before
