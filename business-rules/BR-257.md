## Rule

In production, a received-share mutation run with `sharedWithMe=true` and `sharedWrite=true` fetches a new complete `shared_with_me` list even while a read snapshot is valid, and is denied, because every received mutation predicate is `false`.

## Rationale

Received-share writes need fresh evidence and stay unauthorized until qualified (D-16-4). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** a received folder with `can_write:true` and a cached received list
  **When** a rename run targets it
  **Then** a new `shared_with_me` GET is made
- **Given** the same run
  **When** it ends
  **Then** it is `denied` with no intent record
