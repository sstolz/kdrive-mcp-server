## Rule

For each matrix client, in order: an `incomplete` or `unsupported` provider yields `not decided`; a needed `unverified` fact yields `undetermined`; `delegate` needs a `delegate-capable` provider and a documented registration mechanism the provider has as `yes` (CIMD only with `none` `yes`); `delegate-static` needs a delegating provider and documented manual client ID entry; these two do not apply to a client documented to reject inconsistent issuer identification on an inconsistent run, whose `unverified` fact is then needed; `proxy` needs a usable ID token and documented dynamic registration; otherwise `not decided`. The P-21 promotion flag is true when at least one client is `proxy`.

## Rationale

SPEC §8 routes a client to `proxy` when it cannot use the provider's registration path; the decision must be explicit per client and never guessed from unverified documentation. Source: [F-008 v1](../features/F-008-oidc-qualification.md), AC-15.

## Examples

- **Given** a `delegate-capable` provider and a client with dynamic registration `supported`.
  **When** the mode is decided.
  **Then** it is `delegate`.
- **Given** the same provider on an inconsistent run with a usable ID token and a client that rejects inconsistent issuer identification.
  **When** the mode is decided.
  **Then** it is `proxy` and the promotion flag is true.
- **Given** the same client with that fact `unverified`.
  **When** the mode is decided.
  **Then** it is `undetermined`.
