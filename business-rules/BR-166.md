## Rule

**v2 (F-053 v1, #73; pending acceptance).** v1 holds, plus: for each HTTP request, `serve` creates one disconnect `AbortController` and passes its signal to `handle()` as an explicit parameter. That controller aborts when, and only when, either the `ServerResponse` `close` event or the `close` event of `req.socket` fires while the response's `writableFinished` is false; it never aborts after the response was completely written. `serve` attaches at most one `close` listener per socket, shared by every unsettled request on that socket; when it fires, it aborts the controller of each unsettled request on the socket and settles each one's pending response-write wait, so every `serve` promise settles and leaves the server's in-flight set even when its response never emits `finish` or `close`. The shared socket listener is removed once the socket has no unsettled request, and each `ServerResponse` listener once its response settles. Neither the request built by `toRequest` nor the SDK request built by `sdkRequest` is constructed with a `signal` option, and neither is ever aborted by a disconnect. `sdkRequest` registers the disconnect signal in a `WeakMap<Request, AbortSignal>` keyed by the SDK request it builds. The SDK request never carries `Authorization`, `Cookie` or `authInfo`. Handlers obtain the disconnect signal only by looking up the SDK context field `ctx.http.req` in that map; no entry (stdio, or no HTTP request) means no disconnect signal. The disconnect signal is distinct from, and never linked to, `ctx.mcpReq.signal`.

The previous version otherwise holds. Its accepted text is preserved below;
acceptance of that text does not establish acceptance of v2.

The request given to the SDK transport carries no `Authorization` or `Cookie` header, and `handleRequest` receives no `authInfo`. No tool handler, `PolicyDependencies` call, `McpServer` or the F-010 upstream port receives a client bearer token; MCP requests make no upstream call.

## Rationale

A client bearer token has no consumer past verification; withholding it removes a leak surface and token passthrough. Source: [F-012 v1](../features/F-012-authenticated-http.md), AC-16.

## Examples

- **Given** a request with `Authorization` and `Cookie` headers
  **When** it reaches the SDK transport
  **Then** the transport request has neither header and no `authInfo`.
