## Rule

The adapter never retries. It rejects with `ReadFailure(status)` for a pre-body 401, 403, 422, 429 or 500–599, and for any other 4xx except a metadata 404 with `error.code === "object_not_found"` (`missing` for policy ports per BR-198; an unbranded `READ_UNAVAILABLE` rejection for `describe` and preflight); it rejects with an unbranded `Error` whose message is exactly `READ_UNAVAILABLE` for a transport, TLS, address, deadline, size, encoding, redirect or queue failure, and, for the preflight and content ports only, for an envelope failure (policy ports return `incomplete` instead, BR-198/BR-201). The client-visible code of each outcome is fixed by the Error-mapping table. No rejection carries a provider body, header, URL, ID, cursor or token.

## Rationale

Clients and the central retry helper need a fixed mapping; provider bodies, URLs, IDs and tokens must never surface in errors. Source: [F-014 v1](../features/F-014-production-kdrive-adapter.md).
