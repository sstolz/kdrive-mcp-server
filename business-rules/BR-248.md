## Rule

Only an HTTP 429 response is retried, for at most 3 attempts per run; the wait before attempt n+1 is the 429's `Retry-After` value in seconds when it consists of 1–10 ASCII digits, or else 1,000 × 2^(n−1) ms; when the wait exceeds 30 s or would end after the run's total deadline, or the third attempt answers 429, the run ends `failed` with code `RATE_LIMITED`.

## Rationale

Only a 429 proves the write was not performed (assumption D-16-5); bounded waits keep calls finite. Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** a 429 without `Retry-After` then a 200
  **When** the run ends
  **Then** two attempts were made 1,000 ms apart
- **Given** a 429 with `Retry-After: 31`
  **When** the run ends
  **Then** it is `failed`/`RATE_LIMITED` after one attempt
