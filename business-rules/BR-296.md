# BR-296 — File bound to issuer, audience and upstream issuer

## Rule

The file's `meta` table binds it to the exact strings the proxy uses for its tokens (BR-124): `issuer` is the proxy issuer, the WHATWG serialization of `publicUrl` without trailing slashes; `audience` is the configured audience as used for `aud`, which the HTTP handler sets to `publicUrl` verbatim; `upstream_issuer` is the WHATWG serialization of `oauthIssuer` without trailing slashes. They are written when the file is initialized; a file whose three values are not byte-identical to these strings for the effective configuration stops startup with `OAUTH_STATE_MISMATCH` and is left unchanged.

## Rationale

Identities and resources in the file are meaningful only for the proxy that wrote them. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** a file written for issuer `https://a.example/mcp`
  **When** a proxy for `https://b.example/mcp` opens it
  **Then** `OAUTH_STATE_MISMATCH` and the file is unchanged
- **Given** a file initialized by the proxy
  **When** its `meta` rows are read
  **Then** the three values equal the binding strings byte for byte
