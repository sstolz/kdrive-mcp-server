## Rule

Any write error, short write, `fdatasync` error or stream `error` event latches the sink as failed for the process lifetime; every later append rejects without I/O. An oversize record (BR-236) does not latch the sink.

## Rationale

After a failed write the trail can no longer be trusted, so later writes are refused (D-16-1). Source: [F-016 v1](../features/F-016-mutation-audit-gate.md).

## Examples

- **Given** a write failing with `ENOSPC`
  **When** an append runs
  **Then** it rejects and the next append rejects without a write call
- **Given** an oversize record
  **When** its append rejects
  **Then** the next normal append succeeds
