# BR-303 — Entry and file size bounds

## Rule

The client and family stores each hold at most 1,000 entries (BR-142 v2) and a family holds one current token hash. The database `max_page_count` is set at open so that the file cannot exceed 67,108,864 bytes; a write that would exceed it fails under BR-299. A file holding more than 1,000 rows in either table is refused at open (BR-295 step (8)).

## Rationale

A bounded file keeps startup and disk use bounded and rejects a file stuffed by a writer. Source: [F-019 v1](../features/F-019-persistent-oauth-state.md).

## Examples

- **Given** 1,000 clients and 1,001 families in a file
  **When** the store opens
  **Then** `OAUTH_STATE_CORRUPT`
- **Given** a file at its page limit
  **When** a write would exceed it
  **Then** the write fails and the store latches
- **Given** 1,000 stored clients
  **When** a new client registers
  **Then** an entry is evicted in the transaction of the new one
