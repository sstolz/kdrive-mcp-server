# BR-342 — Deny-pattern secret confinement

## Rule

`secrets.PRIVACY_DENY_PATTERNS` appears only in step 3 of `privacy-scan`; no Sonar secret appears in `privacy-scan`. `make privacy-scan` passes every `PRIVACY_*` variable to the dev container by name (`-e NAME`, never `-e NAME=value`), and the script never writes the pattern text to a file, argv, stdout or stderr.

## Rationale

The patterns themselves name what must stay private; printing, echoing, writing or passing them as arguments leaks them (T2). Source: [F-023 v1](../features/F-023-hosted-ci-privacy-scan.md).

## Examples

- **Given** the deny secret added to the `lint` step env
  **When** the validator runs
  **Then** it is rejected
- **Given** a Sonar secret added to the `privacy-scan` step env
  **When** the validator runs
  **Then** it is rejected
- **Given** the `Makefile`
  **When** the recipe is read
  **Then** every `PRIVACY_*` name is passed as `-e NAME` without a value
