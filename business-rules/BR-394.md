# BR-394 — CIMD events

## Rule

The proxy adds the event `client_metadata_refused` (handler `authorize`, fields `reason` and `status`), with `reason` one of `not_allowed` (BR-305), `blocked_address`, `resolution`, `connection`, `certificate`, `timeout`, `status`, `content_type`, `size`, `document` (BR-306–BR-308, and a `redirect_uri` not kept from the document) or `busy` (BR-309). Every refused authorization request logs exactly one event, the one Contract details "Authorization refusal events" assigns to it: with an empty list, and for a `client_id` that does not start with `https://`, today's event only; `client_metadata_refused` only with a nonempty list. The proxy also adds the event `client_metadata_fetched` (fields `status` and `count`, where `count` is the number of cache entries) logged once per completed successful fetch. In both events `status` is the HTTP status code of the document response, or `0` when no response status was received (`not_allowed`, `blocked_address`, `resolution`, `connection`, `certificate`, `busy`, and `timeout` before the status line); it is therefore always 200 in `client_metadata_fetched`. The status of the proxy's own page follows from `reason` (BR-309). `reason` joins the BR-143 field list. No event, response, page other than the consent page, or thrown message contains a CIMD URL, host, resolved address, document member or TLS error text.

## Rationale

Operators need one event per refusal with a reason they can act on, while logs must not carry client URLs, hosts, addresses or TLS text. Source: [F-028 v1](../features/F-028-client-id-metadata-documents.md).

## Examples

- **Given** a nonempty list and a CIMD client ID under an unlisted origin
  **When** authorize refuses it
  **Then** exactly one `client_metadata_refused` with `reason` `not_allowed` and `status` 0
- **Given** an empty list and an https client ID
  **When** authorize refuses it
  **Then** exactly one `authorization_refused` and no `client_metadata_refused`
- **Given** a successful fetch
  **When** the document is cached
  **Then** one `client_metadata_fetched` with `status` 200 and the cache count
